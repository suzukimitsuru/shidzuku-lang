### 2026-09-26 思考実験 24 で Hike の取り組みを突き合わせた

suzukimitsuru の指示により、プログラミング言語 Hike(`hike-lang`。Go に似た構文の、GC の無いシステム言語)の設計上の取り組み17件を、
仕様の対応する所と突き合わせた([思考実験 24](../../experiments/24-Hikeの取り組み.md))。新しい系は書いていない。**何も決めていない。**

| 判定           | 件数 | 主な物                                                                                                   |
| -------------- | ---- | -------------------------------------------------------------------------------------------------------- |
| 取り込む候補   | 5    | 共有の仕方を宣言の側で言う・送り出しと待ちを分ける・ロックの制限・元の記述への対応表・出力先の対を揃える |
| 既に持っている | 5    | テキストとバイト列の分離・共有状態への侵入の禁止・接着コードの生成・型に値の引数・識別子の目録           |
| 取り込まない   | 7    | 既定の引数・綴りで決まる可視性・常駐しない実行時・寿命の模型・インラインアセンブリ等                     |

- **取り込む候補は全てコンポーネントの内側に集まった。** Hike はプロセスの内側の言語であり、コンポーネントの間(接続・障害境界・配置)には比べる物を持たない。
- 論点1〜3(`state` に並行時の欄を足すか・`ask` を送り出してから待てるか・待つ所を印として現すか)は **U10 の比較の材料**にする。
  内側の並行を許すと、全ての `state` 宣言に欄が一つ増える。逐次(actor)を選ぶ理由を宣言の数で見せる材料である。
- 論点4(`ask` の閉路を検証器で見つける。`flow` の辺は数えない)は、第3章 3.5 の未定事項「依存の循環の扱い」への入力である。重さは U10 の再入の決定と組にして決める。
- 論点5・6(バックエンドの責務 G7 に元の記述への対応表を足すか・出力言語で直に書く逃げ道を置くなら全出力先の対を必須にするか)は Phase 1 と U12 への入力である。接合面 H1〜H8 には触れない。
- 取り込まない物は、いずれも ADR 0008(省略の禁止)か ADR 0012(分担)で切れた。新しい理由を要した物は無い。
- 第0章 0.9 の系譜には足さない。取り込む候補を U10 や Phase 1 の ADR が採った時に、取り込んだ範囲と併せて足す(ADR 0024 の背景と同じ理由)。

### 2026-10-08 思考実験 32 で実行モデルと順序を書き比べた

suzukimitsuru の指示により、コンポーネントの実行モデル(U10)とメッセージの順序保証(U11)の材料として、[思考実験 32(実行モデルと順序)](../../experiments/32-実行モデルと順序.md) を行った。**本書は何も決めていない。**
題材は思考実験 04 の KVCore、ADR 0031 の机上検証1 の OrderIntake、思考実験 02 の流れ、思考実験 20 の論点3 である。

| 実行モデルの案         | 分かった事                                                                                                              |
| ---------------------- | ----------------------------------------------------------------------------------------------------------------------- |
| 待たせる逐次           | KVCore の取得が書きの詰まりに巻き込まれ、OrderIntake の期限が待ち行列の長さで破られる。`ask` の閉路は必ず期限切れになる |
| 待つ所で次を受ける逐次 | 取得は通るが、KVCore の格納どうしで追い越しが起きる。TypeScript では何もしなくてもこの形になる                          |
| 内側の並行             | TypeScript に写せず、混在の適合試験が成り立たない。全ての `state` に並行時の欄が増える                                  |

- **九つの問いは、待つ所で何をするかの一つに集まった。** 閉路の成否・出る順の入れ替わり・`ask` の応答と `flow` の到着の扱い・溜まる物の上限が、そこから決まる。
- **再入の害は、状態と待つ所の両方を持つ仕事にだけ出る。** KVCore の取得は受けてよく、格納は待たせたい。再入を公開面ごとに選ぶ形が要りそうである。
- **順序について言語が言える事は二つ**——送り手1つ・受け手1つの接続の中は FIFO(先に入った物が先に出る)、durable の再送は古い物から元の順で行い「重複はあり得るが追い越しは無い」。
  接続を跨ぐ順序と、`ask` の応答と `flow` の到着の間の順序は無い。`correlate` の並びは送った順であり、届く順ではない(ADR 0023 への入力)。
- **上限**: `pressure block` と `drop` には待ち行列の上限が要り、`latest` は意味から 1 である。`ask` の受け口と、待つ所で止まっている仕事にも上限が要る。
- 2026-10-15、suzukimitsuru の指示で、ADR の起案の前に論点3(再入を公開面ごとに選ぶか)を思考実験 01・02・04 の全ての受け口に当てた(思考実験 32 の第10節)。
  - **14 の受け口と 1 つの時計で始まる仕事のうち、待たせたいのは 3 か所だった**——KVCore の `格納`、Persister の `書込記録`、Aggregator の時計の締めと受け口の組。全ての受け口に書かせると、11 か所で同じ答えを書き写す。
  - **害は受け口ではなく、仕事の組に出る。** 再入を受け口ごとに選ぶ形より、重ならない仕事の組を宣言する形(仮の語 `exclusive`。3 行)が害の形に合う。`idempotent` と同じく該当時のみの約束にするかが、省略の禁止(ADR 0008)との論点になる。
  - **状態の宣言だけでは害を見つけられない。** Persister の害は `state` に無いログのファイルから出た。
  - **待つ所の範囲**(`io` の層の外部への入出力を含むか)と、**公開面から始まらない仕事**(時計で始まる仕事・`on expiry`)に言語の形が無い事が、U10 の ADR の論点に加わった。
- 次は U10・U11 の ADR を起案する。

### 2026-11-05 ADR 0032 で実行モデルと順序保証を起案した

[ADR 0032(実行モデルと順序保証)](../../decisions/0032-実行モデルと順序保証.md) を提案として起案した。材料は思考実験 32(実行モデルと順序)と思考実験 24(Hike の取り組み)の論点1〜4 である。**採否は決めていない。**

| 決めた方向         | 中身                                                                                                                     |
| ------------------ | ------------------------------------------------------------------------------------------------------------------------ |
| 中は逐次           | 同時に計算している仕事は常に一つ。内側の並行は採らず、`state` に欄を足さない                                             |
| 待つ所で次を受ける | 待つ所は `ask` の応答・`pressure block` の受付・`io` の層の外部への入出力の三つ                                          |
| 重ならない仕事の組 | 害の出る組だけを `exclusive` で名指す。全ての仕事を一組にすれば待たせる逐次になる                                        |
| 仕事の起点         | 受け口・時計・期限切れの三つ。時計の仕事は `timer <名前> every <時間>`(仮の語)で宣言する                                 |
| 順序               | `flow` の接続の中は FIFO。durable の再送は古い物から元の順で「重複はあり得るが追い越しは無い」。それ以外の順は保証しない |
| 上限               | `pressure block`・`drop` に `bound`、`ask` の受け口の `expose` に `bound`。`latest` は書かせない                         |
| `ask` の閉路       | フローの段で警告(W0032-1)。body の記法が決まったら、`exclusive` の組に閉じる閉路をエラー(E0032-3)                        |

- 思考実験 32 の第10節(論点3 の数え上げ)の通り、害は受け口ではなく仕事の組に出るため、再入を受け口ごとに選ぶ形を捨て、組の宣言を採った。
- 検証は E0032-1〜E0032-4・W0032-1・W0032-2 の六つ。既存の言語に移せるのは E0032-1 と W0032-2(宣言を足せば移せる)である。
- 接合面には、時計の仕事を起こす呼び出しを10個目として足す(ADR 0012 の決定3(接合面)の改訂)。
- suzukimitsuru に決めてもらう事は五つ——`exclusive none` を書かせるか、時計の仕事の語と置き場、`ask` の受け口の上限の置き場、durable の `bound` が縛る物、`ask` の閉路の重さ。いずれも推奨を添えた。
- 仕様書への反映は、採用の作業で行う。

### 2026-11-06 ADR 0032 の決めてもらう事を推奨の通りに決めた

suzukimitsuru の判断により、[ADR 0032(実行モデルと順序保証)](../../decisions/0032-実行モデルと順序保証.md) の決めてもらう事の五つを、全て推奨の通りに決めた。ADR の状態は提案のままであり、採否はまだ決めていない。

| 決めてもらう事                  | 決めた事                                                                       |
| ------------------------------- | ------------------------------------------------------------------------------ |
| `exclusive none` を書かせるか   | 必須とする。重ならない組を持たないコンポーネントも `exclusive none` と書く     |
| 時計で始まる仕事の語と置き場    | `constraint` に `timer <名前> every <時間>`。語は採用の時に ADR 0014 に従う    |
| `ask` の受け口の上限の置き場    | `expose` の欄に、受け口ごとに `bound` を書く                                   |
| durable の `bound` が何を縛るか | 件数一つで、記憶と永続の記憶域の両方を縛る                                     |
| `ask` の閉路の重さ              | フローの段は警告(W0032-1)、body で `exclusive` の組に閉じる物はエラー(E0032-3) |

- ADR の本文では、決定3(重ならない仕事の組)・決定4(仕事の起点)・決定6(`bound`)・決定7(`ask` の受け口の上限)・決定11(`ask` の閉路)・決定14(検証)に決めた事を書き入れた。
  `exclusive` は E0008-1(必須宣言の欠落)の対象に加わった。
- 選ばなかった候補は、ADR の「捨てたもの・理由」に足した。
- 次は採否である。採用すれば、移行の条件の M3(接合面の写し元)のうち、H2・H3(U10)と H5(U11)が揃う。
