  候補の表と段(第1段 04、第2段 01 系・02、第3段 03・10・08)を 4.5 に置いた。
- **文法とは body の記法か**——見直し前の問いは、宣言の層も含めた形式文法を文書にする時期であった。
  一方で、body の記法そのものが決まっていない事が分かった(全ての思考実験が `body { ... }` のまま)。これを **U26** として新設し、U14 の次に置いた。

### 2026-10-03 省略表現を使わない規則を置いた

### 2026-10-18 思考実験 31 で反証と肯定をまとめた

suzukimitsuru の指示により、言語仕様に対する反証(今のプログラマに受け入れられない所)と肯定(プログラマ以外の人に与える良い影響)を、
外部の研究と事例に照らして[思考実験 31(反証と肯定)](../../experiments/31-反証と肯定.md)にまとめた。外部の知見は要旨と二次資料に拠り、論文の本文は読んでいない。**何も決めていない。**

| 判定     | 主な物                                                                                                                    |
| -------- | ------------------------------------------------------------------------------------------------------------------------- |
| 強い反証 | 言語の外の物(ライブラリ・既存のコード・慣れ)・外部世界が書けない(U12)・警告を黙らせられない                               |
| 中の反証 | 書く量(省略の禁止)・意図を書かせる事・慣れた操作が無い・設計を書く層(UML(統一モデリング言語)の轍)・実行の枠・動く物が無い |
| 強い肯定 | 科学技術・計測・金融の担当者 — 単位の取り違えと暗黙の変換で値が化けない                                                   |
| 中の肯定 | 業務の専門家(業務の語が型と区分の名前になる・境界を読める)・監査と規制への対応・後任(捨てた選択肢が残る)                  |
| 弱い肯定 | 運用者・母国語で学ぶ人・AI(人工知能)に実装を書かせる人(いずれも推論か、研究が直接は当たらない)                            |

- **反証の芯は、費用を書き手が払い、利益を読み手が受ける非対称である。** 言語を選ぶのは書き手であり、普及は機能より生態系で決まる(Meyerovich & Rabkin)。
- 強い反証は三つとも未完成の部分であり、設計そのものへの反証は意図して逆を選んだ所(ADR 0008(省略の禁止)・ADR 0013(文字列型の廃止、text 型の導入、および層モデル)・ADR 0024(APoSD と結合バランスの考え方の取り込み))に当たる。
- 肯定はいずれも**読む事**で得られる。振る舞い駆動開発の経験から、読み手に書かせない線を守り、読める形(図・名前と区分の一覧)で早く届ける事が条件になる。
- 論点は7つ(書く量を道具で減らす時期・読み手を誰と定めるか・外部世界との境界(U12)の優先・警告の抑止・意図の置き場と規制の追跡・名前の言語と肯定の関係・反証を測る)。
  論点6(名前の言語と肯定の関係)は、思考実験 29 の論点7(名前を英語に限る事)の判断材料として渡す。課題(U)は足していない。
