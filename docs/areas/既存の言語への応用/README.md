## 経緯

### 2026-09-28 思考実験 26 で既存の言語に移せる検査を抜き出した

suzukimitsuru の指示により、第3章 3.3 の検査と、それを支える宣言を既存の言語(主に Rust と TypeScript)の lint に移せるかで分けた
([思考実験 26](../../experiments/26-shidzuku-lint.md))。仮称を shidzuku-lint とした。新しい系は書いていない。**何も決めていない。**

| 判定               | 件数 | 主な物                                                                       |
| ------------------ | ---- | ---------------------------------------------------------------------------- |
| そのまま移せる     | 11   | 期限の明示・待ち行列の上限・公開面の `bool` と素の数値・システム時刻での計測 |
| 宣言を足せば移せる | 17   | 層の強度と役割・依存の許可リスト・状態の宣言・意図の構造                     |
| 既にある           | 10   | 混同可能な識別子・網羅の分岐・暗黙の変換・整数の除算・未使用の依存           |
| 移せない           | 9 群 | 障害の非伝播・配達保証・フロー・システムの入れ子・量の種別の算術             |

- **lint が届くのは、コンポーネントの内側とその公開面まで**である。動作環境が担う物とプロセスを跨ぐ記述には届かない。
- ADR 0008・0013 が lint を退けたのは Shidzuku の中の話であり、既存の言語では lint しか届く手段が無い。本実験はその判断を覆さない。
  lint の弱さ(無視できる)は、抑止に理由を書かせる事で ADR 0003 の `rejected` と同じ形の記録に変えられる。
- 宣言の置き場は三案(設定ファイル・言語の属性・文書コメント)を並べた。文書コメントに Shidzuku の語彙をそのまま書けば、lint の宣言が Shidzuku の記述の下書きになる。
- Shidzuku へ跳ね返る論点が3つ出た。論点2(直和の分岐の「残り全部」)と論点3(警告の抑止)は 4.5 の「Phase 1 の中で決める物」に、
  論点3・4(W0003-2 の判定基準の一案)は第3章 3.5 の未定事項に足した。論点5(外への要求の期限)は 4.5 の U12 の行への入力に足した。
- **shidzuku-lint を作るか・いつ作るかは suzukimitsuru に決めてもらう**(論点1)。Phase 0 の間は実装に着手しない原則(第9節)との関係があるためである。
  作らない場合も、表は Phase 1 の検証器の設計の入力として残る。→ 同日に作る事が決まった(7.12)。

### 2026-09-28 ADR 0026 で shidzuku-lint を作る事を決めた

suzukimitsuru の判断により、思考実験 26 の論点1 に答えを出した([ADR 0026](../../decisions/0026-shidzuku-lintの作成.md)、起案と同日に採用)。
suzukimitsuru の理由は「**他の言語での応用を言語仕様と共に考える事で得る物がある**」である。思考実験 26 だけで仕様の穴が3つ見つかった事が、これを裏付けている。

- **決定1 作る**: 既存の言語へ考え方を先に届ける足場であり、仕様を既存の言語の側から試す検証の手段とする。
  **shidzuku-lang と shidzuku-lint は分けて考える**——ADR 0008・0013 が lint を退けたのは言語としての shidzuku-lang の判断であり、
  既存の言語を対象とする shidzuku-lint の設計はそれに縛られない(suzukimitsuru の指示で同日に改めた)。
- **決定2 時期**: Phase 1 の言語実装と並行して着手し、Phase 2 以降も継続して改良する。検証器と規則の一覧を共有する。
- **決定3 範囲**: そのまま移せる11件と既にある10件を作る。宣言を足せば移せる17件は要検討。移せない9群は作らない。
- **決定4 既にある10件**: 再実装せず、既存の lint の設定として束ねる。深刻度は shidzuku-lint の選択として shidzuku-lang に合わせ、抑止には理由を必須にする。
- **決定5 言語**: Rust と TypeScript から始める。suzukimitsuru の指示で **Hike** を検討し、shidzuku-lint の三つ目の対象に加える
  (Rust・TypeScript で規則の形が固まってから。既存の lint が無いため「束ねる物が無い」場合を試す)。
  shidzuku-lang のトランスパイル先としては、GC の無い言語での写像と寿命を試せるため ADR 0012 決定7 の候補に加える事を提案とし、接合面の凍結の後に判断する。
- **決定6 仕様と共に**: 以後、検査を足す ADR は、既存の言語に移せるか(4つの判定)を併せて書く。suzukimitsuru が採用を確かめた。

- 第0章 0.8 の実現戦略に4つ目として足し、第1節 Phase 1 と 4.5 の「Phase 1 の中で決める物」(宣言の置き場と構文・規則の番号・Hike をトランスパイル先に加えるか)、第9節 進め方の原則に反映した。
- 17件の宣言の置き場と構文は、パーサと重なるため U14 の決定を待って検討する。置き場所と実装の言語は Phase 1 の着手時に決める。
