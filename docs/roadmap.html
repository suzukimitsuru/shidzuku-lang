2. Phase 0 のいま

2-1. 検討の領域(docs/areas/)

仕様の検討は領域の木に分けてある。各領域の節は、その領域のフォルダの roadmap.js が差し込む(番号の一覧は docs/numbering.md)。

  • 図の読み方 — 左から課題・決定(ADR)・思考実験。線は、ADR が決めた課題(実線)・関連する課題(点線)と、ADR が依拠する思考実験を結ぶ。他の領域と結ぶ物は線を引かず「他の領域」と注記した。
  • 色 — 採用・執筆済み 提案・判断待ち 点線の枠は一部・先行のみ決定済み、打ち消し線は破棄、白い枠は ADR 無し(未着手・再検討中)。
  • 仕様の章との関係 — 各章が依拠する ADR は、章の頭の「依拠」の行にある(docs/spec/)。

3. ADR の検討順

ADR は互いを改訂する。改訂される側を先に採ると採用の直後に書き直しが要り、改訂する側を先に採ると依拠先が提案のままで宙に浮く。

  • ステップにまとめる — 改訂の関係にある ADR をまとめ、同時に採否を判断する。
  • ステップを並べる — 依拠の向き(名前 → 型 → 指針 → 接合面)に並べる。
  • いまの状態 — 2026-08-28 の採用(0005・0013・0015)と 2026-08-29 の採用(0014)でステップ1 は空になり、ステップ2 の一部も先に抜けた。2026-09-17 の採用(0012)でステップ5 も、2026-09-18 の採用(0006)でステップ3 も、2026-09-25 の採用(0018)でステップ4 も空になった。2026-09-26 の採用(0023)でステップ4 の新規 ADR も空になった。同日に思考実験 23 から 0024・0025 を起案してステップ3 に入れ、2026-09-28 に2本とも採用した。判断待ちの ADR は無い。残るのはステップ4 の未着手の課題(U10〜U14・U20・U26)である。
  • ステップの番号は動かさない — 採用の記録と対応が付くようにするため。
  • Phase 1 へ移る条件(2026-09-28 確定) — docs/PLAN.md 第4節 4.5 に置いた。M1: Phase 1 の前に決める課題(U10〜U14・U20・U26)が採用されている。M2: U21 は採用済みか、Phase 1 の期中へ送る判断が記録されている。M3: 接合面の写し元(H2・H3 = U10、H5 = U11、H8 = U13)が決まっている。M4: 成果物の題材を最新の仕様だけで書き下ろし、書けない所が無い。M5: 判断待ちの ADR が無い(ステップ3 の 0024・0025 は 2026-09-28 に採用した)。ADR 0026 により、この条件は shidzuku-lint の着手条件も兼ねる。
