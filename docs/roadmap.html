3. ADR の検討順

ADR は互いを改訂する。改訂される側を先に採ると採用の直後に書き直しが要り、改訂する側を先に採ると依拠先が提案のままで宙に浮く。

  • ステップにまとめる — 改訂の関係にある ADR をまとめ、同時に採否を判断する。
  • ステップを並べる — 依拠の向き(名前 → 型 → 指針 → 接合面)に並べる。
  • いまの状態 — 2026-08-28 の採用(0005・0013・0015)と 2026-08-29 の採用(0014)でステップ1 は空になり、ステップ2 の一部も先に抜けた。2026-09-17 の採用(0012)でステップ5 も、2026-09-18 の採用(0006)でステップ3 も、2026-09-25 の採用(0018)でステップ4 も空になった。2026-09-26 の採用(0023)でステップ4 の新規 ADR も空になった。同日に思考実験 22 から 0024・0025 を起案し、ステップ3 に入れた。残るのはこの2本と、ステップ4 の未着手の課題(U10〜U14)である。
  • ステップの番号は動かさない — 採用の記録と対応が付くようにするため。

  • 2026-09-03 — 4つの方向のうち3つを白紙から再検討

  • 2026-09-25 — ADR 0018 を採用し、判断待ちの ADR が無くなった
    採否の判断に先立って読み直したところ、決定1 と決定5 が噛み合っていない事が分かった——決定1 はコンポーネントとシステムが一つの contains に混在してよいと定めたのに、決定5 の depends は相手をシステムに限っており、混在させた当人どうしがどの行にも当たらない。depends の相手を兄弟(同じ contains)と親の兄弟、そして external に揃え、相手がコンポーネントかシステムかを問わない形にして塞いだ(検証番号は増えていない。E0018-3 の定義が広がった)。逆向きを「元の ask への後からの戻り(コールバック)」で説明する案は捨てた——ask は期限内に必ず返ると定めており(ADR 0004)、内側のシステムが自分から出す ask・flow(採番・監査)も説明できないためである。対になる通信の相関は第4章 4.6 の未定事項に残した。第1章 1.4・1.5、第2章 2.3、第3章 3.2・3.3 に反映した。
  • 思考実験 20 → U25 を新設
    ADR 0018 の採用で残った「対になる通信」(第4章 4.6)を、受注の確定が後から決まる系で書き下ろした。flow 宣言に二本を並べれば意図と障害時の埋め合わせは書けるが、二本を結ぶ鍵(受注番号)が同じ物である事は検査されず、同じ相手に複数の ask があると戻りがどれの続きか決まらない。さらに 「確定が何分以内に決まるか」という仕事全体の期限を書く場所が無い事が分かった(ask の deadline は応答までの期限、pressure block の期限は投入までの期限である)。案は3つに整理し、flow 宣言に相関の鍵と期限を書く案を第一候補とした。ADR 0004(通信は ask と flow の2方式)を改訂せずに済むためである。
  • 思考実験 21 → U25 の形を直し、論点5 を U13 へ送った
    D-2(flow 宣言に相関の鍵を書く案)を起案する前に、引当 → 決済 → 確定という巻き戻しが要る系で検証した。業務上の補償(引当の解放)は普通の接続として書けたため、サーガの単位は要らない。一方で、同じ補償が障害時には on failure の散文になり、その通信は depends も型も期限も検査されない事が分かった(第4章 4.6 に「on failure の欄の形」として足した)。さらに鍵は仕事に一つではなく、結ぶ対ごとにある(受注番号と引当番号)事が分かり、D-2 の形を直す入力になった。孤児の引当が残る論点は、仕事の期限を U13(失敗の体系)へ送った判断を裏付けた。
  • 2026-09-26 — U25 の ADR 0023 を起案し、同日に採用した
    思考実験 20・21 が材料を出し切ったため、ADR 0023 を起案した。flow 宣言にcorrelate 受注番号 : 受注 -> 受注の状態 のように二本を結ぶ鍵を書く。鍵は仕事に一つではなく接続の対ごとであり、接続が2本以上ある宣言では必須(結ぶ対が無ければ correlate none)。仕事の期限(U13)と on failure の欄の形は、あえて含めていない。机上検証では相関がフローの切り方を押す事が分かった — 受付と確定を別の宣言に切ると、在庫を戻す道が記述の上で切れる。同日に採用し、第4章 4.2 に correlate を、第3章 3.3 に E0023-1〜E0023-4・W0023-1 を、第5章 5.3 に語彙を入れた。U25 は閉じた。
  • 思考実験 22 → ADR 0024・0025 を起案した(2026-09-26)
    系譜に挙げる APoSD(深いモジュール)は一つのコンポーネントの形を問うが、コンポーネントの間の関係を問う知見(Khononov の結合バランス)は参照していなかった。思考実験 22 で既存の 01・02・08・20・21 を強度・距離・変動性で読み直すと、侵入結合の禁止・境界の層・correlate を同じ宣言に置く制約が、結合の語彙を使わずに釣り合いを保っていた。欠けていたのはモデル結合(data の共有)の距離で、08 の 商品の見出し と 20 の 注文 は actor まで届いていた。U14 論点1・2 への入力(K-a・K-b)を計画書 第5節に記し、ADR 0024(取り込みの範囲と既定値の対比)と ADR 0025(粒度のシグナル)を提案として起案した。
