設計意図から実装までを一本の記述で貫く言語 — docs/PLAN.md の4フェーズと、2026-11-07 時点の現在地。

1. フェーズと決定の地図

各フェーズは「動く最小の成果物」で締める。未解決課題 U1〜U22 は、それぞれの決定フェーズの下に置いた。言語仕様(Phase 0)の列で未決の課題は、ADR 0033(試作を先に置く進め方) により、最小の言語実装(Phase 1)の試作の中で仮に決めて確かめる。

2. 検討のいま

検討の領域ごとの現在の状態と、仕様の章の状態。

2-1. 検討の領域(docs/areas/)

仕様の検討は領域の木に分けてある。各領域の節は、その領域のフォルダの roadmap.js が差し込む(番号の一覧は docs/numbering.md)。

  • 図の読み方 — 左から課題・決定(ADR)・思考実験。線は、ADR が決めた課題(実線)・関連する課題(点線)と、ADR が依拠する思考実験を結ぶ。他の領域と結ぶ物は線を引かず「他の領域」と注記した。
  • 色 — 採用・執筆済み 提案・判断待ち 点線の枠は一部・先行のみ決定済み、打ち消し線は破棄、白い枠は ADR 無し(未着手・再検討中)。
  • 仕様の章との関係 — 各章が依拠する ADR は、章の頭の「依拠」の行にある(docs/spec/)。

2-2. 仕様の章立て(docs/spec/)

  • 第0章 ビジョン 四つの段初稿 ✓
  • 第1章 システムコンテキスト Context初稿 ✓
  • 第2章 コンポーネントの定義 Component・Code初稿 ✓
  • 第3章 制約の体系初稿 ✓
  • 第4章 通信モデル 段を跨ぐ関係初稿 ✓
  • 第5章 記述の表記 段に属さない・ADR 0014初稿 ✓
  • 第6章 データと型 段に属さない・データ宣言は record・choice・id(ADR 0028)・基本型 11 種(数値は ADR 0021、量の種別は 0022)初稿 ✓

3. 最小の言語実装(Phase 1)の試作の順

三つの試作を順に作り、各試作は動く物で締める。前の試作が動くまで次へ進まない(ADR 0033(試作を先に置く進め方) の決定3)。

  • 仮置き — 未決の課題は、試作の中で仮に決めて確かめる。仮置きは決まった事ではなく、仕様書には書かない。表は docs/PLAN.md 第4節「仮置き」にある。
  • 書き戻し — 試作で動いた事は仕様書に書き戻す。ADR を起こすのは、二つ以上の候補を比べて選ぶ時だけである。
  • それまでの検討順 — ADR の検討順(同時に採否を決めるステップ)と、Phase 1 へ移る条件・先に着手する部分は役目を終え、docs/PLAN.md から外した。古い記述は、計画書 第4節の冒頭にある外す直前の版へのリンクで読む。

4. 試作のループ

仕様だけを先行させないための往復。仮に決めて動かし、動いた事を仕様へ書き戻す。試作で決められない時(候補を比べる時、まだ作れない段を考える時)だけ、思考実験(docs/experiments/)に戻る。

往復の記録は、第2節 2-1(検討の領域)の各領域の節の「検証ループ」に、起きた順に置く。
