3. ADR の検討順

ADR は互いを改訂する。改訂される側を先に採ると採用の直後に書き直しが要り、改訂する側を先に採ると依拠先が提案のままで宙に浮く。そこで、改訂の関係にある ADR を束にして同時に採否を判断し、束を依拠の向き(名前 → 型 → 指針 → 接合面)に並べる。2026-08-28 の採用(0005・0013・0015)と 2026-08-29 の採用(0014)で束 A は空になり、束 B の一部も先に抜けた。残りだけを判断待ちとして示す。段の番号は採用の記録と対応が付くよう動かさない。

4. Phase 0 の検証ループ

仕様だけを先行させないための往復。U1(意図)・U2(通信)・省略の禁止(ADR 0008)に続き、2026-08-28 に U3(ADR 0005・0013)・U18(ADR 0015)が採用され、内部階層(強度と役割)とシステムコンテキストが確定した。2026-08-29 に U17(ADR 0014)も採用し、記述の表記が確定して第5章が加わった。判断待ちは U5(ADR 0012)・U7(ADR 0006)・U9(ADR 0009)・U15(ADR 0010・0017)・U14 の一部(ADR 0018)。配置の記述は ADR 0015 が「動作環境の設定として Phase 2 で決める」と答えた。採用の検証(思考実験 08)で U19〜U21 を新設し、U19(検証番号の採番)は ADR 0016 で即日決着した。ADR 0017 は思考実験 07 が洗い出した ADR 0010 の限界(近似が本質の計算が書けない)への差し戻しであり、このループが一周した例である。残る U20・U21 は U4・U10〜U14・U16 と併せて順次検討する。ADR 0018(提案)は、ADR 0015 が残した「1プログラム = 1システム」を外してシステムの入れ子(C4 の System Landscape)を許し、思考実験 08 の論点5 に機械検証できる問いを一つ足した。
