# 思考実験 19: 単位の種別 — 数える量・割合・位置を単位の体系に入れる

- 状態: Draft
- 日付: 2026-09-17
- 目的: `unitless` で書いていた「個数・版・連番」「列の添字・長さ」「税率」に単位を持たせ、
  **量を種別(足し算・掛け算の振る舞い)に分けて書き手が宣言する**形で、これまでの数値が書けるかを確かめる
- 進め方: 書き手の指定(下記)を出発点に、単位の性質を洗い出して種別を定め、思考実験 04・06・13・18 の数値を書き直す。
  書けない所・困る所を数え、結論を ADR 0022 に渡す

## 1. 出発点

第6章 6.3 と ADR 0021 は、次の値を `unitless` で書いていた。

```plaintext
int64(0) unitless   # 個数・版・連番
uint64(0) unitless  # 列の添字・長さ
int64(4) unitless   # 税率(0.1000 = 10%)
```

書き手から「これらも単位として指定してよいのではないか」という問いがあり、検討の上で次の2点が指定された。

| 指定                                         | 帰結                                                            |
| -------------------------------------------- | --------------------------------------------------------------- |
| **数える量は、掛けると単位が消える**         | `円 × 個 = 円`。単価は `円毎個` ではなく `円` と書く            |
| **単位を種別に分け、書き手が量を定義できる** | 種別(足し算を禁じる・掛けると消える 等)を選んで `量` を宣言する |

単価は**通貨として、円や米ドルと同じ扱い**にする。思考実験 13 は `円毎個` の読みを示したが、それは採らない。

思考実験 13 が「数える単位では U23 は解けない」とした主な理由(§3.1: 次元は通るが `整数 × 十進数` の型が合わない)は、
ADR 0021 で両辺が `int64` になった事で**既に消えている**。残る障害は §3.2〜3.6 の5つであり、本実験はそれらを種別で解けるかを見る。

## 2. 単位の性質を洗い出す

値に単位を付けるとき、言語が知る必要のある振る舞いは3つある。

| 軸     | 選択肢                                                    | 例                               |
| ------ | --------------------------------------------------------- | -------------------------------- |
| 足し算 | できる / 差とだけできる / できない                        | 長さ / 版・座標 / 郵便番号       |
| 掛け算 | 単位が残る(組立の量) / 単位が消える / できない            | 長さ×長さ=面積 / 円×個=円 / 版×3 |
| 換算   | 比で換算できる(`基準 <単位>`) / 換算できない(`基準 なし`) | メートル↔インチ / 円↔米ドル      |

換算の軸は ADR 0010 以来の物であり、他の2軸と独立している。**新しいのは足し算と掛け算の2軸**である。

### 2.1 組み合わせを数える

足し算3 × 掛け算3 = 9 通りのうち、意味を持つものを数える。

| 足し算         | 掛け算     | 意味があるか                                              | 例                   |
| -------------- | ---------- | --------------------------------------------------------- | -------------------- |
| できる         | 残る       | **ある**。物理量と貨幣                                    | メートル・秒・円     |
| できる         | 消える     | **ある**。数える量と比                                    | 個・人・パーセント   |
| できる         | できない   | 無い。足せる量は倍にもできる(3個 + 3個 + 3個 = 3個 × 3)   | —                    |
| 差とだけできる | 残る       | 無い。位置を倍にする事に意味が無い                        | —                    |
| 差とだけできる | 消える     | 無い。同上                                                | —                    |
| 差とだけできる | できない   | **ある**。順番と座標                                      | 版・連番・添字・座標 |
| できない       | (いずれも) | **数値型の仕事ではない**。識別子型・直和で書く(第6章 6.2) | 郵便番号・区分コード |

**意味を持つ組み合わせは3つしかない。** 「足し算ができて掛け算で消える」の中は、さらに2つに分かれる。

- **比** — 同じ量どうしの比(`税額 ÷ 小計`)。基準は数の 1 であり、何の比かは値の名前が言う。比 × 比 は比である。
- **数える量** — 数えた物の数(個・人・件)。基準は数える単位であり、個 × 個 に意味は無い(行数 × 列数 = 升目数 のように、宣言すれば意味を持つ)。

### 2.2 4つの種別

| 種別     | 足し算                        | 掛け算                     | 基準                   | 例                         |
| -------- | ----------------------------- | -------------------------- | ---------------------- | -------------------------- |
| **比率** | できる                        | 消える                     | 数の 1 (`unitless`)    | パーセント・税率・歩留まり |
| **計数** | できる                        | 消える(相手が比率なら残る) | 数える単位             | 個・人・件・行・要素       |
| **計量** | できる                        | 残る(組立の量の宣言が要る) | 基準単位 / なし        | メートル・秒・円・米ドル   |
| **位置** | 差の量とだけ。位置+位置は不可 | できない                   | 差の量の単位に対応する | 版・連番・添字・座標       |

`位置` は新しい物ではない。**`時点` と `量 時間` の関係(第6章 6.4)を、書き手が宣言できる形にしたもの**である。
`時点 + 時間の量 → 時点` であり、`時点 + 時点` は書けず、2つの時点の隔たりは演算子ではなく `隔たり(…)` で取る。

## 3. 宣言の形

```plaintext
量 <名前> <種別> 基準 <単位 | なし>
量 <名前> 位置 差 <差の量> 基準 <位置の単位>
単位 <名前> : <量> = <基準単位> × <比>
```

種別の欄に既定は無い(ADR 0008)。**書かれていなければ E0008-1** である。種別の綴り(ASCII の語彙)は Phase 1 で決める(第5章 5.3)。

```plaintext
量   通貨   計量 基準 なし             # 円・米ドルは換算比を持たない
単位 円     : 通貨
単位 米ドル : 通貨

量   長さ   計量 基準 メートル
単位 センチメートル : 長さ = メートル × 1/100

量   個数   計数 基準 個
単位 ダース : 個数 = 個 × 12
単位 ケース : 個数 = 個 × 24

量   人数   計数 基準 人
量   件数   計数 基準 件

量   版差   計数 基準 版               # いくつ版を進めたか
量   版番号 位置 差 版差 基準 版目      # 何版目か

単位 パーセント       : unitless = unitless × 1/100   # 比率の量に単位を足す
単位 ベーシスポイント : unitless = unitless × 1/10000
```

### 3.1 比率の量は言語が1つだけ持つ

比率の基準は必ず数の 1 である。**比率の量を書き手が宣言できるようにすると、基準が 1 の量が複数でき、互いに換算できるのに足せない**という奇妙な体系になる。
そこで、比率の量は言語が1つだけ持ち、その基準単位を `unitless` とする。書き手は**単位だけを足せる**(`パーセント`・`ベーシスポイント`)。

- `税率 + 割引率` は足せる。何の比かは値の名前が言う(`時間` を `待ち時間` と `実行時間` に分けないのと同じ)。
- `税率 + 個数` は足せない。個数は計数の量であり、比率とは別の量だからである(E0010-1)。

### 3.2 位置の単位は差の単位と1対1に対応する

`版目`(位置)と `版`(差)は同じ刻みであり、`3 版目 + 2 版 = 5 版目` である。日本語の「〜目」が序数を表す慣習と一致し、読み違えにくい。

- 位置の量は**単位を1つだけ持つ**。原点をずらした単位(摂氏と華氏の絶対温度)は本実験では扱わない(§10 論点6)。
- 位置の量の数値型は差の量と同じ規則に従う(`int`/`uint`/`float`。`dec` は内部計算のみ)。

## 4. 掛け算・割り算の規則 — 強さの順

種別に **比率 < 計数 < 計量** の強さの順を置くと、乗除算の規則が1本にまとまる。位置は乗除算に現れない。

### 4.1 掛け算

| 左辺 \ 右辺 | 比率       | 計数                 | 計量                 |
| ----------- | ---------- | -------------------- | -------------------- |
| 比率        | 比率       | 右辺の計数           | 右辺の計量           |
| 計数        | 左辺の計数 | 組立の量の宣言が要る | 右辺の計量           |
| 計量        | 左辺の計量 | 左辺の計量           | 組立の量の宣言が要る |

**強い方の単位が残り、弱い方が消える。同じ強さどうしは、比率を除いて組立の量の宣言が要る**(E0010-5 のまま)。

- `int64(2) 円 × int64(0) 個` → `int64(2) 円`
- `int64(0) 個 × int64(2) パーセント` → `int64(2) 個`(在庫 × 歩留まり)。位取りは後述の 4.3 による
- `量 升目数 計数 = 行数 × 列数` を宣言すれば、`行数 × 列数` は `升目数` になる

### 4.2 割り算(`割る`・`分ける`)

| 被除数 \ 除数 | 比率         | 計数                             | 計量                             |
| ------------- | ------------ | -------------------------------- | -------------------------------- |
| 比率          | 比率         | 組立の量の宣言が要る             | 組立の量の宣言が要る             |
| 計数          | 被除数の計数 | 同じ量なら比率。違えば宣言が要る | 組立の量の宣言が要る             |
| 計量          | 被除数の計量 | 被除数の計量                     | 同じ量なら比率。違えば宣言が要る |

- **弱い方で割ると、弱い方が消える。** `円 ÷ 人 = 円`(割り勘)、`税込 ÷ 110 パーセント = 税抜`。
- **同じ量どうしで割ると比率になる。** `税額 ÷ 小計` は `unitless`、`件 ÷ 件` も `unitless`。単位が違えば基準へ換算してから割る(換算比を持たない量は同じ単位どうしに限る。E0010-2)。
- **強い方で割るには、組立の量の宣言が要る。** `個 ÷ 円`(1円あたりの個数)・`件 ÷ 人`(1人あたりの件数)は、宣言した量だけが存在する。

### 4.3 比率の単位は位取りに畳み込む

比率の単位の比が 10 の冪(`1/100`・`1/10000`)なら、単位を消す時にその比を**位取りへ足す**。丸めは起きない。

```plaintext
小計 × 税率   # int64(2) 円 × int64(2) パーセント
              # 位取り = 2 + 2 + 2(パーセントの比 1/100)= 6 → int64(6) 円
```

- 比が 10 の冪でない比率の単位(書き手が `1/3` を宣言した場合)は、消す所で丸めが避けられない。**丸めの宣言が無ければ E0010-3** である。
- 比が 10 の正の冪(`× 10`)なら `m` を 10 倍する。溢れ得る(ADR 0021 決定5 の失敗のまま)。
- 計数の単位(`ダース`)は掛け算で消える時に比を掛けない。**消えるのは単位であって量ではない**——`int64(2) 円 × int64(0) ダース` は「1ダースあたり何円か」を知らずに `円` になり、これは書き手の値の意味の問題である(§10 論点3)。

### 4.4 足し算と比較

- 比率・計数・計量: **同じ量どうしだけ**(E0010-1 のまま)。単位が違えば ADR 0010 以来の規則で換算する。
- 位置: `位置 + 差`・`位置 - 差` → 位置。`差 + 位置` は書かない(`時点` と同じく左辺が位置)。
- 位置どうしは**比較だけ**ができる。`位置 + 位置` と `位置 - 位置` は書けない。
- 位置の隔たりは `隔たり(<始め>, <終わり>, <型>)` で取り、結果は `<型> <差の単位>` になる。**結果の型は符号付きに限る**(逆向きの隔たりが負になるため)。
  丸めは起きないため丸めの欄を持たない(`float` の `÷` が `割る` を持たないのと同じ理由)。
- `合算(列)` は比率・計数・計量に書け、位置には書けない。

## 5. 書き下ろし1 — 明細と請求(思考実験 18 の2節)

```plaintext
data 明細 {
  単価: int64(2) 円,
  数量: int64(0) 個,
}

data 請求 {
  小計: int64(2) 円,
  税率: int64(2) パーセント,   # 10.00 = 10%
  税額: int64(2) 円,
  合計: int64(2) 円,
}
```

```plaintext
金額 = 単価 × 数量                                   # 計量 × 計数 → int64(2) 円
税額 = 丸める(小計 × 税率, int64(2), 丸め 切り捨て)    # int64(6) 円 → int64(2) 円
合計 = 小計 + 税額                                   # int64(2) 円
```

**書ける。** 思考実験 18 の書き下ろしと比べて、次が変わった。

| 箇所         | 思考実験 18                         | 本実験                | 変わった事                                  |
| ------------ | ----------------------------------- | --------------------- | ------------------------------------------- |
| 数量         | `int64(0) unitless`                 | `int64(0) 個`         | 件数・行数と取り違えると落ちる              |
| 税率         | `int64(4) unitless  # 0.1000 = 10%` | `int64(2) パーセント` | 注記が要らない。`10` と `0.10` を型が分ける |
| 金額の式     | `円 × unitless = 円`                | `円 × 個 = 円`        | 規則は強さの順の1本になった                 |
| 税額の位取り | `2 + 4 = 6`                         | `2 + 2 + 2 = 6`       | 同じ結果。比が位取りに畳まれる              |

`dec` を挟む書き方(思考実験 18 の 7.3)も変わらない。

```plaintext
素   = 変換(小計, dec(18.2)) × 変換(税率, dec(3.2))   # dec(19.6) 円。パーセントの比 1/100 は位取りへ畳まれる
税額 = 収める(素, int64(2), 丸め 切り捨て)
```

### 5.1 ケースで仕入れて個で売る

```plaintext
data 仕入 { 箱数: int64(0) ケース, 箱単価: int64(2) 円 }

仕入額 = 仕入.箱単価 × 仕入.箱数                                # int64(2) 円
在庫   = 換算(仕入.箱数, 個, int64(0), 丸め 切り捨て)           # int64(0) 個。比 24、丸めは起きない
```

**`3 ケース` を `3 個` として在庫に足す誤りは落ちる**(`個` と `ケース` は同じ量だが単位が違い、足すには換算が要る)。
思考実験 13 が「本当の利得」とした検査が、そのまま手に入った。

## 6. 書き下ろし2 — 按分と一人当たり(思考実験 06 の按分)

```plaintext
data 割り勘 { 合計: int64(2) 円, 人数: int64(0) 人 }

(一人分, 余り) = 分ける(割り勘.合計, 割り勘.人数)   # 計量 ÷ 計数 → int64(2) 円、余りも円
```

**書ける。** 思考実験 18 の 2.4 で「除数の型」として詰まった所は、ADR 0021 の論点1(幅と符号だけ揃える)と強さの順で通る。

```plaintext
量 一人当たり件数 計数 = 件数 ÷ 人数

処理率 = 割る(処理件数, 担当者数, int64(2), 丸め 切り捨て)   # int64(2) 一人当たり件数
```

`件 ÷ 人` は同じ強さ(計数どうし)で量が違うため、**宣言が無ければ E0010-5** である。
これは書き手に「1人あたりの件数」という量の名前を求める——`件` のまま受けると、件数の欄へ一人当たりの値を渡す誤りが落ちなくなるからである。

```plaintext
達成率 = 割る(実績件数, 目標件数, int64(2), 丸め 切り捨て)   # 件 ÷ 件 → int64(2) unitless
表示率 = 換算(達成率, パーセント, int64(2), 丸め 切り捨て)    # unitless → パーセント。比 100、丸めは起きない
```

同じ量どうしの比は比率になり、パーセントとの往来は換算で書ける。

## 7. 書き下ろし3 — 版と連番(思考実験 04 の KV ストア・U24)

```plaintext
量 版差   計数 基準 版
量 版番号 位置 差 版差 基準 版目

data 書込記録 { キー: キー, 値: 値, 版: int64(0) 版目 }
```

思考実験 12 の 5節は、版について「比較と +1 しかせず」と書いていた。その2つだけが書ける。

```plaintext
新しい版 = 現在.版 + 1 版              # 位置 + 差 → int64(0) 版目
上書き可 = 受信.版 > 現在.版            # 位置どうしの比較
遅れ     = 隔たり(受信.版, 現在.版, int64(0))   # int64(0) 版

現在.版 + 受信.版                       # E0022-1。位置 + 位置
現在.版 × 3                             # E0022-2。位置の乗算
```

**U24(序数と基数の区別)が、新しい基本型を足さずに解けた。** 「版3 + 版5」は型が落とす。

- リテラルの綴り(`1 版`)は本実験の仮置きであり、Phase 1 で決める。
- 連番も同じ形で書ける(`量 受注件数 計数 基準 件`、`量 受注連番 位置 差 受注件数 基準 件目`)。
- ページ番号も同じである(`ページ目`)。

### 7.1 外部との詰め替え

```plaintext
受信値 = 復号(受信, int64(0), ビッグエンディアン)   # int64(0) unitless
版     = 単位を付ける(受信値, 版目)                  # body 内でのみ書ける
```

`復号` の結果は今のまま `unitless` である(ADR 0021 決定9)。位置の単位も `単位を付ける` で付けられる。
**`unitless` から位置を作る操作は `単位を付ける` だけ**であり、ここが境界の目印になる。

## 8. 書き下ろし4 — 列の添字と長さ(E0019-4)

思考実験 13 の §3.3 は「`list<商品>` の長さは `個`、`list<明細>` の長さは `行`」とすると要素の型で単位が決まり、依存型に近づくと指摘した。
そこで、**言語が最初から持つ量を2つ置く**(`量 時間` と同じ扱い)。

```plaintext
量 要素数 計数 基準 要素                 # 言語が持つ
量 要素番号 位置 差 要素数 基準 要素目     # 言語が持つ
```

| 値           | 型                 | 種別 |
| ------------ | ------------------ | ---- |
| 列の長さ     | `uint64(0) 要素`   | 計数 |
| 繰り返し回数 | `uint64(0) 要素`   | 計数 |
| 列の添字     | `uint64(0) 要素目` | 位置 |

```plaintext
先頭 = 0 要素目
末尾 = 先頭 + 長さ(明細列) - 1 要素    # 位置 + 差 - 差 → uint64(0) 要素目。空の列なら範囲外で失敗
行   = 明細列[末尾]

明細列[長さ(明細列)]                    # E0019-4。添字に計数を書いている
```

**添字と長さの取り違え(off-by-one の一因)が型に出た。** 長さを添字に使うには、原点に足して位置にする事を書く。

### 8.1 要素数を業務の個数にする

```plaintext
件数 = 単位を付ける(単位を外す(長さ(注文列)), 件)   # 要素 → 件
```

**これが手間として現れる。** `要素` と `件` は別の量であり、比も無い。
しかし「注文の列の要素数が注文の件数である」は書き手の知識であって言語の知識ではない——明細の列の要素数は注文の件数ではない。
手間は、この知識をソースに書かせる代償である(§10 論点4)。

## 9. 書き下ろし5 — 計測と座標(思考実験 02・06)

```plaintext
量 長さ 計量 基準 メートル
量 座標 位置 差 長さ 基準 メートル地点

data 測点 { x: float64 メートル地点, y: float64 メートル地点 }

移動後 = 測点.x + 変位         # float64 メートル地点 + float64 メートル → float64 メートル地点
距離   = 隔たり(始点.x, 終点.x, float64)   # float64 メートル
始点.x + 終点.x                # E0022-1
```

座標と変位の取り違えが型に出る。**位置の量は整数だけの物ではない**事が確かめられた。

`温度` は `計量 基準 なし` のまま残す。摂氏・華氏の絶対温度は位置の量だが、原点をずらした単位を扱う規則を持たないためである(§10 論点6)。

## 10. 見つかった論点

| # | 論点                                   | 中身                                                                                                |
| - | -------------------------------------- | --------------------------------------------------------------------------------------------------- |
| 1 | **計数どうしの乗除算**                 | `件 ÷ 人`・`行数 × 列数` は組立の量の宣言を要する(§6)。書き手の指定「数える量は消える」の範囲の確認 |
| 2 | **単価と金額が同じ `円` になる**       | 単価を金額の欄へ渡す誤りは型で落ちない。書き手の指定による代償                                      |
| 3 | **計数の単位は消える時に比を掛けない** | `円 × ダース` は `円`。「1ダースあたり」かどうかは値の名前が言う(§4.3)                              |
| 4 | **`要素` と業務の計数の往来**          | `単位を外す` → `単位を付ける` の2段が要る(§8.1)                                                     |
| 5 | **比率の量は1つ**                      | 書き手は単位だけを足せる。`税率 + 割引率` は足せる(§3.1)                                            |
| 6 | **原点をずらした位置の単位**           | 摂氏・華氏の絶対温度は位置だが、単位の間にずれがある。本実験では扱わない(§9)                        |
| 7 | **リテラルの綴り**                     | `1 版`・`0 要素目` は仮置き。Phase 1 のパーサで決める                                               |
| 8 | **宣言の数**                           | 位置の量は差の量と対で宣言する。版・連番・ページごとに2行ずつ増える                                 |

### 10.1 論点1 への案

| 案                                             | 利点                                    | 欠点                                                  |
| ---------------------------------------------- | --------------------------------------- | ----------------------------------------------------- |
| (a) **同じ強さどうしは組立の量の宣言を要する** | 計量の規則(E0010-5)と同じ形。例外が無い | `件 ÷ 人` のたびに量の宣言が要る                      |
| (b) 計数どうしは左辺が残る                     | 宣言が要らない                          | `件 × 人 = 件` が通り、左右を入れ替えると結果が変わる |
| (c) 計数どうしは両方消えて `unitless`          | 宣言が要らない                          | 何の数かが消え、書き手が単位を付け直す事になる        |

**(a) を推す。** 書き手の指定は「数える量は掛けると消える」であり、その相手は計量(`円 × 個`)と比率である。
計数どうしの積は数えた物が2種類ある場面であり、**どちらを残すかを言語が決めると、読み手は左右の順を覚える事になる**。
計量どうしの積に宣言を要する規則(ADR 0010)と同じ形で閉じる方が、覚える事が少ない。

### 10.2 論点2 への案

- 単価と金額の区別は**単位ではなく欄の名前**に置く。`data 明細 { 単価: int64(2) 円, … }` の名前が値の意味を言う。
- 取り違えを型で落としたい書き手は、今後の型の別名(`data 単価 = int64(2) 円`。ADR 0021 の将来の変更想定)で名前的に分けられる。
- **量と単位で落とすのは次元の誤り(長さ + 重さ)であり、同じ次元の中の役割の誤りではない**——この線引きを ADR に残す。

## 11. 検証結果

### 11.1 書けた事

- 明細の金額(`円 × 個`)・税額(`円 × パーセント`)・按分(`円 ÷ 人`)が、**強さの順の規則1本で書けた**。
- `unitless` の3つの例が、それぞれ計数(`個`)・位置(`版目`・`要素目`)・比率(`パーセント`)の単位で書けた。
- **U24(序数と基数)が、新しい基本型を足さずに位置の量で解けた。** 版・連番・添字・座標のいずれでも、位置 + 位置は落ちる。
- 思考実験 13 が挙げた検査(ケースと個の取り違え・件数と行数の取り違え)が、そのまま手に入った。
- 税率の注記(`0.1000 = 10%`)が型に吸収された。

### 11.2 思考実験 13 の障害は解けたか

| 13 の節 | 障害                       | 本実験での扱い                                                          |
| ------- | -------------------------- | ----------------------------------------------------------------------- |
| 3.1     | 次元は通るが型を跨ぐ       | **消えた**(ADR 0021 で両辺が `int64`)                                   |
| 3.2     | 単位なしのスカラー倍が残る | **比率の種別として規則に入った**。`unitless` は比率の量の基準単位になる |
| 3.3     | 列の長さで原則が破れる     | **言語が持つ `要素`・`要素目` で閉じた**。代償は §8.1 の往来            |
| 3.4     | 序数まで加算可能に見える   | **位置の種別で解けた**(U24)                                             |
| 3.5     | 助数詞の数だけ宣言が増える | **残る**。ただし換算比を持たない計数は1行で済む(`量 人数 計数 基準 人`) |
| 3.6     | 採用済みの決定と衝突する   | 第6章は既に物理量に限定していない。ADR 0021 の決定4・11 を改訂する      |

### 11.3 判定

**種別の体系は書ける。** 種別を4つに固定し、書き手は量と単位を定義する時に種別を選ぶ。
種別の規則を書き手が作れるようにはしない——意味を持つ組み合わせは §2.1 の3つ(と比率の分かれ)しかなく、
自由に組ませても無意味な組み合わせが増えるだけであり、同じ `×` の意味がプロジェクトごとに変わるためである。

交換したのは次の一組である。

| 得た物                                   | 払った物                                     |
| ---------------------------------------- | -------------------------------------------- |
| 数える量・比・順番の取り違えが型で落ちる | 量の宣言が増える(位置は差と対で2行)          |
| U24 が解ける                             | 種別の欄を全ての量の宣言に書く               |
| 税率の意味が型から読める                 | 単価と金額は単位で区別できない(書き手の指定) |
| 添字と長さが型で分かれる                 | `要素` と業務の計数の往来に2段の操作が要る   |

## 12. 未解決課題への入力

- **U24(序数と基数)**: 位置の種別で解く。ADR 0022 で決める。
- **U15・U23(数値型)**: ADR 0021 の決定4(`unitless` とのスカラー倍)と決定11(添字と長さ)を ADR 0022 が改訂する。
- **U9(データ型)**: 単価と金額の役割の区別は型の別名(名前的型付け)に置く(§10.2)。
- **U13(失敗の体系)**: 位置 - 差 が `uint` の範囲を出る事(空の列の末尾)は、ADR 0021 の「加減乗の結果が幅を出る」に含まれる。新しい失敗は増えない。
- **U14(プログラム宣言)**: 言語が持つ量が `時間` に加えて `要素数`・`要素番号` と比率の量になる。量の可視範囲(PLAN 第5節 5.4)の対象が増える。
