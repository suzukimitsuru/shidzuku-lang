# 思考実験 13: 数える単位 — スカラー倍を「個」に制限できるか(U23)

- 状態: Draft
- 日付: 2026-08-29
- 目的: U23(数値型を跨ぐスカラー倍)に対する「**数える値にも単位を持たせる**」案を書き下ろし、何が解け何が解けないかを分ける
- 進め方: 制限案を実際に書いてみて、既存の決定(第6章)と衝突する所を数える。解ける問題と解けない問題を明示的に分ける

## 1. 問題のおさらい

思考実験 12 の論点1。明細行の金額が書けない。

```plaintext
data 明細 { 単価: 十進数(7.2) 円, 数量: 整数 単位なし }
単価 × 数量        # E0019-3。3つの数値型が明示の変換なしに混ざる
```

書くには `収める(数量, 十進数(5.0))` を挟む。**これが全ての明細行に現れる。**

検討する案は「**数量に `個` のような単位を持たせれば、スカラー倍を単位の体系で扱えるのではないか**」である。

## 2. 制限案を書き下ろす

### 2.1 数える量と単位を宣言する

```plaintext
量 個数 基準 個
単位 ダース : 個数 = 個 × 12
単位 ケース : 個数 = 個 × 24

data 明細 { 単価: 十進数(7.2) 円, 数量: 整数 個 }
```

ここまでは第6章 6.3 の語彙でそのまま書ける。**量と単位の宣言は物理量に限られていない。**

### 2.2 掛けると何になるか

`十進数(7.2) 円 × 整数 個` の結果の量は `通貨 × 個数` である。第6章 6.3 はこう定める。

> **組立の量は宣言されたものだけが存在する**(E0010-5)。無名の量は作らない。

つまり `量 円個 = 通貨 × 個数` を宣言しなければ書けない。**しかし答えは「円」であってほしい。**

次元として正しいのは、**単価が「円」ではなく「円毎個」である**という読みである。

```plaintext
量 単価 = 通貨 ÷ 個数 基準 円毎個

data 明細 { 単価: 十進数(7.2) 円毎個, 数量: 整数 個 }
単価 × 数量        # 円毎個 × 個 = 円。次元は通る
```

**次元の側は、これで完全に通る。** そして得るものもある。

| 得られる検査             | 例                                           |
| ------------------------ | -------------------------------------------- |
| 数える単位の換算         | `3 ケース` を `72 個` へ、比 24 で厳密に換算 |
| 数える量どうしの取り違え | `件数` と `行数` を足すとエラー(E0010-1)     |
| 単価と金額の取り違え     | `円毎個` を `円` の欄へ渡すとエラー          |

## 3. しかし、解けていない

### 3.1 型を跨ぐ問題は残る — 単位の軸と型の軸は直交している

`十進数(7.2) 円毎個 × 整数 個` は、**次元は通るが型が違う**。E0019-3(3つの数値型が明示の変換なしに混ざる)はそのまま落ちる。

| 軸       | 何を見るか   | この案で変わるか   |
| -------- | ------------ | ------------------ |
| 量と単位 | 次元が合うか | **合うようになる** |
| 数値型   | 表現が同じか | **変わらない**     |

U23 は**型の軸の問題**である。単位を必須にしても、`整数` を `十進数` の式に混ぜる事は依然として書けない。
**この案は U23 を解かない。**

### 3.2 単位なしのスカラー倍は消えない — 割合と率が残る

数える値に単位を持たせても、**本当に無次元の値**は残る。

```plaintext
data 請求 { 小計: 十進数(9.2) 円, 税率: 十進数(1.4) 単位なし }
小計 × 税率        # 円 × 単位なし = 円。これはスカラー倍そのもの
```

税率・割引率・掛け率・確率・歩留まりは、ISO 80000-1 でいう**次元が 1 の量**であり、単位は「1」である。
第6章 6.3 も「割合・税率は `単位なし`」としている(ADR 0010、思考実験 06 の 3.2-3)。

**したがって「単位なしとの乗除算」は、どのみち規則が要る。** 数える値に単位を持たせても、その規則は消えない。

### 3.3 列の長さで原則が破れる

第6章 6.3 はこう定める。

> 列の添字・長さ・繰り返し回数は `整数 単位なし` に限る(E0019-4)。

「数える値には単位を持たせる」を原則にすると、**列の長さは何の単位か**が問題になる。

- `list<商品>` の長さは `整数 個`?  `list<明細>` の長さは `整数 行`?
- 要素の型ごとに量が変わる事になり、**型引数に依存して単位が決まる**(依存型に近づく)。
- 単位を持たせないなら E0019-4 のままで、**「数える値は単位を持つ」という原則が全域でなくなる**。

原則が全域でない事は、それ自体が欠点である。書き手は「どの数える値に単位が要るか」を覚える事になる。

### 3.4 序数と基数の区別が新しく必要になる

数えた値には、**足して意味のあるもの(基数)と無いもの(序数)**がある。

| 値           | 種類 | 足せるか                 |
| ------------ | ---- | ------------------------ |
| 注文の数量   | 基数 | 足せる(3個 + 5個 = 8個)  |
| 在庫数       | 基数 | 足せる                   |
| 版・世代番号 | 序数 | **足せない**(版3 + 版5?) |
| ページ番号   | 序数 | **足せない**             |
| 列の添字     | 序数 | **足せない**             |
| 受注の連番   | 序数 | **足せない**             |

単位を持たせると、**序数まで加算可能に見えてしまう**。`整数 版` と `整数 版` は同じ量なので E0010-1 に落ちない。
現在は `整数 単位なし` で一様に足せてしまうため状況は同じだが、**単位を強制すると「単位があるのに足してはいけない値」という説明が要る**。

序数を型で分ける道はある(`序数 版` のような別の型)。しかしそれは U23 とは別の、より大きな決定になる。

### 3.5 助数詞の数だけ宣言が増える

日本語の助数詞は数百ある。業務システムに現れるものだけでも多い。

```plaintext
量 個数 基準 個      量 件数 基準 件      量 行数 基準 行
量 台数 基準 台      量 人数 基準 人      量 回数 基準 回
量 枚数 基準 枚      量 本数 基準 本      量 箱数 基準 箱
```

- **換算比を持つのは一部だけ**である。個↔ダース↔ケースは比を持つが、件↔行は持たない(注文1件が何行かは注文ごとに違う)。
- 比を持たない量は `基準 なし` で宣言する事になる(第6章 6.3。通貨・温度と同じ形)。
- **宣言の数が業務語彙の数だけ増える。** ADR 0010 が「組立の量は宣言されたものだけ」とした重さが、数える値の全部に掛かる。

### 3.6 採用済みの決定と衝突する

第6章 6.3 はこう書いている(ADR 0010、思考実験 06 の 3.2-3 が裏付け)。

> 単位を付ける対象は物理量と貨幣に限り、個数・回数・割合・税率は `単位なし` とする。

**数える値に単位を必須にする案は、この決定を正面から改訂する。** 改訂には思考実験 06 の判断を覆す根拠が要るが、
本実験で見つかったのは「次元は通るようになるが U23 は解けない」であり、覆すだけの根拠になっていない。

## 4. 検証結果

### 4.1 判定 — 制限案は U23 を解かない

| 期待した効果                       | 実際                                      |
| ---------------------------------- | ----------------------------------------- |
| スカラー倍が単位の体系で扱える     | 次元は通るが、**型を跨ぐ問題は残る**(3.1) |
| 単位なしのスカラー倍が要らなくなる | **残る**。割合・税率は本当に無次元(3.2)   |
| 数える値の取り違えが落ちる         | **落ちる**(2.2)。これは本当の利得         |

**単位の軸と数値型の軸は直交している。** U23 は型の軸の問題であり、単位を必須にしても解けない。

### 4.2 しかし、捨てるには惜しい — 別の課題として切り出す

数える単位が**落とす誤り**は本物である。

- `3 ケース` を `3 個` として扱う誤り(比 24 の換算忘れ)
- `件数` と `行数` の取り違え
- `単価`(円毎個)を `金額`(円)の欄へ渡す誤り

そして**これらは今でも書ける**。第6章 6.3 の量と単位の宣言は物理量に限定されておらず、
「単位を付ける対象は物理量と貨幣に限る」は**指針**であって禁止ではない。

→ 指針を「**数える値にも、換算比を持つ単位があるなら付けてよい**」へ緩める事は、決定の改訂ではなく指針の明確化で足りる。

### 4.3 U23 そのものへの入力 — 型の軸で解く3案

| 案                                                    | 利点                                       | 欠点                                            |
| ----------------------------------------------------- | ------------------------------------------ | ----------------------------------------------- |
| (a) `単位なし` の `整数` によるスカラー倍を暗黙に許す | 明細行が素直に書ける                       | 「暗黙の変換を置かない」の例外が1つできる       |
| (b) 現状のまま明示の変換を書かせる                    | 例外が無い                                 | 全ての明細行に `収める(…)` が現れる             |
| (c) `倍する(<値>, <整数>)` という名前のある操作を置く | 例外を作らず、名前が「スケールする」と言う | 語彙が1つ増え、`×` と `倍する` の使い分けが要る |

- (a) は丸めが原理的に起きない向き(`整数` → `十進数`)に限れば安全である。しかし `実数` 側では 2^53 を超える整数が丸まる(W0019-1)。
- (c) は ADR 0010 が除算に `割る(…)` を要求したのと同じ形である。**演算子でなく名前にする**事で、変換が起きている事を読み手に見せる。
- 本実験は (c) を推す。理由は「例外を作らない」——第6章 6.3 の「3つの数値型は暗黙に混ざらない」を一つも崩さずに済む。

### 4.4 新しく見つかった論点 — 序数

3.4 で出た**序数と基数の区別**は、単位の話とは独立に存在する。

- `版` `ページ番号` `列の添字` `連番` はいずれも `整数 単位なし` であり、**足し算が書けてしまう**。
- 「版3 + 版5」に意味は無いが、型は落とさない。
- ADR 0010 が量と単位で「距離 + 重さ」を落としたのと同じ問題が、**数える値の中に残っている**。

これは U23 とは別の課題である(下記 5)。

## 5. 未解決課題への入力

- **U23(数値型を跨ぐスカラー倍)**: 単位を必須にする案は U23 を解かない(4.1)。型の軸で解く(4.3)。本実験は `倍する(…)` を推す。
- **U9(データ型の記述)**: 第6章 6.3 の指針「単位を付ける対象は物理量と貨幣に限る」を、
  「**換算比を持つなら数える単位にも付けてよい**」へ緩める(4.2)。決定の改訂ではなく指針の明確化。
- **U24(新設。序数と基数)**: `版`・`ページ番号`・`列の添字`・`連番` は数えた値だが足し算に意味が無い(4.4)。
  型で分けるか、指針に留めるか。分けるなら基本型が1つ増える。

## 6. 次の行動

- U23 の ADR を起案する際、4.3 の3案と本実験の推奨((c) `倍する`)を入力とする
- 第6章 6.3 の単位の指針を緩める(U9 の小さな改訂)
- U24(序数と基数)を登録し、必要が確認されたら思考実験を回す
