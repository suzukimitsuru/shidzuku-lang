# 思考実験 07: 数値型の限界と指数部(ADR 0010 の反証試験)

- 状態: Draft
- 日付: 2026-08-25
- 目的: ADR 0010(提案)の数値型で**書けない数・書けない計算**を洗い出し、指数部の追加で改善するかを判定する
- 進め方: これまでの思考実験が「書けるか」を試したのに対し、本実験は逆向きに**反証を探す**。書けない事が見つかったら、それが原理的な限界か、設計で救えるものかを分ける

## 1. 表現できない数の棚卸し

ADR 0010 の数値は `m × 10^-s`(`m` は宣言桁に収まる符号付き整数、`s` は宣言された小数部桁)である。この形に載らない数を4種に分けた。

| 種       | 例                         | 原因                           | 設計で救えるか     |
| -------- | -------------------------- | ------------------------------ | ------------------ |
| 循環小数 | 1/3、1/7、1/6              | 分母に 2・5 以外の素因数がある | 救えない(丸めのみ) |
| 無理数   | √2、π、e                   | 有限の位取り表現に載らない     | 救えない(丸めのみ) |
| 窓の外   | 電子の質量、0.4 円の累積   | 桁の窓の位置・幅が合わない     | 救える             |
| 桁の爆発 | 複利 `(1+r)^360`、連鎖乗算 | 厳密解の桁数が指数的に増える   | 救える(丸めの宣言) |

### 1.1 循環小数 — 原理的に書けない

有限の十進小数になるのは、既約分数の分母が `2^a × 5^b` の形のときだけである。

```plaintext
有限になる分母(20 以下): 1, 2, 4, 5, 8, 10, 16, 20
ならない分母(20 以下): 3, 6, 7, 9, 11, 12, 13, 14, 15, 17, 18, 19
```

1/3 は何桁取っても書けない。これは十進固定小数点の欠陥ではなく**位取り記数法の性質**であり、二進でも、指数部を足しても変わらない。ADR 0010 が除算に丸めの宣言を要求しているのは、この限界を設計の表面に出すためである。

丸めた後の値は元に戻らない。`割る(1, 3, 数値(1.3), 丸め 四捨五入) × 3` は `0.999` であり `1` ではない。按分のように「分けて足すと元に戻る」事が要る場面は、除算ではなく `分ける`(商と余り)で書く——この切り分けは ADR 0010 で既に決着している。

### 1.2 無理数・超越数 — 原理的に書けない

√2・π・e は有限桁で書けない。従って以下の計算は、丸めなしには結果を得られない。

| 計算       | 現れる場面                        | 結果         |
| ---------- | --------------------------------- | ------------ |
| 平方根     | 標準偏差、二点間の距離、RMS       | 一般に無理数 |
| 三角関数   | 座標変換、緯度経度からの距離      | 一般に無理数 |
| 対数・指数 | デシベル、情報量、連続複利        | 一般に無理数 |
| 累乗(実数) | 年利から月利への換算 `(1+r)^1/12` | 一般に無理数 |

ADR 0010 は四則しか定めておらず、これらの演算の記述形式が**未定のまま残っている**。除算と同じく「結果の桁と丸め方の宣言を要求する」形に揃えれば体系は保てる。

### 1.3 桁の窓から外れる — 上と下

宣言した桁は、値の取れる**窓**を決める。窓から外れる値は2方向ある。

- **上に溢れる**: `数値(9.0) 円` に 10 億円は入らない。ADR 0010 は `収める` の直和(`数値(9.0) 円 | 桁溢れ`)で扱うと決めており、実行時に黙って壊れる事はない。**決着済み**。
- **下に消える**: `数値(9.0) 円`(刻み 1 円)に 0.4 円は入らず、丸めれば 0 になる。1回の丸めは宣言されているが、**繰り返すと累積する**。0.4 円の計上を 1000 回丸めれば 400 円が消える。

後者は ADR 0010 の穴である。丸めの宣言が示すのは**1回の誤差の上限**であって、反復回数を掛けた上限は型に現れない。

### 1.4 桁が爆発する計算

厳密に計算し続けると桁が指数的に増える。月利 0.4167%(小数部6桁)の複利を 360 か月分、厳密に求めた場合:

```plaintext
(1.004167)^360 の厳密解 = 小数部 2160 桁(6 桁 × 360 回)
必要な記憶域 = 約 898 バイト
実際に意味のある値 = 4.468278...
```

有効数字 7 桁の答えを得るために 898 バイトを費やす事になる。**累乗は各段で丸めを宣言しなければ実用にならない**。これも ADR 0010 に演算が無く、未定のまま残っている。

### 1.5 表現はできるが割に合わない — 窓の位置が極端な値

物理定数は、有効桁は少ないのに窓の位置が原点から遠い。

| 値                        | 指数部なしの宣言 | 総桁 | バイト |
| ------------------------- | ---------------- | ---- | ------ |
| 電子の質量 9.10938e-31 kg | `数値(0.36)`     | 36   | 16     |
| 素粒子の断面積 1e-28 m²   | `数値(0.33)`     | 33   | 16     |
| プランク定数 6.62607e-34  | `数値(0.39)`     | 39   | 32     |
| アボガドロ定数 6.02214e23 | `数値(24.0)`     | 24   | 16     |

有効桁は6桁(必要なのは4バイト)なのに、位置を表すためだけに 16〜32 バイトを使う。無駄なのは**桁の幅ではなく位置**である。

### 1.6 数値型の管轄外

以下は「大きな数」に見えるが数値ではない。ADR 0009 の識別子型・バイト列が担当し、数値型の限界ではない。

- 暗号鍵・ハッシュ値(256 ビット) — 演算対象ではなく同一性の対象
- 連番 ID・口座番号 — 加減算に意味がない(ADR 0009 の識別子型)

### 1.7 桁と2のべきの境目

十進の桁を単位にすると、二進の器と噛み合わない箇所が出る。

```plaintext
ナノ秒の Unix 時刻(2026年) = 1774000000000000000  (19 桁)
64 ビット符号付きの最大    = 9223372036854775807  (19 桁)
19 桁に必要なビット = 65 -> 割当は 16 バイト
```

値は 8 バイトに収まるのに、桁を単位にすると 16 バイトになる。これは ADR 0010 が「桁の意味はバイト数に依存しない」と決めた事の代償であり、移植性と引き換えの既知のコストである(該当は 19 桁・39 桁・77 桁の境目のみ)。

## 2. 指数部を足すと何が変わるか

指数部には**型に書く静的な指数**と**値が持つ動的な指数**の2つがある。両者は性質が正反対である。

### 2.1 静的指数 — 型に書く

```plaintext
数値(<整数部>.<小数部> 指数 <e>)      # 値 = m × 10^(e - 小数部桁)
数値(1.5 指数 -31) キログラム         # 6 桁のマンティサ、刻み 10^-36
```

窓の**位置**だけを動かし、幅(桁数)は変えない。

| 値                        | 指数なし     | バイト | 指数あり             | バイト |
| ------------------------- | ------------ | ------ | -------------------- | ------ |
| 電子の質量 9.10938e-31 kg | `数値(0.36)` | 16     | `数値(1.5 指数 -31)` | 4      |
| アボガドロ定数 6.02214e23 | `数値(24.0)` | 16     | `数値(1.5 指数 23)`  | 4      |
| プランク定数 6.62607e-34  | `数値(0.39)` | 32     | `数値(1.5 指数 -34)` | 4      |

厳密さは一切失われない。指数は型情報であり、実行時の値は整数のままである。

- **加算**: 両辺の窓の下端(`指数 - 小数部桁`)の細かい方へ揃え、上端の大きい方に桁上がりを1つ足す。結果の桁は静的に決まり、値は厳密である。
- **乗算**: 桁は和、指数も和。厳密である。
- **桁溢れ**: 従来どおりコンパイル時に決まる。
- **記憶域**: 総桁数だけで決まり、指数は影響しない。

窓が遠く離れた値どうしを足すと桁が膨らむ(`数値(1.5 指数 23)` + `数値(1.5 指数 -31)` は 61 桁 = 26 バイト)。ただしこれは**コンパイル時に見える形で現れる**。黙って片方が消える事はない。

さらに、10 のべきの単位換算が**指数の付け替えだけ**で済むようになる。

```plaintext
数値(4.2) メートル  ->  数値(6.0 指数 1) ミリメートル    # 6 桁のまま、刻みは 10 mm
```

ADR 0010 の現行規則では `数値(7.0) ミリメートル` へ広げる必要があり、元の型が表せない値(9999.999 m)まで受け入れる型になっていた。指数があれば**値の集合が完全に一致**する。

### 2.2 動的指数 — 値が持つ(十進浮動小数点)

IEEE 754-2008 の decimal32/64/128 に相当する。指数を値ごとに持ち、実行時に動く。

| 形式       | バイト | 有効桁 | 指数範囲    | 同バイトの固定小数点 |
| ---------- | ------ | ------ | ----------- | -------------------- |
| decimal32  | 4      | 7      | -95..96     | 9 桁                 |
| decimal64  | 8      | 16     | -383..384   | 18 桁                |
| decimal128 | 16     | 34     | -6143..6144 | 38 桁                |

窓の**幅**を動かせる代わりに、Shidzuku が拠って立つ性質を失う。

```plaintext
有効16桁(decimal64 相当)
  (1e16 + 1) + (-1e16) = 0
  1e16 + (1 + (-1e16)) = 1        # 足す順序で答えが変わる(結合則が成立しない)
  1e16 + 1 = 1e16                 # 小さい方が黙って吸収される
```

金額でも同じ事が起きる。総額 99,999,999,999,999.99 に 0.01 を4回足すと、厳密には 100,000,000,000,000.03 だが、有効16桁では 100,000,000,000,000.00 になり 3 銭が消える。固定小数点(整数演算)なら、どの順序でも厳密に一致する。

### 2.3 比較

| 観点                  | 固定(ADR 0010 現行) | 静的指数       | 動的指数(十進浮動)   |
| --------------------- | ------------------- | -------------- | -------------------- |
| 加算の厳密さ          | 厳密                | 厳密           | 桁が離れると吸収     |
| 加算の結合則          | 成立                | 成立           | 不成立               |
| 丸めが起きる場所      | 宣言した所だけ      | 宣言した所だけ | 全ての演算(値に依存) |
| 桁溢れの検出          | コンパイル時        | コンパイル時   | 実行時               |
| 所要記憶域            | 静的に決まる        | 静的に決まる   | 静的に決まる         |
| 窓の位置(極端な値)    | 桁が膨らむ          | **解決**       | 解決                 |
| 窓の幅(1値の動的範囲) | 固定                | 固定           | 広い                 |
| 循環小数(1/3)         | 書けない            | 書けない       | 書けない             |
| 無理数(√2・π)         | 書けない            | 書けない       | 書けない             |

## 3. 検証結果

### 3.1 判定

**指数部が解くのは「窓の位置」であって「窓の幅」ではない。**

- 1.1(循環小数)・1.2(無理数)は**指数部では解けない**。位取り記数法の限界であり、丸めの宣言で扱うほかない。
- 1.5(位置が極端な値)は**静的指数で完全に解ける**。厳密さ・結合則・静的検査を一つも失わず、記憶域は 1/4〜1/8 になる。さらに 10 のべきの単位換算が値の集合を保ったまま書けるようになる。
- 1.3 下方向の累積・1.4 桁の爆発は指数部とは無関係であり、**演算の語彙の不足**である。

**動的指数(十進浮動小数点)は採らない。** 得るものは「1つの値の中の動的範囲」だけで、失うものは加算の厳密さ・結合則・丸め箇所の静的な既知性・桁溢れのコンパイル時検出——ADR 0010 が守ろうとしている性質のほぼ全部である。同じバイト数で桁数も減る(8 バイトで 18 桁 → 16 桁)。

そして**1つの量の中で必要な窓の幅は、実際には広くない**。

| 量           | 範囲             | 必要な総桁 | バイト |
| ------------ | ---------------- | ---------- | ------ |
| 金額(円)     | 1 円 〜 1 兆円   | 13         | 8      |
| 長さ(製造)   | 1 µm 〜 10 m     | 8          | 4      |
| 音圧         | 20 µPa 〜 200 Pa | 8          | 4      |
| 確率         | 1e-6 〜 1        | 7          | 4      |
| 時刻(ナノ秒) | 1 ns 〜 300 年   | 19         | 16     |

量と単位が問題を分割しているため(距離と質量は足せない、E12)、**桁が大きく離れた値どうしの加算はそもそも起きにくい**。動的範囲は、単位の選択(nm / m / km)という静的な手段で既に扱われている。

### 3.2 単位と指数の関係 — 同じ仕組みの2つの顔

静的指数は新しい概念ではない。ADR 0010 の「10 のべきの単位換算は桁の付け替え」は、**単位が量に静的指数を与えている**事に他ならない。`ナノメートル` は「`メートル` に指数 -9 を付けた単位」である。

- **量を持つ値**: 単位が窓の位置を担う(nm / mm / m / km)
- **単位なしの値**: 位置を掛ける先が無い。確率・比率・濃度・無次元の定数には**型の指数が要る**

静的指数を導入すると、単位の 10 のべき換算はその特別な場合になり、規則が一つに畳める。

### 3.3 書けなかった事 — 仕様に戻す論点

1. **丸めが要る演算が四則以外にある**。平方根・三角関数・対数・実数の累乗は ADR 0010 に無い。除算と同じ形(結果の桁と丸め方を宣言させる)へ揃えるのが素直である。
  → `平方根(値, 数値(桁), 丸め <方式>)`・`累乗(底, 回数, 数値(桁), 丸め <方式>)` を演算の語彙に加える。
2. **繰り返しの中の丸めは累積する**。丸めの宣言が示すのは1回の誤差の上限であり、反復回数を掛けた上限は型に現れない(1.3)。
  → 累積を型で防ぐ手段は無い。**合算する状態は、足し込む値の刻みより細かい桁で持つ**という指針を書く(0.4 円を足すなら状態は `数値(9.1) 円` 以上)。刻みが足りない加算は警告(W4)にできる。
3. **桁の窓の位置に指数がいる**(1.5・3.1)。→ ADR 0010 に静的指数を追加する。
4. **19 桁・39 桁・77 桁の境目でバイト数が倍になる**(1.7)。桁を意味の単位とした事の代償であり、既知のコストとして記録する。設計で救うなら「その型は 8 バイトに収まる」という実装の裁量を認める事になるが、移植性(桁の意味がバイト数に依存しない)を崩すため採らない。
5. **誤差を許容する計算の置き場所**。反復解法・確率の積・信号処理は、丸めを1回に閉じ込める形では書けない。ADR 0010 の「将来の変更想定」にある浮動小数点型は、**名前が近似である事を告げる別の型**として設けるほかない(公開面に現れたときに、読み手が厳密でないと分かる事)。

## 4. 未解決課題への入力

- **U15(数値の型と単位)**: 静的指数を追加し、動的指数は採らない。平方根・累乗の丸め宣言を語彙に加える。合算の刻みの指針(W4)を置く。→ ADR 0010 を改訂。
- **U13(失敗の体系)**: 0 除算は NaN を返さず失敗とする。NaN は黙って伝播するため「静かさ」の反対である(桁溢れと同じ扱いの候補)。
- **U12(外部世界との境界)**: 外部から来る IEEE 754 の double を十進で厳密に受けるには最大 751 有効桁(小数部 1074 桁)が要る。境界では必ず丸めの宣言を伴う受け取りになる。
- **U5(トランスパイル先の言語)**: 静的指数は型情報のみで実行時表現を変えないため、出力先の要件は変わらない(多倍長整数)。

## 5. 次の行動

- ADR 0010 を改訂する(静的指数の追加、動的指数の棄却、演算語彙の補完)→ 済
- U13 の検討時に 0 除算・桁溢れ・NaN の扱いを入力とする
- 反復計算の誤差の上限を型に載せる方法は、Phase 1 の実装で必要が確認されたら再検討する
