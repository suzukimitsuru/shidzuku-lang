# 思考実験 11: 暦の拡張 — 和暦とイスラム暦は書けるか

- 状態: Draft
- 日付: 2026-08-29
- 目的: ADR 0019(提案)は「言語が持つ暦は算術暦(グレゴリオ暦・ユリウス暦)だけ」と決めた。元号(和暦)・イスラム暦・仏暦を実際に書こうとして、**何が足りないのか**を確かめる
- 進め方: 暦ごとに「何を知っていれば日付が決まるか」を分解し、ADR 0019 の語彙で書けるかを判定する。書けないものは、**書けない理由が同じか違うか**で分ける

## 1. ADR 0019 が暦を2つに限った理由と、その穴

ADR 0019 決定5 はこう書いている。

> **算術暦**(規則だけで定まる暦)に限る。(中略)元号は法令で決まり、イスラム暦は月の観測に依る。
> これらは**版が変わる表**であり、分散したノードで表が食い違えば同じ入力から違う結果が出る。

この理由は正しい。しかし**退けた対象を取り違えている**。

- 退けるべきなのは「**言語が**表を持つ事」である。tzdata のように実行環境から表が来ると、ノードごとに版が違い得る。
- 退けた事になっているのは「表を要する暦を**書ける**事」である。**書き手がソースの中に表を書く**場合、表はプログラムの一部であり、版は食い違わない。

ADR 0010 は既に同じ形の判断をしている。**量と単位の表を言語は持たず、書き手が宣言する。**

```plaintext
量   長さ 基準 メートル
単位 インチ : 長さ = メートル × 127/5000
```

インチの定義は言語が知らない。書き手が書く。同じ形が暦にも使えるはずである。

## 2. 暦ごとに「何を知っていれば日付が決まるか」

| 暦                             | 年の呼び方    | 月の切れ目         | 必要な知識                     |
| ------------------------------ | ------------- | ------------------ | ------------------------------ |
| グレゴリオ暦                   | 連番          | 規則(閏年)         | 規則だけ                       |
| ユリウス暦                     | 連番          | 規則(4年に1度)     | 規則だけ                       |
| 和暦(明治6年以降)              | **元号 + 年** | グレゴリオ暦と同じ | **改元日の一覧**               |
| 仏暦(タイ)                     | 西暦 + 543    | グレゴリオ暦と同じ | 起点1つ                        |
| 民国紀元                       | 西暦 − 1911   | グレゴリオ暦と同じ | 起点1つ                        |
| 皇紀                           | 西暦 + 660    | グレゴリオ暦と同じ | 起点1つ                        |
| 和暦(明治5年以前)              | 元号 + 年     | **太陰太陽暦**     | 改元日 + **各月の長さの表**    |
| イスラム暦(タブラー暦法)       | 連番          | **規則(30年周期)** | 規則だけ。ただし**流派が複数** |
| イスラム暦(ウンム・アルクラー) | 連番          | **天文計算+観測**  | **毎年発表される表**           |

**この表は3本の線で割れる。**

1. **月日はグレゴリオ暦と同じで、年の呼び方だけが違う暦**(和暦・仏暦・民国紀元・皇紀)
2. **月の切れ目そのものが違うが、規則で決まる暦**(イスラム暦のタブラー暦法)
3. **月の切れ目が観測または毎年の発表で決まる暦**(ウンム・アルクラー暦、明治5年以前の和暦)

### 2.1 一つ目の線 — 年の呼び方だけが違う

和暦の明治6年以降は、**月日がグレゴリオ暦とまったく同じ**である。1873年1月1日に太陽暦へ移り、
それ以前(明治5年12月2日 = 1872年12月31日)までは天保暦だった。つまり和暦は 1873-01-01 を境に**別の暦になっている**。

明治6年以降の和暦を書くのに要るのは、**改元日の一覧だけ**である。

```plaintext
明治 → 1873-01-01 の時点で 6 年
大正 → 1912-07-30 から 1 年
昭和 → 1926-12-25 から 1 年
平成 → 1989-01-08 から 1 年
令和 → 2019-05-01 から 1 年
```

- 年番号は**基準の暦の年が変わる所で 1 増える**。昭和元年は 1926-12-25 から 12-31 までの7日間しかなく、翌 1927-01-01 が昭和2年である。
- 仏暦・民国紀元・皇紀は、この表の要素が1つだけの場合にすぎない。**同じ仕組みで書ける。**

### 2.2 二つ目の線 — 規則で決まるが、月の切れ目が違う

イスラム暦のタブラー暦法(算術暦)は、30年周期に 11 回の閏年を置く規則だけで決まる。表も観測も要らない。
**しかし閏年をどの年に置くかに複数の流派がある。**

| 流派                       | 30年周期の閏年                                |
| -------------------------- | --------------------------------------------- |
| 最も広く使われる形         | 2, 5, 7, 10, 13, 16, 18, 21, 24, 26, 29       |
| 端数の扱いを変えた形       | 16 の代わりに 15                              |
| イスマーイール派タイイブ派 | 3番目を8年、7番目を19年、10番目を27年へずらす |

規則は固定だが、**どの規則を採るかは書き手の判断**である。言語が1つを選べば、他を使う系が書けなくなる。

### 2.3 三つ目の線 — 観測または毎年の発表

ウンム・アルクラー暦(サウジアラビア)はメッカの座標での天文計算に基づき、**数年先まで発表される**。
ラマダーンなど一部の月は実際の月の観測で確定する。明治5年以前の和暦(天保暦)も、各月の長さが個別に決まる。

これらは**版を持つ表**であり、tzdata とまったく同じ性質を持つ。

## 3. ADR 0019 の語彙で書いてみる

### 3.1 和暦(明治6年以降)

ADR 0019 の `日付 <暦>` の暦の欄には、言語が持つ2つしか書けない。

```plaintext
data 届出 { 受理日: 日付 和暦 }     # 書けない。和暦という暦が無い
```

テキストで持つ案は ADR 0013 決定4(部分取得・分割の禁止)に当たり、年を取り出せない。
直積で持つ案(`{ 元号: 明治 | 大正 | …, 年: 整数, 月: 整数, 日: 整数 }`)は書けるが、**比較も日数差も書き手が実装する事になる**。
`日付` が持っている性質(全順序・日数差・曜日)を全部失う。

### 3.2 書けるようにするには何を足せばよいか

第2節の一つ目の線に限れば、要るのは**起点の表を書く語彙だけ**である。

```plaintext
暦 和暦 : グレゴリオ暦 の紀年法 {
  紀元 明治 : 1873-01-01 から 6 年
  紀元 大正 : 1912-07-30 から 1 年
  紀元 昭和 : 1926-12-25 から 1 年
  紀元 平成 : 1989-01-08 から 1 年
  紀元 令和 : 2019-05-01 から 1 年
}

暦 仏暦 : グレゴリオ暦 の紀年法 { 紀元 仏滅紀元 : 0001-01-01 から 544 年 }
```

- 内部表現は変わらない。**日番号1つのままである。** 暦は「その日番号を年月日でどう呼ぶか」だけを決める(ADR 0019 決定5)。
- したがって比較・日数差・曜日・`日を足す` はそのまま効く。**失うものが無い。**

### 3.3 何が変わるか — 換算が全域でなくなる

ADR 0019 は「暦の換算は常に厳密であり、往復は必ず一致する」と書いた。**紀年法を足すとこれが弱まる。**

```plaintext
換算(1500-01-01 グレゴリオ暦, 和暦)   ->  暦の外
```

表の最初の起点より前は、その紀年法では**呼びようが無い**。丸めは起きない(厳密さは保つ)が、**全域ではなくなる**。

| 換算            | 厳密か | 全域か                   |
| --------------- | ------ | ------------------------ |
| 算術暦 ↔ 算術暦 | 厳密   | 全域                     |
| 算術暦 ↔ 紀年法 | 厳密   | **部分的**(表の外がある) |
| 紀年法 ↔ 紀年法 | 厳密   | **部分的**(両方の表の中) |

→ 結果を直和で受ける(`日付 和暦 | 暦の外`)。ADR 0019 の「無いは直和で明示する」がそのまま効く。

### 3.4 表がソースの中にある事の意味

これが tzdata との決定的な違いである。

| 観点               | tzdata(時間帯)   | 紀年法の宣言                |
| ------------------ | ---------------- | --------------------------- |
| 表の出所           | 実行環境(外)     | **ソース(中)**              |
| ノード間の食い違い | 起き得る         | **起きない**                |
| 更新の仕方         | 実行環境の更新   | プログラムの変更            |
| 更新が見える所     | どこにも見えない | **差分・レビュー・W0003-2** |

**改元がプログラムの変更として見える事は、欠点ではなく利点である。** 新しい元号が来たら宣言を1行足す。
それは公開面の変更(W0003-2)であり、レビューを通り、版として記録される。分散したノードは同じソースから動くため、表は食い違わない。

### 3.5 イスラム暦は書けるか

**タブラー暦法は紀年法の仕組みでは書けない。** 年の呼び方ではなく**月の切れ目の規則**が違うためである。
書けるようにするには「閏年の配置を宣言する語彙」が要り、紀年法(起点の列挙)とは別の仕組みになる。

**ウンム・アルクラー暦と観測ベースは書けない。** 毎年発表される表を要し、tzdata と同じ性質を持つ。
ソースに 100 年分の月の長さを書けば形の上は書けるが、それは**表を人が書き写す**事であり、間違いが混ざる。

## 4. 検証結果 — 仕様に戻す論点

1. **ADR 0019 の「元号は持たない」は、退ける対象を取り違えていた。** 退けるべきは「言語が表を持つ事」であり、
  「書き手がソースに表を宣言する事」は ADR 0010 が量と単位で既に採っている形である。
2. **紀年法(年の呼び方だけが違う暦)は、起点の表を書く語彙だけで足りる。** 内部表現は日番号のままであり、
  比較・日数差・曜日・`日を足す` を一つも失わない。和暦・仏暦・民国紀元・皇紀が同じ仕組みで書ける。
3. **換算が全域でなくなる。** 表の外は `暦の外` として直和で受ける。厳密さ(丸めが無い事)は保つ。
  ADR 0019 の「往復は必ず一致する」は、**表の中では**という条件が付く。
4. **和暦は 1873-01-01 で別の暦になっている。** 明治5年以前は天保暦であり月日が違う。
  宣言の `紀元 明治 : 1873-01-01 から 6 年` は、**その事実をそのまま書いている**——1年目からではなく6年目から始まる表である。
5. **イスラム暦は2つに割れる。** タブラー暦法は算術だが月の切れ目の規則が違い、紀年法では書けない。
  さらに閏年の配置に流派が複数あり、言語が1つを選べば他が書けなくなる。
  ウンム・アルクラー暦と観測ベースは版を持つ表であり、tzdata と同じ理由で持てない。
6. **暦は3つの種に分かれる。** 算術暦(言語)・紀年法(書き手が宣言)・表暦(持たない)。
  この3分は「表が要るか」ではなく「**表がどこから来るか**」で引いた線である。

## 5. 未解決課題への入力

- **U22(基本型の体系)**: 論点1〜4・6 は新しい ADR で決める。ADR 0019 決定5 の「言語が持つ暦は算術暦だけ」を改訂する。
- **U16(版の移行)**: 論点4。改元で宣言が増えると、永続化済みの `日付 和暦` の読み方は変わらないが、
  新しい元号の値を古い版のプログラムが読めない。版の混在の一例である。
- **U12(外部世界との境界)**: 論点5。ウンム・アルクラー暦のような版を持つ表を外から受ける場合の扱いは、tzdata と同じ節で扱う。
- **U13(失敗の体系)**: `暦の外` はデータとして正常な不在であり、系の失敗ではない(思考実験 05 の 3.2-3 の切り分け)。

## 6. 次の行動

- ADR 0020(暦の拡張 — 紀年法の宣言)を起案する → 済
- タブラー暦法のイスラム暦は、算術暦を書き手が宣言する仕組みとして将来検討する
- 観測ベースの暦は「書けない」と認め、その理由(表がどこから来るか)を記録する
