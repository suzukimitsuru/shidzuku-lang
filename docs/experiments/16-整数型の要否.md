# 思考実験 16: 整数型の要否 — 十進数に畳めるか

- 状態: Draft
- 日付: 2026-09-15
- 目的: ADR 0021(提案)が `十進数` を「刻みだけを宣言する任意精度の型」にした結果、`整数` を置く根拠が残っているかを調べる。
  `整数` を無くして**単位付き・静的位取り・任意精度の十進固定小数点数**(`十進数(s)`)だけにした場合の利点と欠点を並べる
- 進め方: まず ADR 0019 が `整数` を置いた時の根拠が ADR 0021 の後も生きているかを確かめる。
  次に第6章で `整数` が現れる場所を棚卸しし、`十進数(0)` で書けるかを1件ずつ見る。最後に他言語の実例で裏を取る。結論は論点として ADR 0021 に渡す

## 1. 問いの成り立ち — 置いた根拠は生きているか

ADR 0021 の `十進数(0) 単位なし` は、**刻み 1・上限なし・厳密**の数である。これは任意精度の整数そのものであり、`整数` と値の集合が重なる。

ADR 0019 は `整数` を置くとき、「置かない(`十進数(i.0)` で代用)」案を2つの理由で退けていた。その2つは ADR 0021 で消えている。

| ADR 0019 が退けた理由                                | ADR 0021 の後                                                     |
| ---------------------------------------------------- | ----------------------------------------------------------------- |
| 桁の宣言が全ての「数えた値」に掛かる                 | **失効**。整数部の欄が無くなり、書くのは `十進数(0)` の `0` だけ  |
| 19 桁で記憶域が倍になる(`十進数(19.0)` は 16 バイト) | **失効**。可変長なので 19 桁の値は 8 バイト(ADR 0021 の机上検証4) |

さらに ADR 0019 は「置く(任意精度)」も「所要記憶域が実行時まで決まらない」として退けていたが、
**ADR 0021 はその性質を `十進数` について受け入れている**。整数だけを別扱いする理由も、そこからは出てこない。

つまり **`整数` を置いた根拠は3つとも失効している**。残すにしても、理由を書き直さなければ「意図を残す」に反する。

## 2. `整数` が現れている場所の棚卸し(第6章)

| #  | 役割                                     | 現在の書き方             | `十進数(0)` で書けるか | 付随して起きる事                                |
| -- | ---------------------------------------- | ------------------------ | ---------------------- | ----------------------------------------------- |
| 1  | 個数・数量・在庫数・回数                 | `整数 単位なし`          | 書ける                 | なし                                            |
| 2  | 列の添字・長さ・繰り返し回数(E0019-4)    | `整数 単位なし`          | 書ける                 | 機械語に収まる事が型から言えなくなる            |
| 3  | 版・連番・世代番号                       | `整数 単位なし`          | 書ける                 | 序数の問題(U24)は型を変えても残る               |
| 4  | 時間量                                   | `整数 ナノ秒`            | 書ける                 | なし                                            |
| 5  | `時点` の内部表現                        | `整数 ナノ秒`            | 書ける                 | 「1677〜2262 年」という範囲が型の帰結でなくなる |
| 6  | `日付` の内部表現・天文学的年番号        | `整数 日`                | 書ける                 | 範囲は暦側(-9999〜9999)が決めるため影響は小さい |
| 7  | `時刻` の内部表現・`時計を進める` の戻り | `整数 ナノ秒`・`整数 日` | 書ける                 | なし                                            |
| 8  | `隔たり` の結果                          | `整数 <単位>`            | 書ける                 | 最大 584 年で起きる桁溢れが**消える**           |
| 9  | 識別子型の中身(64 ビットの識別子)        | `整数 単位なし`          | 書ける                 | 「64 ビットに収まる」が型から言えなくなる       |
| 10 | 単位の比(有理数の分子/分母)              | 宣言の中の数             | 影響なし               | 実行時の値ではない                              |

**10 件すべてが `十進数(0)` で書ける。** 書けない物は無い。問題は書けるかどうかではなく、書いた後に何を失うかである。

## 3. 利点

### 3.1 暗黙の橋が要らなくなる(最大の利点)

ADR 0021 の決定6 は `整数` → `十進数` の昇格を暗黙にした。**`整数` が無ければ、この橋は存在しない。**

```plaintext
data 明細 { 単価: 十進数(2) 円, 数量: 十進数(0) 単位なし }

単価 × 数量        # 同じ型どうしの乗算。小数部は和(2 + 0 = 2)で 十進数(2) 円
```

- 「数値型は暗黙に混ざらない」が**例外ゼロの規則**に戻る(Swift・Ada・Haskell と同じ厳格さ。思考実験 14 の分類)。
- U23(スカラー倍)は**問題そのものが消える**。型を跨いでいないため、変換の規則を書く必要がない。
- 計画書 6.1 の9組の表は、`実数` が絡む組だけの4組になる。そのすべてがコンパイル時エラーで揃い、例外を持たない。
- 可換性(問題5)・両辺 `単位なし`(問題6)・E の文面(問題7)は、規則が1本になるので論点ごと消える。

### 3.2 型が2つになり、選ぶ問いが1つになる

`実数` と `十進数(s)` の2つだけになる。判断は「**厳密か、測った値か**」の1問である。
ADR 0019 決定7 の3列の指針(数えた・刻みを決めた・測った)は2列に畳める——**数えた値は「刻みが 1」という特別な場合**に過ぎない。

### 3.3 桁溢れと特別扱いが消える

- `整数` の 64 ビット桁溢れは**演算ごとの検査**を要求していた(ADR 0019 決定2。`十進数` は中間が自動で広がるため「名前を得る所」で足りていた)。この非対称が消える。
- 加減乗が言語全体で常に厳密になる。U13(失敗の体系)から失敗が1種類減る。
- `隔たり` がナノ秒で 584 年を超えると桁溢れする問題(思考実験 10 の論点6)も消える。

### 3.4 換算の規則が1本になる

ADR 0019 決定2 は整数専用の換算規則(「1 より粗い単位へ移せば必ず情報が落ちる」)を別に置いていた。
`十進数(0)` なら、既存の規則(粗い単位へは小数部が足りないので丸めの宣言が要る。E0010-3)が**そのまま当たる**。特別扱いが1つ減る。

### 3.5 基本型が 10 から 9 に減る

語彙が減り、第6章の記述量も減る。「刻み」という1つの言葉で、数える値も金額も説明できる。

## 4. 欠点

### 4.1 「厳密かつ固定長」の型が言語から消える(最大の欠点)

ADR 0021 の決定9 は、WCET が要る所・組込みの逃げ場を **`整数 <細かい単位>`**(例: `整数 銭`)に置いていた。`整数` を消すと、この逃げ場が無くなる。

| 型          | 厳密か | 記憶域と実行時間の上界 |
| ----------- | ------ | ---------------------- |
| `整数`      | 厳密   | 型が定める             |
| `十進数(s)` | 厳密   | **無い**               |
| `実数`      | 近似   | 型が定める             |

残るのは「厳密だが上界なし」と「上界はあるが近似」の2つだけになる。**両方を満たす型が1つも無くなる。**

- 任意精度の演算は動的確保を伴い、再確保の回数が値に依存するため WCET が立たない。組込みでは固定容量の器が原則である。
- 分散でも効く。Raft のログとノード間メッセージのサイズが、値の大きさに依存するようになる。

#### 用語 — 「WCET」と「`no_std`」

**WCET(最悪実行時間・Worst-Case Execution Time)** とは、ある処理が**どんな入力でも、どんな状態でも、これ以上はかからない**と言える実行時間の**上界**である。
自動車のエアバッグ展開やモータ制御のように「締切を1回でも破れば失敗」という系(ハードリアルタイム)では、締切に間に合う事を示すために各処理の WCET を見積もる。
見積もりは実測ではなく**静的解析**で行う——取り得る実行経路を数え上げ、各命令の所要サイクルを積む。真の最悪時間を下回ってはならないため、常に安全側に出す。

静的解析が成り立つには前提がある。

| 前提                                           | 破れると何が起きるか                                                           |
| ---------------------------------------------- | ------------------------------------------------------------------------------ |
| 全てのループの回数に上界がある                 | 積む回数が決まらない                                                           |
| 再帰・動的な呼び先が無い                       | 呼ぶ先が決まらず、経路を数えられない                                           |
| 各操作の所要時間が値に依存しないか、上界がある | 値ごとに時間が変わるなら、最悪値が決まらない                                   |
| 動的なメモリ確保が無い                         | 確保の時間は空き領域の状態(断片化)に依存し、汎用の確保器は最悪時間を保証しない |

**「WCET が立たない」**とは、この前提が破れて**上界が計算できない**(あるいは計算できても意味を成さない大きさになる)場合を指す。
`十進数` は後ろの2つに当たる。

```plaintext
state 合計: 十進数(2) 円      # 上限が無い

合計 = 合計 + 明細.金額        # 1回の加算にかかる時間は、合計の桁数に比例する
```

- 加算は桁数に比例し、乗算はさらに増える。**桁の上界が型に無いため、1回の演算の上界が決まらない。**
- 桁が機械語に収まらなくなった時点でヒープの確保が起きる。**いつ起きるかは値次第**であり、確保そのものの時間も一定ではない。

結果として「この `ask` は必ず 5 ミリ秒以内に返る」と**示せない**。ADR 0004 の `deadline` は宣言できるが、守れる事を静的に裏づける手段が無い——これが「WCET が立たない」の中身である。

**`no_std`(Rust)** は、標準ライブラリ `std` を使わずに書く構成(`#![no_std]`)である。
`std` は OS の機能(ファイル・スレッド・ネットワーク)と**ヒープ**を前提にしており、OS の無いマイコン(ベアメタル)では使えない。

| 層      | 何が入っているか                                                             | ヒープ                           |
| ------- | ---------------------------------------------------------------------------- | -------------------------------- |
| `core`  | `Option`・`Result`・整数と浮動小数点・スライスなど、外部の支えが要らないもの | **不要**                         |
| `alloc` | `Vec`・`String`・`Box` など、確保を伴うもの                                  | **要る**(確保器を自分で登録する) |
| `std`   | 上記 + OS の機能                                                             | 要る                             |

`no_std` では `core` だけが既定で使える。`Vec` や `Box` を使うには `alloc` を足し、**グローバルな確保器と、確保に失敗したときの処理を自分で用意する**必要がある。
多くの組込みはそれをしない方針を採る——断片化・確保失敗・最悪時間の不確定を避けるためであり、固定容量の器(`heapless` など)で済ませる。

任意精度の数は、桁が伸びるたびに**その場で領域を確保する**のが普通の実装である(GMP・`num-bigint` など)。したがって:

- ヒープを持たない `no_std` では、`十進数` は**そのままでは動かない**。固定長のバッファに収める実装にするなら、それは上限を設けた別の型である。
- ヒープを用意しても、確保の失敗と最悪時間の不確定が入るため、上の WCET の問題はそのまま残る。

一方 `実数`(binary64)と幅付き整数(ADR 0021 の決定9)は**レジスタとスタックだけで完結する**ため、`core` だけで動く。
しかし `実数` は近似である——**「厳密である」事と「ヒープを使わない」事を同時に満たす型が無い**、というのがこの空白の正体である。

### 4.2 添字と長さが可変長になる

E0019-4 は「列の添字・長さ・繰り返し回数は `整数 単位なし` に限る」と定めている。`十進数(0)` にすると、**機械語に収まる事を型が言わなくなる**。

Haskell は整数リテラルの既定を任意精度の `Integer` に置きながら、`length` は機械語の `Int` を返す(任意精度を返す `genericLength` は遅い)。
**任意精度を既定に据えた静的型の言語でも、長さと添字だけは機械語整数に落としている。** これは最適化の都合というより、境界が値に依存しないという保証である。

### 4.3 トランスパイル先の負担が増える

| 出力先     | `整数` がある場合  | `十進数(0)` だけの場合                                                 |
| ---------- | ------------------ | ---------------------------------------------------------------------- |
| TypeScript | `number`(Smi 経路) | **すべて `BigInt`**。V8 の BigInt は最適化が薄く number より大幅に遅い |
| Rust       | `i64`              | 多倍長。添字は `usize` への変換が常に要る                              |

ADR 0012 の要件(多倍長整数を持つ事)は変わらないが、**多倍長が使われる頻度が桁違いに増える**。ループカウンタまで多倍長になる。

### 4.4 凍結されていない採用済みの決定に波及する

ADR 0019 の決定4(`時点`)・決定5(`日付`・`時刻`)・決定6(時間量)は**凍結の対象外で、採用済みのまま有効**である。
そのいずれもが内部表現に `整数` を使っている(第2節の 5〜8)。`整数` を消すと、この3つの決定と第6章 6.4〜6.6 を書き直す事になる。

とくに `時点` の「表せる範囲 1677〜2262 年」は 64 ビットの帰結であり、可変長にすると範囲が消える。
範囲が消えるのは一見利点だが、**時刻の演算が値に依存する時間で走る**事を意味する。時刻は最も多く触る値であり、影響は小さくない。

### 4.5 「64 ビットに収まる」が型から言えなくなる

ADR 0019 が `整数` を置いた背景は「ナノ秒の時点(19 桁)と 64 ビットの識別子の置き場所が消えていた」事だった。
識別子型の中身に使う値が 64 ビットに収まる事は、外部形式(プロトコル・DB の `BIGINT`)との接合で意味を持つ。可変長ではその保証が型から落ちる。

### 4.6 静的型の言語に先行例が無い

任意精度整数だけを持つのは、Python・Ruby・Erlang・Smalltalk・Scheme といった**動的型の言語**である。
いずれも fixnum・Smi(小さい整数を1ワードの即値で持つ実装最適化)で実用速度を保っている——**言語の型ではなく実装の工夫**で凌いでいる。

静的型の言語で機械語整数を持たない例は見つからなかった。Haskell は `Integer` と `Int` の両方を持ち、Ada・Swift・Rust は機械語整数が中心である。
**「厳密な値の上界を型で言う」事を捨てた静的型の言語は無い**——組込みと分散を想定する言語にとって、この空白は軽くない。

## 5. 中間の案

| 案                                                                            | 橋(暗黙変換)                 | 固定長の受け皿 | 型の数 |
| ----------------------------------------------------------------------------- | ---------------------------- | -------------- | ------ |
| (a) `整数` を残す(ADR 0021 の現状)                                            | 1本要る                      | `整数`         | 3      |
| (b) `整数` を無くす                                                           | **要らない**                 | **無い**       | 2      |
| (c) `整数` を残し、`十進数(0)` を使わない指針を置く                           | 1本要る                      | `整数`         | 3      |
| (d) `整数` を「器を宣言した `十進数(0)`」と定義し直す(`十進数(0) 器 64` 相当) | **要らない**(同じ型の器違い) | 残る           | 実質2  |

(d) は、`整数` を別の型ではなく **`十進数` の器の宣言**として位置づける案である。
刻みは 0 桁、器は 64 ビット。昇格は「器の有無」の違いだけになり、丸めは原理的に起きないまま、固定長の受け皿も残る。
ADR 0021 が「将来の変更想定」に送った**値域の宣言**(`十進数(2) 円 範囲 0..999999999`)と同じ形であり、統合できる可能性がある。

## 6. 検証結果

### 6.1 判定

**利点は規則の単純さに集中し、欠点は実装と保証に集中する。**

| 無くすと得るもの                         | 無くすと失うもの                                |
| ---------------------------------------- | ----------------------------------------------- |
| 暗黙の橋が消え、例外ゼロの規則に戻る     | 「厳密かつ固定長」の型が言語から消える          |
| U23 が問題ごと消える                     | 添字・長さの上界が型から消える                  |
| 桁溢れの検査と整数専用の換算規則が消える | `時点`・`日付`・`時刻` の決定を書き直す事になる |
| 基本型が1つ減り、指針が2列になる         | トランスパイル先で多倍長が常用になる            |

決め手は「**この言語は、厳密な値について記憶域と実行時間の上界を型で言う事を、全面的に諦めるか**」である。
ADR 0021 は `十進数` についてそれを諦めた。しかし全ての厳密な型について諦めるかは、別の判断である。
組込み・リアルタイム・分散を想定用途に挙げている以上(第0章)、**上界を言える厳密な型を1つも持たない状態は薦められない**。

### 6.2 推奨

- **`整数` は残す。** ただし**残す理由を書き直す**。ADR 0019 の3つの根拠(桁の宣言・19 桁で倍・任意精度は記憶域が読めない)は ADR 0021 で失効している。
  新しい理由は「**厳密かつ、記憶域と実行時間の上界を型が言う唯一の型だから**」である。
- ADR 0021 の決定9(固定長が要る所は `整数 <細かい単位>`)は、この理由をすでに使っている。決定1 の記述をそれに合わせる。
- (d)(器の宣言として統合する案)は、値域の宣言と併せて Phase 1 の検討に送る。

## 7. 前提の見直し — 書き手の指定(2026-09-15)

第4節の欠点は、3つの前提の上に立っていた。書き手からその前提が違うと示された。

| 本実験が置いていた前提                            | 書き手の指定                                                     |
| ------------------------------------------------- | ---------------------------------------------------------------- |
| `十進数` を Raft など外部システムとの接合にも使う | **使わない**。外部との接合は別の語彙で扱う                       |
| `時点`・`日付`・`時刻` は内部表現に `整数` を使う | **内部で整数で保持すればよい**。言語の型として `整数` は要らない |
| 固定長の厳密な値は `整数 <細かい単位>` で書く     | 外部との接合で **8/16/32/64 ビットの整数を限定的に扱えればよい** |

### 7.1 欠点の再評価

| 節  | 挙げた欠点                            | 前提を入れ替えた後                                                                                     |
| --- | ------------------------------------- | ------------------------------------------------------------------------------------------------------ |
| 4.1 | 「厳密かつ固定長」の型が消える        | **境界には残る**(幅付き整数)。ただし内側(body・state)には無く、WCET の空白は残る(7.3)                  |
| 4.2 | 添字と長さが可変長になる              | **実装の話に落ちる**。時間の型と同じく内部で機械語整数に持てばよい。型は `十進数(0) 単位なし`          |
| 4.3 | 出力先で多倍長が常用になる            | **残る**。ただし小さい整数の即値化(fixnum・Smi)は実装の定石であり、言語の型の問題ではない              |
| 4.4 | `時点`・`日付`・`時刻` を書き直す     | **言い換えで済む**。「内部表現は `整数 ナノ秒`」→「表せる範囲は仕様が定め、内部表現は実装に委ねる」    |
| 4.5 | 「64 ビットに収まる」が型から言えない | **境界で言う**。幅は外部表現の性質であり、詰め替える所で宣言する                                       |
| 4.6 | 静的型の言語に先行例が無い            | **当たらなくなる**。幅を境界だけで言う形は Erlang のビット構文・Ada の表現節・Rust の `#[repr]` と同じ |

**前提が変われば判定は反転する。** 汎用の `整数` は置かず、幅付き整数を境界に限って持つ形が通る。

### 7.2 幅付き整数をどこに置くか

| 案                                    | 形                                                               | 増える型 | 要る規則                             |
| ------------------------------------- | ---------------------------------------------------------------- | -------- | ------------------------------------ |
| (あ) 基本型として置く                 | `整数32 単位なし` 等。符号あり/なし × 4幅                        | **8**    | 桁溢れ・巻き戻り・単位・変換を全種に |
| (い) **境界の符号化の語彙として置く** | `符号化(値, 符号付き 32 ビット, ビッグエンディアン) -> バイト列` | **0**    | 詰め替えの宣言だけ                   |

(い)を推す。

- **幅は値の性質ではなく、外部表現の性質である。** ADR 0010 が単位を型に載せ、外部での綴り(`cm`・`℃`)を U12 へ送ったのと同じ切り分けである。
- 「限定的に扱えればよい」という要望に、型を8つ増やす答えは重い。演算は内側の `十進数(0)` で行い、境界で詰め替える。
- ADR 0013 の役割「境界」「解析」と噛み合い、外部表現の器(`バイト列`)は既にある。
- 範囲外は失敗(U13)。幅・符号・バイト順を必ず書かせる形は、`割る(…, 桁, 丸め)` と同じである(省略の禁止)。

(あ)にも利点はある。外部の構造体をそのまま写した宣言を書きたい場合、幅が型に出る方が読みやすい。
中間案として、**符号化の指定に名前を付けられる**形(`外部形式 ヘッダ { 版: 符号なし 8 ビット, 長さ: 符号なし 32 ビット ビッグエンディアン }`)があり、これは U12(外部世界との境界)の管轄になる。

### 7.3 残る空白 — WCET と組込み

内側には、厳密でありながら記憶域と実行時間の上界を型が言う型が無くなる。`十進数` は上界を持たず、`実数` は近似である(用語は 4.1 の「用語 — 「WCET」と「`no_std`」」)。
**値域の宣言**(ADR 0021 の将来の変更想定)が来るまで、この空白は埋まらない。組込み・実時間を Phase 1 の対象に含めるなら、値域の宣言を前倒しする必要がある。

具体的に何が起きるかは、8つの場面に分けて ADR 0021 の欠点(「『厳密かつ上界あり』が無い事で、具体的に何が起きるか」)に書き出した。要点は3つである。

- **期限(`deadline`)が値の大きさで超過し得る**。同じ記述が、値によって間に合ったり間に合わなかったりする(ADR 0004)。
- **失敗し得る演算が「すべての算術」になる**。確保の失敗はどこでも起き得るため、「失敗は型に出す」という方針と噛み合わない(U13)。
- **多倍長の確保による一時停止が、Raft の心拍・選挙の締切に乗り得る**(ADR 0001)。

いずれも第0章 0.5 の「運用で驚きがない」に当たる。ADR 0010 が排したのは「値が黙って壊れる驚き」だったが、ここで入るのは「**資源と時間が値に依存する驚き**」である。
ただし**値が壊れる事・複製の状態が食い違う事・境界の先を壊す事は無い**(ADR 0021 の同節)。危険は自ノードの資源と応答時間に閉じている。

### 7.4 更新した推奨(6.2 を差し替える)

- 汎用の `整数` は**置かない**。数える値は `十進数(0) 単位なし` で書く。
- 外部との詰め替えは、幅・符号・バイト順を宣言する**境界の語彙**として持つ(案(い))。基本型は増やさない。
- `時点`・`日付`・`時刻` は**表せる範囲を仕様が定め**、内部表現は実装に委ねる(整数で保持すればよい)。
- 数値型は `実数` と `十進数(s)` の2つになり、**型のあいだの暗黙の変換は1本も要らなくなる**(ADR 0021 の決定6 が不要になる)。
- WCET の空白は値域の宣言で埋める(U15 の将来)。

## 8. 未解決課題への入力

- **U23(数値型の設計全体)**: 汎用の `整数` を置かなければ、暗黙の橋は1本も要らない。U23(スカラー倍)は問題ごと消える。
- **U12(外部世界との境界)**: 幅・符号・バイト順の宣言(案(い))と、その名前付き(`外部形式`)は U12 の管轄である。
- **U13(失敗の体系)**: 失敗から「整数の桁溢れ」が消え、「境界の詰め替えで範囲外」が入る。`時点`・`日付` の範囲外は仕様が定める範囲による。
- **U24(序数と基数)**: 序数の問題は `整数` の有無と独立である。どちらの案でも掛け算は書けてしまう。
- **U5(トランスパイル先)**: 数え上げが多倍長になる。小さい整数の即値化は出力先の実装に委ねる。
- **U15(数値の型と単位)**: WCET の空白を埋める値域の宣言を、Phase 1 の検討に入れる。

## 9. 次の行動

- ADR 0021 を改訂する(数値型を2つにし、決定6 の橋を落とし、境界の幅付き整数と時間の型の範囲を決定に加える)→ 済
- U12 の検討時に、幅・符号・バイト順の宣言と `外部形式` の名前付きを入力とする
- U15 の将来として、値域の宣言(WCET の空白)を Phase 1 に入れる
