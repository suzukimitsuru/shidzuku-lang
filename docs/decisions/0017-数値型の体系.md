# 0017: 数値型の体系 — 主に使う型を二進浮動小数点にする

- 日付: 2026-08-28
- 状態: 提案
- 関連課題: U15(関連: U9・U12・U13・U5)
- 改訂: ADR 0010(数値の型と単位)を改訂する。0010 が定めた十進固定小数点は廃止せず、数値型の1つとして残す
- 採番: 起案時は 0016 としていたが、同日に採用された ADR 0016(検証番号の採番規則)と番号が衝突したため 0017 に振り直した(2026-08-29)

## 背景(なぜ決める必要があるか)

ADR 0010(提案)は数値型を十進固定小数点の1種に定め、**全ての数値に桁の宣言**を、**丸めが起きる全ての場所に丸め方の宣言**を要求した。
誤差の出所は型から読めるようになったが、その代償として記述の重さが全ての数値に一律にかかる。

重さの内訳は、0010 自身が「欠点」に列挙している。

| 重さ               | 書く事                                                                        |
| ------------------ | ----------------------------------------------------------------------------- |
| 桁の見積り         | 値域を設計時に決める。狭ければ桁溢れ、広ければ記憶域の無駄                    |
| 演算ごとの宣言     | `割る(a, b, 数値(3.2), 丸め 四捨五入)` を除算・換算・累乗・平方根のたびに書く |
| 桁を狭める受け渡し | `数値(桁)` と `桁溢れ` の直和になり、呼び手に分岐が増える                     |
| 中間の値ごとの判断 | 距離・座標変換・統計は、途中の値ごとに桁と丸めを決める事になる                |

この前払いは、**刻みを人が十進で決めた値**(金額・税率・単価)には見合う。1円の狂いが事故になる場所では、桁と丸めは設計判断そのものだからである。
しかし**最初から近似である値**——計測値・座標・確率・統計量——には見合わない。丸め方を6種のどれにしても結果の正しさは変わらず、桁を何桁にしても真の値には届かない。
そこで払う宣言は設計判断ではなく作文であり、読み手に伝わる情報も無い。

0010 はこの限界を2箇所で自ら認めている。

- 「総括 — 何と引き換えに何を得るか」の表は、前払いが**割に合わない**列(統計・機械学習、信号処理・数値解析、描画・物理シミュレーション)を明記している。
- 「将来の変更想定」の末尾は、それらを扱うには「**名前が近似である事を告げる別の型**」を設けるほかないとしている(思考実験 07 の 3.3-5 と同じ結論)。

本 ADR は、その別の型を将来ではなく**いま**置く。そして、置く位置を変える——逃げ道としてではなく、**主に使う型**として置く。

## 検討した選択肢

- **十進固定小数点の1種のまま(0010 現行)**: 誤差の場所が全て型に出るが、重さが全ての数値にかかり、近似が本質の計算が書けない。
- **二進浮動小数点の1種にする**: 記述は最も軽いが、金額が壊れる(`0.1 + 0.2 ≠ 0.3`)。0010 が積み上げた判断を丸ごと捨てる事になる。
- **2種を持ち、主に使うのは十進固定小数点**: 0010 を保ったまま逃げ道を足す案。重さは既定の側に残り、書き手の多数派が払い続ける。
- **2種を持ち、主に使うのは二進浮動小数点**: 重さを、厳密さが要る値だけに絞る。近似である事は型の名前が告げる。
- **3種以上を持つ(binary32・binary64・十進固定・十進浮動)**: 選択肢が増えるほど、公開面で型が食い違う組み合わせが増える。

## 決定

### 数値型は1つではなく複数持つ

「数値」という単一の型は置かない。現在の数値型は2つであり、いずれも名前で明示する。

| 型       | 綴り(ASCII) | 表現                     | 桁の宣言 | 丸めの宣言           | 主な用途                     |
| -------- | ----------- | ------------------------ | -------- | -------------------- | ---------------------------- |
| `実数`   | `real`      | IEEE 754 binary64        | 不要     | 不要(常に最近接偶数) | 計測・座標・統計・物理・比率 |
| `十進数` | `decimal`   | 十進固定小数点(ADR 0010) | 必須     | 丸めが起きる所で必須 | 金額・在庫・按分・税・単価   |

両者は**別の型**であり、暗黙には混ざらない(下記「2つの型は暗黙に混ざらない」)。

### 主に使うのは `実数`(IEEE 754 binary64)

```plaintext
実数 <単位 | 単位なし>

実数 メートル      # 長さの計測値
実数 単位なし      # 確率・比率・無次元の定数
```

- **桁を書かない**。値の範囲(±1.7976931348623157e308)と有効桁(53 ビット ≒ 十進 15.95 桁)は、型が1つに定めている。値域の見積りは設計判断から外れる。
- **丸め方を書かない**。丸めは全ての演算で起きる。それは `実数` という名前が告げている性質であり、宣言しても情報が増えない。
- **四則の演算子 `+ - × ÷` を持つ**。除算に `割る(…)` を要求しない(0010 が `÷` を置かなかった理由——丸めが暗黙に起きる——は、丸めが型の性質である実数には当たらない)。
- **`平方根(値)`・`累乗(底, 指数)` も桁と丸めの宣言を要らない**(結果の規定は下記「実数の意味は IEEE 754 に厳密に従う」)。

### 「主に使う」は指針であって既定ではない

型名は必ず書く。**省略時に実数になる規則は置かない**(省略の禁止・ADR 0008)。

- `実数` も `十進数(7.2)` も、書かれて初めてその型になる。書かれなかった欄を既定で補う事はしない。
- 0008 が禁じたのは「書かれなかった物を言語が決める事」であって、「書く事が軽い型を持つ事」ではない。
  `実数` は桁を**省略している**のではなく、**桁という欄を持たない完結した型**である(binary64 の桁は言語が1つに固定している)。
- E0008-1(必須宣言の欠落)は、型名そのものが無い場合に当たる。`実数` に桁が無い事は E0008-1 ではない。

### 厳密さが要る所は `十進数`(ADR 0010 の型)

0010 が定めた型は、名前を `数値` から `十進数` に改めてそのまま残す。**0010 の決定は1つも取り消さない。**

| ADR 0010 の記述                        | 本 ADR での読み替え                      |
| -------------------------------------- | ---------------------------------------- |
| `数値(7.2) 円`                         | `十進数(7.2) 円`                         |
| `数値(1.5 指数 -31) キログラム`        | `十進数(1.5 指数 -31) キログラム`        |
| `割る(a, b, 数値(3.2), 丸め 四捨五入)` | `割る(a, b, 十進数(3.2), 丸め 四捨五入)` |
| 基本型「数値」(ADR 0009)               | 基本型「実数」と「十進数」の2つ          |

- 桁の宣言・静的指数・内部表現(小数桁倍した符号付き2進整数)・演算の規則・丸めの語彙・換算誤差の規則は、全て `十進数` の上で生きる。
- 検証 E0010-3(丸めの宣言)・E0010-4(整数部の桁溢れ)・警告 W0010-1・W0010-2 も `十進数` にのみ適用する。
- 改名は仕様書と索引に限り、ADR 0010 と思考実験 06・07 は決定の履歴として旧称のまま残す(ADR 0015 の先例)。

### 量と単位は両方の型に載る

0010 が単位で得たものは、記述の重さの原因ではない。**そのまま両方の型に適用する。**

- `量`・`単位` の宣言、異なる量の加減算・比較の禁止(E0010-1)、換算比を持たない量の扱い(E0010-2)、宣言のない組立の量の禁止(E0010-5)は変えない。
- **単位の欄は両方の型で省略できない**。単位を持たない事は `単位なし` と明示する(0010 と同じ)。
- 単位は型情報のみであり、実数でも実行時コストはゼロである。
- `単位を外す`・`単位を付ける` は両方の型で body 内でのみ書ける。
- 10 のべきの換算が桁を保つ規則は `十進数` の性質(静的指数)である。実数の換算は比を掛けるだけであり、丸めは他の演算と同じく型の性質として起きる。

**単位の検査は、数値型を軽くしても失われない。** 距離と重さの加算、m とインチの取り違えは、実数でもコンパイル時に落ちる。

### 実数の意味は IEEE 754 に厳密に従う

浮動小数点で「同じ記述が環境で違う結果を出す」原因は、規格ではなく**規格からの逸脱**にある。逸脱を全て禁じれば、分散した複数ノードでの一致(Raft の前提・ADR 0001)は保たれる。

- **binary64 のみ**とする(単精度・四倍精度は持たない)。精度の混在は、同じ式が経路によって違う結果を出す原因になる。
- **丸めは最近接偶数(roundTiesToEven)に固定**する。754 の5つの丸めモードを実行時に切り替える仕組みは持たない。大域の状態で結果が変わる事は「運用の驚き」そのものである。
- **次の最適化を禁じる**。いずれも「速くなるが結果が変わる」変換である。

  | 禁じる事                            | 何が起きるか                                  |
  | ----------------------------------- | --------------------------------------------- |
  | FMA への融合(`a × b + c`)           | 中間の丸めが1回減り、融合の有無で結果が変わる |
  | 再結合(`(a+b)+c → a+(b+c)`)         | 結合則が成立しないため結果が変わる            |
  | 拡張精度での中間保持(x87 80 ビット) | 丸めの回数と幅が経路で変わる                  |
  | 近似逆数・近似平方根命令            | 正しい丸めを満たさない                        |
  | 代数的な書き換え(`x × 0 → 0` 等)    | 特殊値・符号の扱いが変わる                    |

- **`+ - × ÷ 平方根` は IEEE 754 が結果を1ビットまで定めている**(正しい丸め)。上の禁止を守る限り、どのノード・どの出力先(Rust・TypeScript・ADR 0012)でも結果は同一である。
- **超越関数は 754 が結果を定めない**。言語が持つ関数(`累乗` 等)は**正しく丸めた結果を返す事を仕様が要求する**。実装が正しい丸めを保証できない関数は語彙に入れない。
  誤差 0.5ulp を超える実装や、環境の数学ライブラリへの委譲は、同じ記述が環境で違う結果を出すため認めない。
- **列の合算・畳み込みは先頭から順に行うと定める**。実装による並べ替え・並列化は禁じる。
  結合則は成立しない(それは binary64 の性質であり隠さない)が、**結果は一意に決まる**。再現性に必要なのは結合則ではなく順序の一意性である。

### NaN・±∞・-0 は値として持たない

0010 が「NaN は黙って伝播するため静かさの反対である」として排したものを、実数でも持ち込まない。**IEEE 754 の演算規則は採るが、特殊値は値の集合に入れない。**

- **特殊値を生む演算は失敗とする**(U13 の失敗の体系で扱う)。0 除算・負数の平方根・`∞ − ∞`・桁溢れが対象である。
- **検査の位置は 0010 と同じ「値が名前を得る所」**とする。data のフィールド・公開面・状態への受け渡しで、IEEE の例外フラグ(invalid・division-by-zero・overflow)を検査し、立っていれば失敗を返す。
  式の途中では検査しない。演算ごとの分岐を避けるためであり、0010 が「桁の検査は値が名前を得る所でのみ行う」とした規則と同じ形である。
- **-0 は名前を得る所で +0 に正規化する**。`0.0 == -0.0` なのに `1 ÷ 0.0 ≠ 1 ÷ -0.0` という食い違いを持ち込まない。
- **アンダーフロー(非正規化数・0 への丸め)は失敗にしない**。順序も等価も壊さず、0010 の「下に消える」丸めと同じ性質だからである(繰り返せば累積する事も同じ。指針は 0010 の W0010-2 と揃える)。
- 結果として、実数の比較は**全順序**であり、等価は素直である。`NaN ≠ NaN` は起きない。

### 2つの型は暗黙に混ざらない

| 操作                                      | 向き          | 桁・丸めの宣言                  | 失敗           |
| ----------------------------------------- | ------------- | ------------------------------- | -------------- |
| `近似する(値)`                            | 十進数 → 実数 | 不要(最近接偶数で丸める)        | 桁溢れ時のみ   |
| `厳密にする(値, 十進数(桁), 丸め <方式>)` | 実数 → 十進数 | 必須(0010 の規則がそのまま適用) | 整数部の桁溢れ |

- 変換の前後で**単位は保たれる**。型が変わるだけであり、量の検査は変換を跨いで効く。
- 実数と十進数が混ざった式はコンパイル時エラー(E0017-1)。どちらへ寄せるかは書き手の判断であり、言語が決めない。
- **往復は一致を保証しない**。`厳密にする(近似する(x), …)` は元の値に戻らない場合がある(W0017-2)。0010 の単位換算の往復と同じ性質である。
- **リテラルは書かれた通りの十進の値**であり、実数の文脈では最近接の binary64 になる。`0.1` が実数では 0.1000000000000000055511… である事は、`実数` という型名が告げている。

### 使い分けの指針

判断の基準は「**その値の刻みを、人が十進で決めたか**」である。

| 決めた(→ `十進数`)         | 測って得た・計算で作った(→ `実数`) |
| -------------------------- | ---------------------------------- |
| 金額・単価・手数料         | 距離・質量・温度・電圧の計測値     |
| 税率・利率・割引率         | 座標・角度・速度                   |
| 在庫数・注文数・按分の結果 | 平均・分散・標準偏差               |
| 会計・請求・帳簿の値       | 確率・尤度・スコア                 |

- **通貨の量(ADR 0010 の `量 通貨`)を持つ値に実数を使うと警告(W0017-1)**。禁止ではない(集計の速報値など、正当な用があり得る)が、既定の選択ではない事を告げる。
- 迷う場合の既定は `実数` とする。ただし、値が**帳簿に載る**・**外部と金額を突き合わせる**・**按分して合計が一致する必要がある**のいずれかに当たったら `十進数` へ移す。
- 移行は型名と桁の追加であり、公開面の変更(W0003-2)になる。0010 の「値域の見積りを先送りできない」は `十進数` を選んだ時点から始まる。

### 語彙の追補(ADR 0014)

| 語         | 綴り          | 備考                                              |
| ---------- | ------------- | ------------------------------------------------- |
| 実数       | `real`        | IEEE 754 binary64                                 |
| 十進数     | `decimal`     | ADR 0014 の `decimal`(旧「数値」)をそのまま用いる |
| 近似する   | `approximate` | 十進数 → 実数                                     |
| 厳密にする | `exact`       | 実数 → 十進数。桁と丸めの宣言が要る               |

ADR 0014 の基本型の表から `数値 | decimal` の行を上の2行に差し替える。指数(`exp`)・量(`quantity`)・単位(`unit`・ADR 0015)・丸め(`rounding`)の語は変えない。

### 検証の改訂(第3章 3.3)

検証番号は ADR 0016(採用)の `E<出自>-<連番>` 形式で書く。本 ADR が新設する検査の出自は `0017` である。
ADR 0010 由来の検査は、0010 の本文では E12〜E16・W3・W4 と書かれている(0010 は提案のまま本文を変えない。ADR 0016 決定5)。

| #       | 検査                                       | 0010 の本文 | 適用範囲            |
| ------- | ------------------------------------------ | ----------- | ------------------- |
| E0010-1 | 異なる量の加減算・比較                     | E12         | 両方(変更なし)      |
| E0010-2 | 換算比を持たない量の、単位を跨ぐ演算・換算 | E13         | 両方(変更なし)      |
| E0010-3 | 丸めが避けられない演算に丸めの宣言がない   | E14         | `十進数` のみ(改訂) |
| E0010-4 | 名前を得る所で整数部の桁が宣言を超える     | E15         | `十進数` のみ(改訂) |
| E0010-5 | 宣言のない組立の量の出現                   | E16         | 両方(変更なし)      |
| E0017-1 | 実数と十進数が明示の変換なしに混ざる       | —           | 新設                |

| #       | 検査                                           | 0010 の本文 | 適用範囲      |
| ------- | ---------------------------------------------- | ----------- | ------------- |
| W0010-1 | 換算先の分解能が換算元より粗い                 | W3          | `十進数` のみ |
| W0010-2 | 合算する状態の刻みが、足し込む値の刻みより粗い | W4          | `十進数` のみ |
| W0017-1 | 通貨の量を持つ値に `実数` を使っている         | —           | 新設          |
| W0017-2 | 実数と十進数のあいだで往復変換している         | —           | 新設          |

E0008-1(必須宣言の欠落)の対象は「型名・単位の欄・`十進数` の桁」であり、`実数` に桁が無い事は含まない。
出自ごとに採番するため、他の提案 ADR(0009 の E0009-1、0014 の E0014-1〜3)と衝突しない。採否の順序が変わっても番号は動かない。

## 結果(利点と欠点)

### 利点

#### 記述が軽くなる

| 0010 で書いていた事                    | 本 ADR(実数を使う場合)      |
| -------------------------------------- | --------------------------- |
| `数値(7.3) メートル`                   | `実数 メートル`             |
| `割る(a, b, 数値(3.2), 丸め 四捨五入)` | `a ÷ b`                     |
| `平方根(x, 数値(3.6), 丸め 四捨五入)`  | `平方根(x)`                 |
| 桁を狭める受け渡しの `桁溢れ` の分岐   | 不要(値域は型が1つに定める) |

設計時に値域を見積もる判断が、近似が本質の値では不要になる。桁溢れの分岐も消える。

#### 書けなかった計算が書ける

思考実験 07 の 3.3-5 が「丸めを1回に閉じ込める形では書けない」とした計算——反復解法、確率の積、信号処理、機械学習——が、そのまま書ける。
三角関数・対数も、正しい丸めを満たす限り実数の側に置ける(0010 では「丸めを伴うため語彙に入れない」保留のままだった)。

#### 外部世界との接合が軽くなる

- 外部から来る IEEE 754 の double を**そのまま受けられる**。0010 が抱えていた「double を厳密に受けるには最大 751 有効桁が要る」(思考実験 07 の 4)という境界の重さが、実数を受け口にする限り消える。
- センサー・数値ライブラリ・外部 API の多数派は binary64 である。接合の距離がゼロになる。
- トランスパイル先(ADR 0012)の要件も軽くなる。TypeScript の `number` は binary64 そのものであり、Rust の `f64` も同じである。多倍長整数が要るのは `十進数` を使う場合だけになる。

#### 性能

- 演算装置(FPU)がそのまま使える。0010 の「19 桁を超えると多倍長整数の演算になる」痛みは、`十進数` を選んだ場合だけに限られる。
- 記憶域は 8 バイト固定であり、乗算で中間桁が膨らむ事もない。

#### 失っていないもの

| 0010 が守ろうとしたもの    | 本 ADR での扱い                                     |
| -------------------------- | --------------------------------------------------- |
| 十進の値の厳密さ           | `十進数` にそのまま残る。金額は 0010 のまま書く     |
| 量と単位のコンパイル時検査 | 両方の型に載る。何も失わない                        |
| 分散ノードでの結果の一致   | strict IEEE + 正しい丸め + 合算順序の固定で保たれる |
| NaN・±∞・±0 が無い         | 特殊値を値に持たず、名前を得る所で失敗にする        |
| 比較が全順序・等価が素直   | 保たれる                                            |
| 省略の禁止                 | 型名も単位の欄も必ず書く。既定の数値型は置かない    |

### 欠点

#### 型が2つになる

- **選ぶ判断が全ての数値に発生する**。0010 では「桁をいくつにするか」だったものが、「どちらの型か」に置き換わる(軽くはなるが、無くはならない)。
- 変換(`近似する`・`厳密にする`)の語彙と、往復の非一致(W0017-2)という新しい落とし穴が増える。
- 公開面で型が食い違う組み合わせが生まれる。接続の型検査(ADR 0009 の E0009-1)が落とすが、直す作業は書き手に来る。

#### 主に使う型が誤差を持つ

- `0.1 + 0.2 ≠ 0.3` が、この言語の**既定の経験**になる。0010 が背景の冒頭で排除しようとした事そのものである。
- **金額に実数を使う誤りが起き得る**。W0017-1 は警告であり、禁止ではない。0010 では型システムが構造的に防いでいた誤りが、指針と警告に格下げされる。
- 型を読んでも刻みが分からない(実数の刻みは値の大きさで変わる)。0010 の「型を読めば値の範囲と刻みが分かる」は `十進数` にのみ残る。
- 繰り返しの中の誤差は累積し、上限は型に現れない。0010 の W0010-2 と同じ問題が、実数では警告の網からも外れる(刻みが静的でないため検査できない)。

#### strict IEEE の代償

- **FMA・再結合・並列合算を捨てる**。数値計算の性能は、これらを許す言語(C の `-ffast-math`、Fortran)より落ちる。
- **超越関数に正しい丸めを要求する**のは実装コストが高い(crlibm・RLIBM の系譜)。満たせない関数は語彙に入れないため、語彙が痩せる可能性がある。
- 例外フラグの検査が境界ごとに要る。演算ごとではないため軽いが、ゼロではない。

#### 決定の見え方

- ADR 0010 が「二進浮動小数点を既定の数値型にする案」を捨てた判断を、部分的に覆す事になる。捨てた理由(十進の値が正確でない)は消えていないため、**捨てた案が戻るのではなく、置き場所が変わった**という説明が要る(本 ADR の「捨てたもの」の第1項)。

### 総括 — 何と引き換えに何を得るか

**重さを、必要な所にだけ払う。**

ADR 0010 の総括は「実行時の驚きを、記述の重さとして前払いする」だった。本 ADR はその文を否定しない。**前払いする対象を絞る**。

| ADR 0010                      | 本 ADR                                        |
| ----------------------------- | --------------------------------------------- |
| 全ての数値が前払いする        | 厳密さが要る数値だけが前払いする              |
| 近似が本質の計算は書けない    | 書ける。近似である事は型の名前が告げる        |
| 驚きの排除 = 誤差を型から消す | 驚きの排除 = 型の名前と実際の性質を一致させる |

「運用で驚きがない」(第0章 0.5)の測り方は、**誤差が有るか無いか**ではなく、**型の名前が実際の性質を告げているか**である。
`実数` と書かれた値が近似である事は、名前が告げている。`十進数(7.2) 円` と書かれた値が 0.01 円刻みで厳密である事も、名前が告げている。
黙って壊れる物(NaN の伝播、±∞、-0、桁が静かに落ちる受け渡し)は、どちらの型からも排除したままである。

## 捨てたもの・理由

- **二進浮動小数点を「既定の数値型」にする案**: 本 ADR は既定を置かない。`実数` は主に使う型だが、書かなければその型にならない(省略の禁止・ADR 0008)。
  ADR 0010 が捨てたのは「十進の値が正確に表せない型を、書き手が選ばないまま使わされる事」であり、その判断は生きている。変わったのは**選べる型が増えた**事である。
- **十進固定小数点を廃止する案**: 金額・按分・帳簿が書けなくなる。0010 が思考実験 06 で示した価値(1円が消えない、分散で合計が一致する)は、実数では代替できない。
- **2種を持ち、主に使うのは十進固定小数点とする案(逃げ道として実数を足す)**: 重さが既定の側に残る。「書ける」と「書きやすい」は別であり、多数派の記述が重いままなら本 ADR の背景は解消しない。
- **単精度(binary32)・四倍精度(binary128)も持つ案**: 精度の混在は、同じ式が経路で違う結果を出す原因になる。トランスパイル先の TypeScript は binary64 しか持たない(ADR 0012)。組込みで必要が確認されたら再検討する(「将来の変更想定」)。
- **十進浮動小数点(decimal64/128)を「軽い十進」として置く案**: ADR 0010 と思考実験 07 の判断を維持する。加算の厳密さ・結合則・丸め箇所の静的な既知性・桁溢れのコンパイル時検出を同時に失い、得るものは動的範囲だけである。
  軽さが欲しいなら二進浮動小数点の方が速く、実行環境の支援も厚い。中間の形式を置く理由がない。
- **NaN・±∞ を値として持つ案(754 に完全に従う)**: `NaN ≠ NaN` により比較が全順序でなくなり、等価の意味が壊れる。NaN は黙って伝播するため、障害が伝播しない事を構造から生む(第0章)という理念に正面から反する。
  754 の演算規則は採り、特殊値だけを値の集合から外す。
- **実行時の丸めモード(754 の5モード)を持つ案**: 大域の状態で同じ記述の結果が変わる。分散ノードで設定が食い違えば合意が壊れる(ADR 0001)。
- **FMA・再結合・拡張精度を実装の裁量で許す案**: 速いが、同じ記述が環境で違う結果を出す。ADR 0010 が「桁の意味はバイト数に依存しない」と決めた事(移植性を性能より優先する)と同じ判断である。
- **超越関数を環境の数学ライブラリへ委譲する案**: `sin`・`log` の最終ビットは実装で食い違う。正しい丸めを要求できない関数は、語彙に入れない方を採る。
- **実数には単位を載せない案(軽さを徹底する)**: 単位の検査は記述の重さの原因ではなく(欄を1つ書くだけ)、落とす誤り(距離 + 重さ、m とインチ)は大きい。実行時コストもゼロである。
- **暗黙の型変換(実数 ↔ 十進数)を許す案**: どちらへ寄せるかで結果が変わる。金額を実数へ黙って落とす事は、0010 が排した「黙って桁が落ちる」の再来である。

## 将来の変更想定

- **binary32 の追加**。組込み・センサー・GPU で必要が確認されたら検討する。トランスパイル先(TypeScript)の対応(`Math.fround`)と、精度の混在の規則を先に決める必要がある。
- **三角関数・対数の語彙**。正しい丸めを満たす実装を用意できた関数から順に入れる。Phase 1 の実装で判断する。
- **`十進数` の桁の推論**。リテラルと演算から結果の桁を導き、書く量を減らす案。0010 の「値域の宣言」(`範囲 0..99999`)と併せて Phase 1 で検討する。
- **失敗の体系との統合(U13)**。0 除算・特殊値の発生・桁溢れは同じ失敗の語彙で扱う。検査を「名前を得る所」に置く規則も U13 で確定する。
- **外部世界との境界(U12)**。外部の double は実数で受けるのが素直な形になる(既定として補うのではなく、書き手が実数と書く)。外部形式の十進(JSON の数値、SQL の `DECIMAL`)をどちらで受けるかは U12 で決める。
- **近似である事の可視化(U8)**。図に型を載せる際、実数と十進数の別を示すかどうか。金額の経路に実数が混ざっている事は、図で見えると価値がある。
- 採用時の反映先: ADR 0010 の基本型名を `十進数` として読み替え、ADR 0009 の基本型「数値」を「実数」「十進数」の2つに改める。
  第2章のデータの宣言に両方の型を書き(ADR 0009 の反映先)、第3章 3.3 に E0017-1・W0017-1・W0017-2 を追加し、
  E0010-3・E0010-4・W0010-1・W0010-2 の適用範囲を `十進数` に限る。
