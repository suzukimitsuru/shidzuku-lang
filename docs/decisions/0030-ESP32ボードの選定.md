# 0030: ESP32 ボードの選定 — ロードの段ごとに1枚ずつ選ぶ

- 日付: 2026-10-03
- 状態: 提案
- 関連課題: 全体(Phase 2)。関連 U5
- 依拠: [ADR 0029](0029-最小の動作環境.md)(最小の動作環境。特に決定4 のロードの段と決定6 の認証)、
  [思考実験 27](../experiments/27-ESP32の最小動作環境.md) 第2節(機器)・第3節(通信)・第5節(ロード)
- 区別: 本 ADR が選ぶのは試作と Phase 2 の成果物に使う開発ボードであり、製品に載せる機器ではない。言語仕様には何も足さない

## 背景(なぜ決める必要があるか)

ADR 0029 は ESP32 の最小の動作環境を Phase 2 に置き、ロードを段で進めると決めた。第1段は P-1(一体の書き込み)と1機器1コンポーネント、
1台に複数を載せる時に P-2(WASM)を足す。思考実験 27 第2節は「P-1 なら ESP32-C6、P-2 なら PSRAM の付く ESP32-S3 が向く」と見立てたが、
品種を並べただけで、ボードは選んでいない。その後に PSRAM を持つ RISC-V の品種(ESP32-C5・ESP32-C61)が量産に入っており、見立てを確かめ直す必要がある。

ボードに求める事は、ADR 0029 の決定から次の7つになる(R7 は公式ボード以外を比べた時に足した)。

| #   | 求める事                                                 | 出どころ                          | 理由                                                                                                       |
| --- | -------------------------------------------------------- | --------------------------------- | ---------------------------------------------------------------------------------------------------------- |
| R1  | Rust で ESP-IDF の上に書ける                             | ADR 0029 決定1、思考実験 27 第2節 | 器は Rust で書き、zenoh-pico と WAMR は ESP-IDF の部品として配られる                                       |
| R2  | zenoh-pico が動く                                        | ADR 0001、思考実験 27 第3節       | 通信の全てである。ESP-IDF の上で UDP・TCP・シリアルを持つ                                                  |
| R3  | セキュアブートを持つ                                     | ADR 0029 決定6                    | P-1 のロードの認証を担う                                                                                   |
| R4  | 2面の OTA 区画が取れるフラッシュ                         | ADR 0029 決定4                    | P-1 は空いている区画に書き、起動に失敗したら前の区画に戻る。8MB あれば余裕を持てる                         |
| R5  | USB だけで書き込みとシリアルが繋がる                     | 思考実験 27 第3節                 | 最小の構成は PC 1台+ ESP32 1台。シリアルで繋げば Wi-Fi の設定無しに始められる                              |
| R6  | P-2 では PSRAM と WAMR の対応                            | ADR 0029 決定4                    | wasm の線形記憶は 64KiB を単位に取る。WAMR の ESP-IDF 部品が品種に対応している事                           |
| R7  | USB の口が UART と USB シリアル/JTAG の2つに分かれている | 思考実験 27 第3節・第4節          | 一方を zenoh-pico のシリアルの繋がりに、もう一方を書き込み・ログ・JTAG に使える。1つの口では両者が取り合う |

R6 は P-2 にだけ掛かる。P-1 の段では PSRAM を要らない。R7 は必須ではないが、最小の構成(シリアルで繋ぐ)で開発する間は効きが大きい。

## 検討した選択肢

品種ごとに、Espressif の公式の開発ボード(DevKitC-1)を候補とした。回路図と資料が揃い、版の違いが追える。

| 品種      | 候補のボード              | CPU          | PSRAM    | Rust の道具              | Rust の ESP-IDF の上の成熟 | WAMR   | 無線                   | 判定                  |
| --------- | ------------------------- | ------------ | -------- | ------------------------ | -------------------------- | ------ | ---------------------- | --------------------- |
| ESP32-C6  | ESP32-C6-DevKitC-1(N8)    | RISC-V 1コア | 無い     | rustc 本流のターゲット   | 成熟                       | 対応   | Wi-Fi 6・BLE・802.15.4 | **P-1 に推す**        |
| ESP32-S3  | ESP32-S3-DevKitC-1(N16R8) | Xtensa 2コア | 8MB      | Espressif の分岐した道具 | 成熟                       | 対応   | Wi-Fi 4・BLE           | **P-2 に推す**        |
| ESP32-C5  | ESP32-C5-DevKitC-1(N8R4)  | RISC-V 1コア | 4MB      | rustc 本流のターゲット   | 若い                       | 対応   | Wi-Fi 6(2.4/5GHz)・BLE | P-2 の段で再評価する  |
| ESP32-C61 | ESP32-C61-DevKitC-1(N8R2) | RISC-V 1コア | 2MB      | rustc 本流のターゲット   | 若い                       | 未対応 | Wi-Fi 6・BLE           | 採らない              |
| ESP32-C3  | ESP32-C3-DevKitC-02       | RISC-V 1コア | 無い     | rustc 本流のターゲット   | 成熟                       | 対応   | Wi-Fi 4・BLE           | 採らない(C6 で足りる) |
| ESP32     | ESP32-DevKitC             | Xtensa 2コア | 版による | Espressif の分岐した道具 | 成熟                       | 対応   | Wi-Fi 4・Bluetooth     | 採らない              |

- 「Rust の ESP-IDF の上の成熟」は、`esp-idf-svc`・`esp-idf-hal` の対応の度合いを指す。標準ライブラリを使わない `esp-hal` は 1.0 で C5・C61 まで対応したが、
  器は zenoh-pico と WAMR を ESP-IDF の部品として使うため(R1)、ESP-IDF の上の対応で見る。
- 型番の `N8` はフラッシュ 8MB、`R8` は PSRAM 8MB を表す。同じボードに型番の違いがあるため、買う時は型番で指す。

### 公式ボード以外の候補(2026-10-03 追記)

suzukimitsuru の指示で、Espressif の公式ボード以外にも最適な物が無いかを調べた。同じ品種を載せた小型ボードと、ESP32 以外の基板を比べた。

| ボード                | 品種     | フラッシュ | PSRAM | USB の口                     | 載っている物                  | 判定                              |
| --------------------- | -------- | ---------- | ----- | ---------------------------- | ----------------------------- | --------------------------------- |
| Seeed XIAO ESP32C6    | ESP32-C6 | 4MB        | 無い  | 1つ(USB シリアル/JTAG)       | 電池の充電、外付けアンテナ    | 採らない(R4・R7)                  |
| Seeed XIAO ESP32C5    | ESP32-C5 | 8MB        | 8MB   | 1つ(USB シリアル/JTAG)       | 電池の充電、外付けアンテナ    | C5 を採る時の小型の候補           |
| M5Stack AtomS3R       | ESP32-S3 | 8MB        | 8MB   | 1つ(USB OTG とシリアル/JTAG) | 画面、6軸 IMU、地磁気センサー | P-2 の小型の候補。R7 を満たさない |
| Raspberry Pi Pico 2 W | RP2350   | 4MB        | 無い  | 1つ                          | 署名付き起動、TrustZone       | ESP32 の範囲の外。採らない        |

- **XIAO の2枚は、小さく安く、外付けアンテナを繋げる。** ただし XIAO ESP32C6 はフラッシュが 4MB で、2面の OTA 区画に余裕が無い(R4)。
  XIAO ESP32C5 は 8MB と 8MB を持ち、公式の C5-DevKitC-1(N8R4)より PSRAM が多い。C5 を採る段(決定2)が来たら候補に入る。
- **AtomS3R は IMU と地磁気センサーを載せ**、SensorIntake の計測値の出どころにそのまま使える。PSRAM も 8MB ある。
  ただし USB の口が1つで、zenoh-pico のシリアルの繋がりと書き込み・ログが取り合う(R7)。
- **Raspberry Pi Pico 2 W** は zenoh-pico が動作確認をしており、RP2350 は署名付き起動と Arm TrustZone を持つ。
  ただし ADR 0029 は ESP32 を前提とし、OTA・セキュアブート・WAMR・zenoh-pico を ESP-IDF の1つの SDK で揃える事を利点としていた。Pico 2 W にはこれが無い。
- 公式の DevKitC-1 は、**USB の口が2つある**(UART 変換と、チップの USB シリアル/JTAG)。シリアルで zenoh-pico を繋ぎながら、もう一方で書き込みとログと JTAG のデバッグができる。
  小型ボードはどれも口が1つであり、R7 を満たすのは調べた中では公式の DevKitC-1 だけだった。

結論として、**決定1・決定2 の推奨は変わらない。** 変わったのは、R7 を推す理由に加えた事、P-1 の枚数(決定1)、C5 を採る時の候補(決定2)である。

## 決定(提案)

### 決定1 — P-1 の段は ESP32-C6-DevKitC-1(N8)とする

- RISC-V であり、**rustc 本流のターゲット**で書ける。Espressif の分岐した道具を要らない(R1)。
- `esp-idf-svc` の対応が成熟しており、zenoh-pico・OTA・セキュアブート(Secure Boot V2)を ESP-IDF の上でそのまま使える(R2・R3)。
- フラッシュ 8MB で、2面の OTA 区画に余裕がある(R4)。
- USB の口が2つあり、一方で zenoh-pico をシリアルで繋ぎながら、もう一方で書き込み・ログ・JTAG のデバッグができる(R5・R7)。調べた小型ボードには無い利点である。
- 計測値の出どころには、チップ内蔵の温度センサーを使える。思考実験 02 の上流を動かすだけなら、外付けのセンサーは要らない。
- 内蔵 RAM は 512KB である。P-1 は1機器1コンポーネントなので PSRAM は要らないと見込む。Wi-Fi・zenoh-pico・動作環境・コンポーネントを載せた時の空きは、最初の実験で測る。
- Phase 2 の題材(思考実験 02 の上流、SensorIntake・Normalizer)は、1台に1つずつで **2枚**要る。
- **セキュアブートの確かめには専用の1枚を充てる。** セキュアブートを有効にすると eFuse を焼き、元に戻せない。開発に使う2枚を焼くと、署名の無いイメージを書いて試す事ができなくなる。
- 開発に2枚、セキュアブートの確かめに1枚、予備に1枚で、**4枚**を推す。

### 決定2 — P-2 の段は ESP32-S3-DevKitC-1(N16R8)とする。ただし P-2 に入る時に ESP32-C5 と比べ直す

- 8MB の PSRAM で、複数の wasm の線形記憶を置ける。WAMR の ESP-IDF 部品が対応し、PSRAM を自動で使う(R6)。
- `esp-idf-svc` の対応は成熟している。代わりに Xtensa であり、Espressif の分岐した道具(`espup`)が要る。
  意味の核は `no_std` の1クレート(ADR 0029 決定1)なので、道具が分かれても核の中身は変わらない。器の組み立てだけが二通りになる。
- **ESP32-C5 は、P-1 と P-2 を RISC-V の1品種で揃えられる唯一の候補である**(PSRAM を持ち、WAMR も対応する)。
  ただし現時点では Rust の ESP-IDF の上の対応が若い。P-2 に入る時点で `esp-idf-svc` の対応を確かめ、成熟していれば S3 に代えて C5 を採る。
  C5 を採る時のボードは、公式の ESP32-C5-DevKitC-1(N8R4)を第一とし、PSRAM がもっと要れば XIAO ESP32C5(8MB)を考える。
- P-2 の段は「1台に複数を載せたくなった時」に来る(ADR 0029 決定4)。今は買わなくてよい。

### 決定3 — 買う時の型番の条件を、品種より先に置く

ボードの型番は流通と版で変わる。品種や型番が手に入らない時は、次の条件で代わりを選ぶ。

- フラッシュは 8MB 以上(R4)
- 内蔵の USB(シリアル/JTAG)か、USB シリアル変換を載せている(R5)。両方を別の口で持つ物を優先する(R7)
- P-2 用は PSRAM 4MB 以上(R6)
- Espressif の公式ボードか、回路図が公開されているボード

## 捨てたもの・理由

- **ESP32-C61**: PSRAM を持つ安価な RISC-V だが、WAMR の ESP-IDF 部品が対応していない(R6)。P-1 だけなら C6 で足り、選ぶ理由が無い。
- **ESP32-C3**: P-1 には足りるが、内蔵 RAM が 400KB で C6 より小さい。C6 を選ばない理由が無い。
- **ESP32(無印)**: 内蔵の USB を持たず、セキュアブートの版(Secure Boot V2)はチップの版(v3.0 以降)に依る。Xtensa で道具も分かれる。新しく選ぶ理由が無い。
- **ESP32-H2・ESP32-P4**: H2 は Wi-Fi を持たない。P4 は無線を持たない。どちらも zenoh-pico をそのまま Wi-Fi で繋げない。
- **P-1 と P-2 を最初から S3 の1品種に揃える案**: 揃える利点はあるが、P-1 の段から Espressif の分岐した道具を背負う。P-2 はまだ来ていない。
- **XIAO ESP32C6**: 小さく安いが、フラッシュが 4MB で 2面の OTA 区画に余裕が無く(R4)、USB の口も1つである(R7)。
- **M5Stack AtomS3R を P-2 に採る案**: センサーと PSRAM を載せて魅力があるが、USB の口が1つである(R7)。P-2 の開発がシリアルを要らない段まで進んだら、代わりの条件(決定3)の範囲で使ってよい。
- **Raspberry Pi Pico 2 W**: zenoh-pico が動き、署名付き起動と TrustZone を持つが、ESP32 の外である。ADR 0029 が前提とした ESP-IDF の1つの SDK(OTA・セキュアブート・WAMR・zenoh-pico)が無い。
- **その他の小型ボード**: 版と回路の違いを追いにくい。代わりの条件(決定3)を満たせば使ってよい。

## 将来の変更想定

- **P-2 に入る時**、ESP32-C5 の Rust の ESP-IDF の上の対応を確かめる(決定2)。成熟していれば S3 に代えて C5 を採り、P-1 と P-2 を RISC-V に揃える。
- **ESP32-C61 が WAMR に対応したら**、PSRAM が 2MB で足りるかを P-2 の実測で見て、候補に戻す。
- **zenoh-pico の ESP-IDF の対応**は、ボードを買った後の最初の実験で確かめる。思考実験 27 の参考資料の版の時点では ESP-IDF の上で UDP・TCP・シリアルを持つ。
- **Phase 2 の題材が思考実験 02 の上流から増えたら**、枚数を足す。1機器1コンポーネントなので、コンポーネントの数がそのまま枚数になる。
