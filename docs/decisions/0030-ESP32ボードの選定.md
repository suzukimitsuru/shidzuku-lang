# 0030: ESP32 ボードの選定 — ロードの段ごとに1種ずつ選ぶ

- 日付: 2026-10-03
- 状態: 提案
- 関連課題: 全体(最小の分散動作環境、Phase 2)。関連 トランスパイル先の言語(U5)
- 依拠: [ADR 0029(最小の動作環境)](0029-最小の動作環境.md)(特に決定4(ロードの段)と決定6(ロードの認証))、
  [思考実験 27(ESP32 の最小動作環境)](../experiments/27-ESP32の最小動作環境.md) の第2節(機器)・第3節(通信)・第5節(プログラムのロード)
- 区別: 本 ADR が選ぶのは、試作と最小の分散動作環境(Phase 2)の成果物に使う開発ボードであり、製品に載せる機器ではない。言語仕様には何も足さない
- 用語: WASM(WebAssembly)、OTA(Over-The-Air、回線越しのファームウェア更新)、PSRAM(Pseudo-Static RAM、外付けの擬似 SRAM)、
  WAMR(WebAssembly Micro Runtime、組込み機器向けの WebAssembly 実行系)、UART(Universal Asynchronous Receiver/Transmitter、非同期シリアル通信)、
  JTAG(Joint Test Action Group、デバッグ用の接続規格)、eFuse(一度だけ書き込めるチップ内の設定領域)

## 背景(なぜ決める必要があるか)

ADR 0029(最小の動作環境)は、ESP32 の最小の動作環境を最小の分散動作環境(Phase 2)に置き、ロードを段で進めると決めた。
第1段は**一体の書き込み**(動作環境とコンポーネントを1つのイメージに焼く)と1機器1コンポーネント、1台に複数を載せる時に**WASM でのロード**を足す。
思考実験 27(ESP32 の最小動作環境)の第2節(機器)は「一体の書き込みなら ESP32-C6、WASM でのロードなら PSRAM の付く ESP32-S3 が向く」と見立てたが、
品種を並べただけで、ボードは選んでいない。その後に PSRAM を持つ RISC-V の品種(ESP32-C5・ESP32-C61)が量産に入っており、見立てを確かめ直す必要がある。

ボードに求める事は、ADR 0029 の決定から次の7つになる。「USB の口の分離」は、公式ボード以外を比べた時に足した。

| 求める事                             | 出どころ                                                      | 理由                                                                                                                                    |
| ------------------------------------ | ------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------- |
| Rust で ESP-IDF の上に書ける         | ADR 0029 の決定1(意味の核)、思考実験 27 の第2節(機器)         | 器は Rust で書き、zenoh-pico と WAMR は ESP-IDF の部品として配られる                                                                    |
| zenoh-pico が動く                    | ADR 0001(分散環境の通信プロトコル)、思考実験 27 の第3節(通信) | 通信の全てである。ESP-IDF の上で UDP・TCP・シリアルを持つ                                                                               |
| セキュアブートを持つ                 | ADR 0029 の決定6(ロードの認証)                                | 一体の書き込みでは、ロードの認証をセキュアブートが担う                                                                                  |
| OTA の区画を2面取れるフラッシュ      | ADR 0029 の決定4(ロードの段)                                  | 一体の書き込みは空いている区画に書き、起動に失敗したら前の区画に戻る。8MB あれば余裕を持てる                                            |
| USB だけで書き込みとシリアルが繋がる | 思考実験 27 の第3節(通信)                                     | 最小の構成は PC 1台と ESP32 1台。シリアルで繋げば Wi-Fi の設定無しに始められる                                                          |
| PSRAM と WAMR の対応                 | ADR 0029 の決定4(ロードの段)                                  | wasm の線形記憶は 64KiB を単位に取る。WAMR の ESP-IDF 部品が品種に対応している事                                                        |
| USB の口の分離                       | 思考実験 27 の第3節(通信)・第4節(状態の確認)                  | UART 変換の口で zenoh-pico をシリアルで繋ぎ、チップの USB シリアル/JTAG の口で書き込み・ログ・デバッグを行う。1つの口では両者が取り合う |

「PSRAM と WAMR の対応」は WASM でのロードにだけ掛かり、一体の書き込みの段では PSRAM を要らない。
「USB の口の分離」は必須ではないが、最小の構成(シリアルで繋ぐ)で開発する間は効きが大きい。

## 検討した選択肢

### Espressif の公式ボード

品種ごとに、Espressif の公式の開発ボード(DevKitC-1)を候補とした。回路図と資料が揃い、版の違いが追える。

| 品種      | 候補のボード              | CPU          | PSRAM    | Rust の道具              | Rust の ESP-IDF の上の成熟 | WAMR   | 無線                   | 判定                          |
| --------- | ------------------------- | ------------ | -------- | ------------------------ | -------------------------- | ------ | ---------------------- | ----------------------------- |
| ESP32-C6  | ESP32-C6-DevKitC-1(N8)    | RISC-V 1コア | 無い     | rustc 本流のターゲット   | 成熟                       | 対応   | Wi-Fi 6・BLE・802.15.4 | **一体の書き込みに推す**      |
| ESP32-S3  | ESP32-S3-DevKitC-1(N16R8) | Xtensa 2コア | 8MB      | Espressif の分岐した道具 | 成熟                       | 対応   | Wi-Fi 4・BLE           | **WASM でのロードに推す**     |
| ESP32-C5  | ESP32-C5-DevKitC-1(N8R4)  | RISC-V 1コア | 4MB      | rustc 本流のターゲット   | 若い                       | 対応   | Wi-Fi 6(2.4/5GHz)・BLE | WASM でのロードの段で比べ直す |
| ESP32-C61 | ESP32-C61-DevKitC-1(N8R2) | RISC-V 1コア | 2MB      | rustc 本流のターゲット   | 若い                       | 未対応 | Wi-Fi 6・BLE           | 採らない                      |
| ESP32-C3  | ESP32-C3-DevKitC-02       | RISC-V 1コア | 無い     | rustc 本流のターゲット   | 成熟                       | 対応   | Wi-Fi 4・BLE           | 採らない(ESP32-C6 で足りる)   |
| ESP32     | ESP32-DevKitC             | Xtensa 2コア | 版による | Espressif の分岐した道具 | 成熟                       | 対応   | Wi-Fi 4・Bluetooth     | 採らない                      |

- 「Rust の ESP-IDF の上の成熟」は、`esp-idf-svc`・`esp-idf-hal` の対応の度合いを指す。標準ライブラリを使わない `esp-hal` は 1.0 で ESP32-C5・ESP32-C61 まで対応したが、
  器は zenoh-pico と WAMR を ESP-IDF の部品として使うため(「Rust で ESP-IDF の上に書ける」)、ESP-IDF の上の対応で見る。
- BLE は Bluetooth Low Energy(省電力の Bluetooth)を指す。
- 型番の `N8` はフラッシュ 8MB、`R8` は PSRAM 8MB を表す。同じボードに型番の違いがあるため、買う時は型番で指す。

### 公式ボード以外の候補(2026-10-03 追記)

suzukimitsuru の指示で、Espressif の公式ボード以外にも最適な物が無いかを調べた。同じ品種を載せた小型ボードと、ESP32 以外の基板を比べた。

| ボード                | 品種     | フラッシュ | PSRAM | USB の口                     | 載っている物                                 | 判定                                 |
| --------------------- | -------- | ---------- | ----- | ---------------------------- | -------------------------------------------- | ------------------------------------ |
| Seeed XIAO ESP32C6    | ESP32-C6 | 4MB        | 無い  | 1つ(USB シリアル/JTAG)       | 電池の充電、外付けアンテナ                   | 採らない(フラッシュ・USB の口の分離) |
| Seeed XIAO ESP32C5    | ESP32-C5 | 8MB        | 8MB   | 1つ(USB シリアル/JTAG)       | 電池の充電、外付けアンテナ                   | ESP32-C5 を採る時の小型の候補        |
| M5Stack AtomS3R       | ESP32-S3 | 8MB        | 8MB   | 1つ(USB OTG とシリアル/JTAG) | 画面、6軸の慣性計測装置(IMU)、地磁気センサー | WASM でのロードの小型の候補          |
| Raspberry Pi Pico 2 W | RP2350   | 4MB        | 無い  | 1つ                          | 署名付き起動、Arm TrustZone                  | ESP32 の範囲の外。採らない           |

- **XIAO の2枚は、小さく安く、外付けアンテナを繋げる。** ただし XIAO ESP32C6 はフラッシュが 4MB で、OTA の区画を2面取るには余裕が無い。
  XIAO ESP32C5 は 8MB と 8MB を持ち、公式の ESP32-C5-DevKitC-1(N8R4)より PSRAM が多い。ESP32-C5 を採る段(決定2(WASM でのロードのボード))が来たら候補に入る。
- **AtomS3R は慣性計測装置と地磁気センサーを載せ**、SensorIntake の計測値の出どころにそのまま使える。PSRAM も 8MB ある。
  ただし USB の口が1つで、zenoh-pico のシリアルの繋がりと書き込み・ログが取り合う。
- **Raspberry Pi Pico 2 W** は zenoh-pico が動作を確かめており、RP2350 は署名付き起動と Arm TrustZone を持つ。
  ただし ADR 0029(最小の動作環境)は ESP32 を前提とし、OTA・セキュアブート・WAMR・zenoh-pico を ESP-IDF の1つの SDK(Software Development Kit)で揃える事を利点としていた。Pico 2 W にはこれが無い。
- 公式の DevKitC-1 は、**USB の口が2つある**(UART 変換と、チップの USB シリアル/JTAG)。シリアルで zenoh-pico を繋ぎながら、もう一方で書き込みとログと JTAG のデバッグができる。
  小型ボードはどれも口が1つであり、「USB の口の分離」を満たすのは調べた中では公式の DevKitC-1 だけだった。

結論として、**決定1(一体の書き込みのボード)・決定2(WASM でのロードのボード)の推奨は変わらない。**
変わったのは、「USB の口の分離」を推す理由に加えた事、一体の書き込みのボードの枚数、ESP32-C5 を採る時の候補である。

## 決定(提案)

### 決定1 — 一体の書き込みのボードは ESP32-C6-DevKitC-1(N8)とする

- RISC-V であり、**rustc 本流のターゲット**で書ける。Espressif の分岐した道具を要らない(「Rust で ESP-IDF の上に書ける」)。
- `esp-idf-svc` の対応が成熟しており、zenoh-pico・OTA・セキュアブート(Secure Boot V2)を ESP-IDF の上でそのまま使える。
- フラッシュ 8MB で、OTA の区画を2面取っても余裕がある。
- USB の口が2つあり、一方で zenoh-pico をシリアルで繋ぎながら、もう一方で書き込み・ログ・JTAG のデバッグができる(「USB の口の分離」)。調べた小型ボードには無い利点である。
- 計測値の出どころには、チップ内蔵の温度センサーを使える。思考実験 02(センサー収集パイプライン)の上流を動かすだけなら、外付けのセンサーは要らない。
- 内蔵の SRAM は 512KB である。一体の書き込みは1機器1コンポーネントなので PSRAM は要らないと見込む。Wi-Fi・zenoh-pico・動作環境・コンポーネントを載せた時の空きは、最初の実験で測る。
- 最小の分散動作環境(Phase 2)の題材(思考実験 02 の上流、SensorIntake・Normalizer)は、1台に1つずつで **2枚**要る。
- **セキュアブートの確かめには専用の1枚を充てる。** セキュアブートを有効にすると eFuse を焼き、元に戻せない。開発に使う2枚を焼くと、署名の無いイメージを書いて試す事ができなくなる。
- 開発に2枚、セキュアブートの確かめに1枚、予備に1枚で、**4枚**を推す。

### 決定2 — WASM でのロードのボードは ESP32-S3-DevKitC-1(N16R8)とする。ただし WASM でのロードに入る時に ESP32-C5 と比べ直す

- 8MB の PSRAM で、複数の wasm の線形記憶を置ける。WAMR の ESP-IDF 部品が対応し、PSRAM を自動で使う。
- `esp-idf-svc` の対応は成熟している。代わりに Xtensa であり、Espressif の分岐した道具(`espup`)が要る。
  意味の核は `no_std` の1クレート(ADR 0029 の決定1(意味の核))なので、道具が分かれても核の中身は変わらない。器の組み立てだけが二通りになる。
- **ESP32-C5 は、一体の書き込みと WASM でのロードを RISC-V の1品種で揃えられる唯一の候補である**(PSRAM を持ち、WAMR も対応する)。
  ただし現時点では Rust の ESP-IDF の上の対応が若い。WASM でのロードに入る時点で `esp-idf-svc` の対応を確かめ、成熟していれば ESP32-S3 に代えて ESP32-C5 を採る。
  ESP32-C5 を採る時のボードは、公式の ESP32-C5-DevKitC-1(N8R4)を第一とし、PSRAM がもっと要れば XIAO ESP32C5(8MB)を考える。
- WASM でのロードの段は「1台に複数を載せたくなった時」に来る(ADR 0029 の決定4(ロードの段))。今は買わなくてよい。

### 決定3 — 買う時の型番の条件を、品種より先に置く

ボードの型番は流通と版で変わる。品種や型番が手に入らない時は、次の条件で代わりを選ぶ。

- フラッシュは 8MB 以上(OTA の区画を2面取るため)
- 内蔵の USB シリアル/JTAG か、USB シリアル変換を載せている。両方を別の口で持つ物を優先する(「USB の口の分離」)
- WASM でのロードに使う物は PSRAM 4MB 以上
- Espressif の公式ボードか、回路図が公開されているボード

## 捨てたもの・理由

- **ESP32-C61**: PSRAM を持つ安価な RISC-V だが、WAMR の ESP-IDF 部品が対応していない。一体の書き込みだけなら ESP32-C6 で足り、選ぶ理由が無い。
- **ESP32-C3**: 一体の書き込みには足りるが、内蔵の SRAM が 400KB で ESP32-C6 より小さい。ESP32-C6 を選ばない理由が無い。
- **ESP32(無印)**: 内蔵の USB を持たず、セキュアブートの版(Secure Boot V2)はチップの版(v3.0 以降)に依る。Xtensa で道具も分かれる。新しく選ぶ理由が無い。
- **ESP32-H2・ESP32-P4**: ESP32-H2 は Wi-Fi を持たない。ESP32-P4 は無線を持たない。どちらも zenoh-pico をそのまま Wi-Fi で繋げない。
- **一体の書き込みと WASM でのロードを最初から ESP32-S3 の1品種に揃える案**: 揃える利点はあるが、一体の書き込みの段から Espressif の分岐した道具を背負う。WASM でのロードの段はまだ来ていない。
- **XIAO ESP32C6**: 小さく安いが、フラッシュが 4MB で OTA の区画を2面取るには余裕が無く、USB の口も1つである。
- **M5Stack AtomS3R を WASM でのロードに採る案**: センサーと PSRAM を載せて魅力があるが、USB の口が1つである。WASM でのロードの開発がシリアルを要らない段まで進んだら、代わりの条件(決定3(型番の条件))の範囲で使ってよい。
- **Raspberry Pi Pico 2 W**: zenoh-pico が動き、署名付き起動と Arm TrustZone を持つが、ESP32 の外である。ADR 0029(最小の動作環境)が前提とした ESP-IDF の1つの SDK(OTA・セキュアブート・WAMR・zenoh-pico)が無い。
- **その他の小型ボード**: 版と回路の違いを追いにくい。代わりの条件(決定3(型番の条件))を満たせば使ってよい。

## 将来の変更想定

- **WASM でのロードに入る時**、ESP32-C5 の Rust の ESP-IDF の上の対応を確かめる(決定2(WASM でのロードのボード))。成熟していれば ESP32-S3 に代えて ESP32-C5 を採り、両方の段を RISC-V に揃える。
- **ESP32-C61 が WAMR に対応したら**、PSRAM が 2MB で足りるかを WASM でのロードの実測で見て、候補に戻す。
- **zenoh-pico の ESP-IDF の対応**は、ボードを買った後の最初の実験で確かめる。思考実験 27(ESP32 の最小動作環境)の参考資料の版の時点では、ESP-IDF の上で UDP・TCP・シリアルを持つ。
- **最小の分散動作環境(Phase 2)の題材が思考実験 02(センサー収集パイプライン)の上流から増えたら**、枚数を足す。1機器1コンポーネントなので、コンポーネントの数がそのまま枚数になる。
