# 0024: APoSD と結合バランスの考え方の取り込み

- 日付: 2026-09-26
- 状態: 提案
- 関連課題: 全体(第0章 0.9 の系譜)。関連 U7(粒度の指針)・U14(プログラムの宣言)・U8(図と実装の一致)

## 背景(なぜ決める必要があるか)

Shidzuku の外に、モジュールの分け方について近い問題を解いてきた先行知見が二つある。

- **APoSD**(John Ousterhout, *A Philosophy of Software Design*): 複雑さを変更の増幅・認知負荷・未知の未知の三つに分け、
  狭いインターフェースの奥に豊かな実装を隠す**深いモジュール**を勧める。第0章 0.9 は系譜として挙げているが、取り込んだ範囲は「深いモジュール」の一語しか書かれていない。
- **結合バランス**(Vlad Khononov, *Balancing Coupling in Software Design*): 結合を**統合の強度**(侵入・機能・モデル・契約)・**距離**・**変動性**の三軸で測り、
  強度と距離が逆向きなら釣り合うとする。仕様のどこにも参照が無い。

APoSD は一つのモジュールの形を問い、結合バランスはモジュールの間の関係を問う。
Shidzuku の意図層は前者を(ADR 0003・0006)、制約層は後者を(`depends`・`expose`・`contains`)記述している。
思考実験 23 で既存の記述を三軸で読み直したところ、仕様は両方の知見を**名前を挙げずに**かなり使っていた。
一方で、APoSD と正面から逆の判断(既定値の廃止、ADR 0008)があり、その対比はどこにも記録されていない。

ADR 0007 が ADR と C4 モデルについてしたのと同じく、どこを取り込み、どこを取り込まないかを決めておく。
取り込みの範囲が書かれていないと、後の ADR が同じ書名を根拠に挙げても、何を根拠にしたのかが読み手に分からない。

### 対応関係の確認

APoSD の知見と、仕様の中で既にそれを担っている所。

| APoSD の知見                       | Shidzuku で担っている所                                                    |
| ---------------------------------- | -------------------------------------------------------------------------- |
| 深いモジュール                     | コンポーネントの定義(第0章 0.4)                                            |
| 浅いモジュール・素通しの委譲       | 小さすぎのシグナル(ADR 0006)                                               |
| 情報漏洩(同じ知識が複数の所に在る) | intent の why を「何の知識を隠すか」と問う(ADR 0003)                       |
| 二度設計する(Design it Twice)      | intent の `rejected` を(選択肢, 理由)の組で必須にする(ADR 0003)            |
| コメントには自明でない事を書く     | 検証不能な意図を言語が強制する(三層記述)                                   |
| 例外を存在しないように定義する     | 障害の非伝播を宣言ではなく不変条件にする。`ask` は必ず返る(ADR 0004・0008) |
| 複雑さを下へ押し込む               | 合意とログの自動出力を実行系が引き受ける(第0章 0.6)                        |
| よく使う場合を簡単にする(既定値)   | **逆を選んだ**。既定値を持たない(ADR 0008)                                 |

結合バランスの三軸と、仕様の中で対応する所(思考実験 23 の第1節)。

| 軸     | Shidzuku で対応する所                                                                              |
| ------ | -------------------------------------------------------------------------------------------------- |
| 強度   | 侵入は書けない(E0018-4)。機能は `correlate` が宣言する。モデルは宣言されない。契約は境界の層が担う |
| 距離   | `contains` の木。コンポーネント間の最短距離がプロセスの境界である(ADR 0012)                        |
| 変動性 | intent の `change` と、`rejected` の理由(自由文)                                                   |

## 検討した選択肢

APoSD について。

- **P1: 系譜の一語(深いモジュール)のまま置く**: 取り込んだ範囲を書かない。
- **P2: 取り込んだ範囲と、取り込まなかった範囲を書く**: 上の対応表を系譜に要約し、既定値についての逆の判断を理由とともに残す。
- **P3: APoSD の推奨に合わせて既定値を戻す**: ADR 0008 を改訂する。

結合バランスについて。

- **K1: 取り込まない**: 系譜に挙げない。
- **K2: 物差しとして取り込む**: 三軸を、設計とレビューの見方として系譜に置く。言語の検証にはしない。
- **K3: 検証として取り込む**: 強度・距離・変動性を言語が計算し、釣り合いの崩れをエラーや警告にする。

## 決定

### 決定1 — APoSD は P2: 取り込んだ範囲と、逆を選んだ所を書く

第0章 0.9 の APoSD の行を「深いモジュール」から、上の対応表の要約(深いモジュール・素通しの委譲・二度設計する・例外を存在しないように定義する)に広げる。

### 決定2 — 既定値については APoSD と逆を選ぶ。理由を二つの知見の両方で記録する

APoSD は、よく使う場合を簡単にするために既定値を勧める。Shidzuku はこれを採らない(ADR 0008 を維持する)。

- **APoSD の側から**: 既定値はインターフェースを短くするが、読み手に既定の表という**未知の未知**を残す。
  Shidzuku が減らそうとしているのは、書き手の手間ではなく、読み手がその記述の外に要る知識である(ADR 0008 の背景)。
- **結合バランスの側から**: 既定値は、全ての記述と言語の既定の表との**モデル結合**である。
  その相手は最も遠く(記述の外にある言語の版)、変わり得る(出力先が2言語、版の混在 U16)。
  **強い・遠い・変わり得る**の三つが揃う、最も釣り合わない結合である。

ADR 0008 の本文は変えない。対比の記録は本 ADR が持ち、ADR 0008 の読み手は第0章 0.9 から本 ADR へ辿る。

### 決定3 — 結合バランスは K2: 物差しとして取り込み、言語の検証にはしない

三軸は、コンポーネントの間とシステムの間を**見る見方**として取り込む。取り込み先は次の三つである。

- 粒度の指針(U7): コンポーネントの間を見るシグナルを足す。ADR 0025 として起案する。
- プログラムの宣言(U14): `data` の帰属と可視範囲を決める時に、型の**届く範囲**(使う相手の最も近い共通の親)を判断材料にする(思考実験 23 の第4節)。
- 図(U8): 型の届く範囲を図に載せるかを、Phase 3 で決める。

### 決定4 — 数値の物差しは取り込まない

Khononov の釣り合いの式(強度・距離・変動性を数に置いて比べる)は取り込まない。
変動性を言語が扱うには `change` の自由文を構造化して比べる事になり、自然言語の内容に踏み込む(ADR 0003)。
強度と距離を数にする事は、ADR 0006 が定量基準を捨てた理由(数値は分割の方向を誤誘導する)と同じ問題を持つ。

## 捨てたもの・理由

- **P1(一語のまま置く)**: 後の ADR が APoSD を根拠に挙げた時、どの知見を根拠にしたのかが読めない。既定値の対比も記録されないまま残る。
- **P3(既定値を戻す)**: ADR 0008 の理由(記述はそれ自体で読める)は、APoSD 自身の「未知の未知を減らす」とも整合する。
  既定値を戻す理由は、書き手の手間以外に見当たらなかった。
- **K1(取り込まない)**: 仕様は既に結合の釣り合いを名前を挙げずに使っている(侵入の禁止、`correlate` を同じ宣言に置く制約、鍵を対ごとにする決定)。
  物差しを名指ししないと、U14 のモデル結合のように**持っていない軸**に気付けない。
- **K3(検証として取り込む)**: 変動性は自由文にしか無く、機械は比べられない(決定4)。
  強度と距離だけを検査すると、変わらない物どうしの害の小さい不釣り合いまで止める事になり、ADR 0003 が退けた「通すためだけの修正」を誘発する。

## 将来の変更想定

- U14 の起案で思考実験 23 の K-b(型の届く範囲の警告)を採るなら、それは結合バランスの一部を検証へ持ち込む事になる。
  その時は決定3 の「言語の検証にはしない」を、警告に限って改訂する。
- 業務の区分(中核・支援・汎用)の語彙を intent に足すかどうかは、変動性を見積もる手掛かりとして検討の余地がある。
  ADR 0003 が必須項目を増やさなかった理由(項目を増やすほど質が下がる)があるため、足すなら任意項目である。今は足さない。
- APoSD の「汎用と専用」の軸は ADR 0003・0006 の将来の変更想定に残ったままである。本 ADR は扱わない。
