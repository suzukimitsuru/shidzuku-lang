# 0029: 最小の動作環境 — 意味の核を一つにして、ESP32 に載せる

- 区別: ADR 0012 は採用済みであり、改訂しない。本 ADR は 0012 の上に、動作環境の器を足す決定として置く(決定2(ADR 0012 との関係))
- 用語: WASM(WebAssembly)、WAMR(WebAssembly Micro Runtime、組込み機器向けの WebAssembly 実行系)、OTA(Over-The-Air、回線越しのファームウェア更新)、PSRAM(Pseudo-Static RAM、外付けの擬似 SRAM)

## 背景(なぜ決める必要があるか)

suzukimitsuru の指示で、ESP32 を Shidzuku の最小の動作環境にできるかを思考実験 27 で検討した。
前提は「管理機能は使わず、通信プロトコルと状態の確認とプログラムのロードだけになる」という見込みである。

思考実験 27(ESP32 の最小動作環境)は、ADR 0012 の決定2(責務の分担)が動作環境に寄せた責務を ESP32 に一つずつ当て、次の事を見つけた。

- **三つでは足りない。** ask の期限・上限付きの待ち行列・`on failure` の再起動は、管理ではなく ask と flow の約束であり、外すと宣言が嘘になる。
- **外すのは管理だけではない。** durable・recoverable・`collator` は言語の意味だが、最小の機器には持てない。弱めて実装すると、同じ語が動作環境によって違う物を指す。
- **障害境界がプロセスから離れる。** ESP32 にはプロセスが無く、ADR 0012 の決定5(接合の方式)の「障害境界=プロセス」がそのまま成り立たない。
- **Rust の出力だけで載る。** ADR 0012「将来の変更想定」は、組込みの帯の縮小版を「C をトランスパイル先に足す判断と同時に来る」としていたが、C は要らなかった。

これらは、ADR 0012 の決定1(動作環境の言語)の「動作環境は Rust の1実装」を ESP32 でどう保つかという一つの問いに集まる。
思考実験 27 は第8節(論点)に論点1〜6 を残し、suzukimitsuru が同日に全てを決めた。論点4(状態の確認)は判断の前に調べる事を求められ、思考実験 27 の第10節(状態の確認の調べ)で調べた。

## 決定

### 決定1 — 意味の核を標準ライブラリに依らない1つのクレートにし、PC と ESP32 が共に使う

- 動作環境を**意味の核**と**器**に分ける。意味の核は1つ、器は PC と ESP32 の2つである。
- 意味の核は標準ライブラリに依らない(`no_std`)Rust のクレートとし、次を置く。
  - ask の期限の判定
  - 待ち行列と `pressure`(`block`・`latest`・`drop`)の適用
  - コンポーネント記述子の照合と、能力の判定(決定3(能力と配置の設定))
  - `on failure` の規則の適用
- 器が持つのは、意味の核に差し込む物だけである。

| 差し込み口 | PC の器                            | ESP32 の器                                              |
| ---------- | ---------------------------------- | ------------------------------------------------------- |
| 通信       | Rust の Zenoh                      | zenoh-pico(C)を Rust から呼ぶ                           |
| 時計       | OS の単調時計                      | ESP-IDF の高分解能時計                                  |
| ロード     | プロセスの起動(並置)と Rust の同居 | 一体の書き込み、後に WASM でのロード(決定4(ロードの段)) |
| 永続化     | durable・recoverable を持つ        | 持たない(決定3(能力と配置の設定))                       |

- 意味の核は、PC の動作環境を作り始める時から `no_std` で作る。後から切り出すと、PC の都合が核に染み込んだ後になる。

### 決定2 — ADR 0012 は改訂しない。本 ADR は 0012 の上に器を足す

- ADR 0012 の決定1(動作環境の言語)の「動作環境は Rust の1実装」は、本 ADR の下では**意味の核が1つである事**として保たれる。
  0012 が捨てた「言語ごとに実行系を生成する案」の危険——意味を二箇所に置く事——は、器が増えても起こらない。器は意味を持たないからである。
- ADR 0012 の決定5(接合の方式。並置を基本とし、Rust に限り同居を許す)は変わらない。ESP32 の一体の書き込みは、Rust の同居の一つの形である。
- ADR 0012「将来の変更想定」の「組込みの帯の縮小版は、C をトランスパイル先に足す判断と同時に来る」は、思考実験 27 で前提が外れた。
  ESP32 には Rust の出力だけで載る。C を足すかは、ADR 0012 の決定7(3言語目以降の順序)のまま、別に判断する。
- 0012 の本文は履歴として残し、この読み方は本 ADR に置く。

### 決定3 — 動作環境は能力を宣言し、配置の設定の時に拒む

- 動作環境は、持つ意味の一覧(**能力**)を宣言する。能力は言語の宣言ではなく、動作環境の側の事実である(ADR 0015)。
- 最小の動作環境の能力は次の通りとする。

| 持つ                                                                                        | 持たない                                                          |
| ------------------------------------------------------------------------------------------- | ----------------------------------------------------------------- |
| Zenoh の通信、ask の期限、上限付きの待ち行列と `pressure`、transient、`on failure` の再起動 | durable と再送、idempotent の重複検出、recoverable の復元元の再生 |
| コンポーネント記述子の照合、状態の確認、ロードとその認証(決定6(ロードの認証))               | `collator`、版の交渉、ログ規約の出力、Raft・複製                  |

- **持たない意味は弱めずに拒む。** 拒む時期は**配置の設定の時**とする。どのコンポーネントをどの動作環境に載せるかを決めた時点で、
  記述子(配達保証・`state`・`collator`・記憶の見積もり)を能力と照らし、合わなければ配置の設定そのものを受け付けない。
  機器にイメージを送ってから分かるより、驚きが小さい。
- 照らすのに要る宣言は、コンポーネント記述子に載っている事を前提とする。`collator` は ADR 0012 の決定9(互換性の単位)の記述子の列挙に無いため、記述子の形を決めるコンポーネントのバージョンと移行(U16)で加える。
- 配置の設定の形式は最小の分散動作環境(Phase 2)で定める(第1章 1.6(動作環境は言語の記述対象外))。本決定は、その形式が能力との照合を持つ事を求める。

### 決定4 — ロードは段を踏む。一体の書き込みと1機器1コンポーネントで始め、複数を載せる時に WASM でのロードを足す

- **第1段は一体の書き込み**とする。動作環境と Rust のコンポーネントを1つのイメージに焼き、ESP-IDF の OTA(区画2面と巻き戻し)で差し替える。
- 一体の書き込みでは障害境界が機器になるため、**1機器に1コンポーネント**とする。コンポーネント=機器=障害境界=配置単位となり、四位一体(第0章 0.4(コンポーネント — 四位一体))が保たれる。
  この規則も配置の設定の時に確かめる(決定3(能力と配置の設定))。
- **1台に複数のコンポーネントを載せたくなった時に、WASM でのロード(WAMR)を足す。** 線形記憶の隔離により、障害境界はコンポーネントに残る。
  接合面の8つの呼び出し(H1〜H8)は wasm の import と export に写り、接合面の三つ目の実現手段になる。PSRAM の付く品種を前提とする。
- ネイティブの動的読込とスクリプトの処理系は採らない(「捨てたもの・理由」)。
- どの段でも、ESP32 に載るのは Rust の出力だけである。混在の適合試験は機器を跨いで行う。

### 決定5 — 状態の確認は Shidzuku のコードに出さない。組み込みのデータ型は提供しない

思考実験 27 の第10節(状態の確認の調べ)で、状態の確認の各項目を「誰が見て判断するか」で確かめた。いずれも動作環境・配置・監督・運用の判断のための物であり、
**コンポーネントのコードが知るべき事は、既に別の形で届いている**——相手の障害と期限切れは ask の失敗として、背圧は `pressure` の宣言として、再起動は `state` の宣言として。

- 状態の確認を読む呼び出しを接合面に足さず、組み込みのデータ型も置かない。
- 理由は四つである。同じ事実が二つの道でコードに届き判断の場所が記述から読めなくなる事、配置でコードの振る舞いが変わる事(ADR 0015)、
  接合面が広がる事(ADR 0012 の決定3(接合面))、全てのプログラムが変わり続ける動作環境の版と結び付く事(ADR 0024 の物差し)。
  ADR 0012 の決定2(責務の分担)が単調時計の読みを言語にも接合面にも出さなかった事と、同じ線引きである。
- 運用を監視する系を Shidzuku で書く場合は、状態の確認を `external`(外部システム)として境界の役割の層で読み、型はその系が自分のデータ宣言で書く(外部との境界(U12))。
- 状態の確認の中身は動作環境の文書に置き、符号化は正準形(ADR 0012 の決定4(正準形))とする。取りに行く形(問い合わせ)だけとし、周期的には送り出さない。

### 決定6 — ロードの認証を最小の動作環境に含める

- 「管理機能を使わない」は、誰でも載せられる事を意味しない。署名を確かめない機器は、回線の上の誰にでも乗っ取られ得る。
- **一体の書き込みでは ESP32 のセキュアブートが認証を担う。** 署名したイメージだけが起動する。
- **WASM でのロードでは動作環境の側で確かめる。** 焼き込んだ公開鍵で `.wasm` の署名を確かめ、合わなければ読み込まない。
- 鍵の配布・更新・失効は管理であり、最小の動作環境は持たない(「将来の変更想定」)。

### 決定7 — ESP32 の最小の動作環境は最小の分散動作環境(Phase 2)に置く

- 最小の分散動作環境(Phase 2)の成果物に、ESP32 の最小の動作環境を加える。
- 題材は思考実験 02 の上流(SensorIntake・Normalizer)とし、**PC 1台と ESP32 1台**で動かす。ノードを跨いだ `pressure` と障害の非伝播を実機で見る。
- 最小の言語実装(Phase 1)では ESP32 の器を作らない。ただし意味の核は、最小の言語実装(Phase 1)の動作環境の着手時から `no_std` で作る(決定1(意味の核))。

### 仕様書への反映

- 第1章 1.6 に、意味の核と器、能力と配置の設定での拒否、ESP32 の器を足す。
- 状態の確認の中身と能力の一覧は、動作環境の文書(最小の分散動作環境(Phase 2)で書く)に置き、仕様書には置かない。

## 捨てたもの・理由

- **ESP32 用に別の動作環境を書く案**: 期限・待ち行列・`on failure` の意味が二箇所に置かれる。ADR 0012 が言語ごとの実行系を捨てた理由がそのまま当たる。
- **ADR 0012 を改訂する案**: 0012 の決定の骨格(Rust・責務の分担・接合面の8つの呼び出し(H1〜H8)・2言語)は変わらない。変わるのは器の数であり、上に積む決定として分けた方が履歴が読める。
- **持たない意味を弱めて実装する案**: durable を「なるべく届ける」で済ませると、同じ語が動作環境によって違う物を指す。記述から振る舞いが読めなくなる。
- **ロードの時に拒む案**: 最後の段で分かるため、送ってから失敗する驚きが残る。配置の設定の時に拒めば、機器に触る前に分かる。
- **WASM でのロードから始める案**: 障害境界は良いが、記憶が重く PSRAM を要し、最初の一歩としては大きい。1機器1コンポーネントの一体の書き込みで意味は保てる。
- **ネイティブの動的読込**: 暴走が動作環境を巻き込む。ADR 0012 が捨てた「埋め込み」と同じ弱さである。
- **スクリプトの処理系**: トランスパイル先の言語に無い。
- **状態の確認を組み込みのデータ型にする案**: 決定5(状態の確認)の四つの理由による。
- **ロードの認証を持たない案**: 乗っ取りの入口を最小の機器に開ける。最小である事は、守らない理由にならない。
- **最小の言語実装(Phase 1)に置く案**: 最小の言語実装(Phase 1)の第1段の題材(思考実験 04(分散 KV ストア))は durable と recoverable を使い、ESP32 には載らない。最小の言語実装(Phase 1)の成果物を増やさない。

## 将来の変更想定

- **コンポーネントのバージョンと移行(U16)で記述子の形が決まる時**、`collator` と記憶の見積もりを記述子に加える(決定3(能力と配置の設定))。
- **配置の設定の形式**(最小の分散動作環境(Phase 2))が決まる時、能力との照合と1機器1コンポーネントの確かめ方をそこに書く。
- **WASM でのロードを足す時**、wasm の import と export に写した接合面の8つの呼び出し(H1〜H8)を、ADR 0012 の決定10(実装の順序と接合面の凍結)の凍結の対象に含めるかを判断する。凍結の後なら、写しの漏れは接合面の漏れである。
- **鍵の配布・更新・失効**が要る規模になったら、管理の機能として別に考える。最小の動作環境には足さない。
- **recoverable の復元元が別のノードにある場合**、再生を通信だけで取り寄せられれば、最小の動作環境でも recoverable を持てる(思考実験 27 の論点2(能力と拒否))。Raft の適用範囲(U6)と併せて判断する。
- **`時点` の供給**(思考実験 27 の第6節(型と時間))。起動直後の ESP32 は壁時計を知らない。外部の時刻の扱いとして外部との境界(U12)で決める。
- **運用を監視する系が思考実験に現れ**、`external` として読む形で書けない所が見つかったら、決定5(状態の確認)を見直す。
