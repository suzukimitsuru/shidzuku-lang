# 0028: データ宣言の語

- 日付: 2026-09-29
- 状態: 採用
- 関連課題: U9(データ型の記述、ADR 0009)。関連 U14(プログラムの宣言)

## 背景(なぜ決める必要があるか)

ADR 0009 は、公開面と `flow` の内容を流れるデータを**トップレベルの `data` 宣言**で定義すると決めた。
一つの語 `data` が、直積・直和・識別子型の三つの形を包んでいる。

``` plaintext
data 注文     { 品目: 品目ID, 数量: int64(0) 個 }   # 直積
data 照会結果 = 見つかった(値) | なし              # 直和
data 受注番号 (id)                                 # 識別子型
```

Phase 1 の残る作業(パーサ・トランスパイラ・shidzuku-lint)に入ると、この語は文法とトランスパイルの写像に固まる。その前に、語を見直す。

- **`data` は一般的すぎる。** Shidzuku のデータ宣言は「コンポーネントの外側を流れる語彙」に限られ、body の内部の型は対象外である(第6章 6.1)。
  この限定が語に表れない。Haskell の `data` は全ての代数的データ型に使う語であり、範囲がずっと広い。
- **形が頭で分からない。** 直積か直和か識別子かは、`{`・`=`・`(id)` のどれが続くかを見るまで読めない。
  省略の禁止(第0章 0.5、ADR 0008)は選択のある宣言を明示させるが、宣言の形そのものは頭の語で名乗っていなかった。
- 語彙はすでに `id`・`list` を持っている(第5章 5.3)。`unit` は単位の語として使っており、`measure` は ADR 0015 の経緯で外した。

## 検討した選択肢

参照している言語(第0章 0.9)と、型の宣言で広く使われる語から集めた。

| 候補                           | 先行例                                                              | 合う所                                                                 | 擦れる所                                                               |
| ------------------------------ | ------------------------------------------------------------------- | ---------------------------------------------------------------------- | ---------------------------------------------------------------------- |
| D-0 `data`(現状)               | Haskell                                                             | 一語で済む                                                             | 一般的すぎる。形が頭で分からない                                       |
| D-1 `type`                     | ML・F#・Elm・TypeScript・Ada(`type ... is record`)                  | 誰でも読める                                                           | `data` より一般的。body 内部の型まで指すように読める                   |
| D-2 `message`                  | Protocol Buffers・Erlang のメッセージ送信                           | 境界を越える事が語に出る                                               | 識別子型や欄に入る直和はメッセージではない。封筒(ヘッダ)を思わせる     |
| D-3 `shape`                    | Smithy(structure・union・string を全て shape と呼ぶ)                | 三つの形をまとめて呼べる。6.1 の「データ形状」と合う                   | 系譜に無い。`shape 受注番号 (id)` の据わりが悪い                       |
| D-4 `term`・`vocab`            | DDD のユビキタス言語(第6章は「語彙」と呼んでいる)                   | 位置付けがそのまま語になる                                             | `term` は型理論で値の式を指す。`vocab` は略語で ASCII の語彙の中で浮く |
| D-5 `value`                    | DDD の値オブジェクト、Ada の limited type との対比                  | 不変の値である事が語に出る                                             | 同一性を持たせる識別子型と噛み合わない                                 |
| D-6 `record` / `choice` / `id` | Pascal・Ada の `record`、ASN.1 の `CHOICE`、Rust の `struct`/`enum` | 汎用の語が消える。頭の語が形を名乗る。出力先の言語の宣言と一対一に写る | 語が一つから三つになる(`id` は既存なので増えるのは二つ)                |

一語で三つの形を包む限り、どの語を選んでも一般的になる(D-1〜D-5)。汎用の語を消せるのは、形ごとに分ける D-6 だけである。

## 決定

### 決定1 — データ宣言は形ごとに語を分ける

``` plaintext
record <名前> { <欄名>: <型>, ... }          # 直積
choice <名前> = <区分>(<型>) | <区分> | ...  # 直和
id     <名前>                                # 識別子型
list<<型>>                                   # 列(宣言ではなく型の形。変わらない)
```

- `data` はキーワードから外す。
- 「データ宣言」は三つの語の総称であり、キーワードではない。仕様の本文はこの総称を使う。
- ADR 0009 の決定(トップレベル・名前的型付け・「無い」は直和・body 内部は自由・intent を課さない)は、語が変わるだけで全て残る。

### 決定2 — 直和の語は `choice` とする

- ASN.1 の `CHOICE` と XML Schema の `choice` に倣う。第6章 6.1 の「直和(選択)」の訳語とも一致する。
- `union` は C の非判別共用体を、`enum` は区分が値を持たない列挙を思わせるため採らない。
  Shidzuku の直和は区分ごとに値を持てる判別共用体である(`見つかった(値) | なし`)。

### 決定3 — 識別子型は `id` を頭に置く

- `data 受注番号 (id)` は `id 受注番号` になる。`id` は既存の語であり、語彙は増えない。
- 識別子型は欄も区分も持たない。名前だけが同一性を与える(名前的型付け)ため、宣言は名前だけで足りる。

### 決定4 — 型の別名には `choice` を使わない

- 第6章 6.6 が未定事項に挙げる型の別名(`単価` を `int64(2) 円` から名前的に分ける形)は、区分を並べる直和ではない。
  `choice 単価 = int64(2) 円` とは書かない。別名の語は、別名を採る時に定める。

## 捨てたもの・理由

- **D-0 `data` を残す**: 一般的すぎ、形が頭で分からない。本 ADR の動機そのものである。
- **D-1 `type`**: `data` より更に一般的である。body 内部の型は自由(第2章 2.4)とする言語で、公開面の語彙だけを指す語にならない。
- **D-2 `message`**: 送る単位を指す語であり、`id 受注番号` のように欄に入るだけの型を包めない。
- **D-3 `shape`**: 一語のまま残す案の中では最も良いが、頭の語が形を名乗らない点は `data` と変わらない。
- **D-4 `term`・`vocab`**: 前者は型理論の用語と衝突し、後者は略語である。
- **D-5 `value`**: 値である事と同一性を持つ事は逆向きであり、識別子型を包むと語が嘘をつく。
- **直和を `union`・`enum`・`variant` とする**: 決定2 の理由による。`variant` は OCaml の用語だが、一つの区分を指す語としても使われ紛れる。

## 将来の変更想定

- 型の別名を採る時に、その語を定める(決定4)。`record` の欄を一つだけ持つ形で足りるなら、別名の語は持たない。
- 対応表(map)・集合(set)を公開面に持つ事になったら、`list` と同じく型の形として足す。宣言の語は増やさない。
- 区分名の可視範囲(`choice` の中に閉じるか)は U14 で定める。本 ADR は語だけを変え、可視範囲には触れない。
- 綴りの最終決定は Phase 1 のパーサ実装で行う(ADR 0014)。
