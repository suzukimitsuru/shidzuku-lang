# 0021: 数値型の体系 — 3つの型と、十進数の桁の宣言

- 日付: 2026-09-10
- 状態: 提案
- 関連課題: U23・U15(関連: U9・U22・U12・U13・U5・U24)
- 位置づけ: 破棄した ADR 0010(数値の型と単位)・ADR 0017(数値型の体系)の後継。ADR 0019 の決定2・決定7 の凍結を解く
- 入力: 思考実験 06・07・12・13・14、計画書 第6節 6.1 の8問題

## 背景(なぜ決める必要があるか)

数値型は 2026-09-03 に白紙へ戻った(計画書 第7節 7.1)。破棄されたのは**型を分けるという方針ではない**。
ADR 0017 の破棄の記録も思考実験 14 の総括も、分離そのものは Swift・Ada・Haskell という先行例に支持されているとしている。
壊れたのは**分けた型のあいだに橋を架けなかった事**の帰結である。

引き金は、`単位なし` の値とのスカラー倍を書こうとした時に現れた9つの組み合わせのうち4つで、**宣言のない丸め**が起きる事だった(計画書 6.1 の問題1)。
とりわけ `十進数(7.2) 円 × 実数 単位なし` は、**金額が静かに近似になる経路**である。

同時に、破棄前の設計は別の負債も抱えたままだった。いずれも ADR 0010 が桁を「整数部と小数部の2つ」で宣言した事から出ている。

| 負債                           | 現れ方                                                                 |
| ------------------------------ | ---------------------------------------------------------------------- |
| 上限の見積りが全ての値に要る   | `十進数(9.2)` の `9` を設計時に決める。外せば桁溢れ、広ければ無駄      |
| 桁を狭める受け渡しが直和になる | `収める(値, 十進数(i.f))` の結果を `桁溢れ` と分けて受ける             |
| 中間の桁が膨らむ               | `十進数(9.2) × 整数 単位なし` は 30 桁 = 16 バイト(計画書 6.1 の問題3) |
| 列の合算の桁が静的に決まらない | `合算(列)` は必ず `収める` で受ける(ADR 0010 が認めた唯一の穴)         |
| 2 のべきの境目でバイト数が倍   | ナノ秒の時刻(19 桁)は 8 バイトに収まる値なのに 16 バイト(思考実験 07)  |

本 ADR は、2つの決定でこの両方に答える。

1. **`十進数` の宣言を刻みだけにする**。小数点以下の桁数だけを書き、上限を型から外す(桁数倍した二進整数を、値の大きさに応じた可変長で持つ)。
2. **`整数` → `十進数` の昇格1本だけを暗黙にする**。他の向きは明示のままとする。

この2つは噛み合っている。上限を持たない `十進数` は、`整数` の値を必ず、丸めも桁溢れもなく受け取れる。
思考実験 13 が推し、思考実験 14 が C# の `decimal` に先行例を見つけた「整数 → 十進数 だけを暗黙にする非対称な橋」が、C# より強い保証で架かる。

ADR 0017 が置いた `実数`(IEEE 754 binary64)は**型としては引き継ぐが、「主に使う型」という位置づけは引き継がない**(決定2)。

## 検討した選択肢

型の数と暗黙変換の2軸は思考実験 14 が比較を済ませている。本 ADR が改めて検討したのは**桁の宣言**と**橋の架け方**である。

### 桁の宣言をどこまで型に残すか

| 案                                    | 先行例                   | 刻みは型から読めるか | 上限は型から読めるか | 記憶域       |
| ------------------------------------- | ------------------------ | -------------------- | -------------------- | ------------ |
| (a) 精度と位取りの両方(`十進数(9.2)`) | ADR 0010・SQL・Ada・PL/I | 読める               | 読める               | 静的に決まる |
| (b) **位取りだけ(`十進数(2)`)**       | 本 ADR                   | 読める               | 読めない             | 値で決まる   |
| (c) どちらも型に持たない              | Java `BigDecimal`        | 読めない             | 読めない             | 値で決まる   |
| (d) 器を1つ固定する                   | C# `decimal`(128 ビット) | 読めない             | 型が1つに固定        | 静的に決まる |

- (a) は上限の見積りを常に要求する。**上限は業務が決めている事が少なく**、書かれた `9` の並びは表現の都合であることが多い。
- (c) は刻みまで値ごとになる。`1.0` と `1.00` が別物になり、等価が表現に依存する(`BigDecimal.equals` の有名な罠)。除算の結果の桁も型から決まらない。
- (d) は宣言がゼロで軽いが、刻みが型から読めない。「1 円未満を切り捨てる」という設計判断が型に残らない。
- (b) は**刻みだけを残す**。刻みは業務が決めた事実であり、上限は入れ物の都合である——この非対称に合わせる。

### 型のあいだに橋を架けるか

| 案                                     | 先行例             | 明細行の書きやすさ | 危険な4組(計画書 6.1) |
| -------------------------------------- | ------------------ | ------------------ | --------------------- |
| (i) 架けない(常に明示)                 | Swift・Ada・現行   | 変換を毎回書く     | 起きない              |
| (ii) **整数 → 十進数 の1本だけ**       | C# の `decimal`    | 素直に書ける       | 起きない              |
| (iii) 塔にする(不正確さの伝染)         | Scheme・Julia      | 素直に書ける       | **起きる**            |
| (iv) `倍する(値, 整数)` の名前付き操作 | 思考実験 13 の推し | 語彙が1つ増える    | 起きない              |

(iii) は近似が厳密を飲み込む向きであり、破棄の原因そのものである。(iv) は安全だが、`×` と `倍する` の使い分けを書き手が覚える事になる。
(ii) は**値が一つも変わらない向き**だけを暗黙にする。可変長の `十進数` では、この向きに失敗が存在しない。

## 決定

### 1. 数値型は3つのまま置く

`整数`・`実数`・`十進数` を維持する(思考実験 14 の判定を採る)。3つは**型が答える問いが違う**。

| 型          | 器            | 刻み                | 上限              | 宣言する事       | 何をした値か         |
| ----------- | ------------- | ------------------- | ----------------- | ---------------- | -------------------- |
| `整数`      | 64 ビット固定 | 常に 1(単位が担う)  | 型が定める(19 桁) | 単位             | 数えた               |
| `実数`      | binary64 固定 | 値の大きさで変わる  | 型が定める        | 単位             | 測った・計算で作った |
| `十進数(s)` | **可変長**    | `10^-s`(型が定める) | **無い**          | 単位と小数部の桁 | 刻みを決めた         |

`整数` は ADR 0019 の決定2 のまま(符号付き 64 ビット・刻みは 1・単位は必須・`÷` を持たない・巻き戻らない)。凍結を解く。

### 2. `実数` は IEEE 754 binary64 とする — 型に序列は置かない

```plaintext
実数 メートル      # 測った長さ
実数 単位なし      # 測って得た比・確率・尤度
```

ADR 0017 の内容を引き継ぐ。要点だけを再掲する(本 ADR が改めて決定する)。

- **桁も丸め方も書かない**。範囲と有効桁は型が1つに定めており、丸めは全ての演算で起きる。それは `実数` という名前が告げている性質である。
- **四則の演算子 `+ - × ÷` を持つ**。`平方根(値)`・`累乗(底, 指数)` も桁と丸めの宣言を要らない。
- **IEEE 754 に厳密に従う**。binary64 のみ、丸めは最近接偶数に固定、FMA への融合・再結合・拡張精度での中間保持・近似逆数・代数的な書き換えを禁じる。
  超越関数は正しく丸めた結果を要求し、満たせない関数は語彙に入れない。列の合算は先頭から順に行い、実装の並べ替えを禁じる。
  これにより、分散した複数ノードで結果が一致する(Raft の前提・ADR 0001)。
- **NaN・±∞・-0 を値として持たない**。生む演算は失敗とし(U13)、検査は「値が名前を得る所」で例外フラグを見る。比較は全順序、等価は素直である。

**「主に使う型」は置かない。** ADR 0017 は `実数` を「主に使う型」と位置づけたが、本 ADR はこれを引き継がない。

- **型は書き手が値ごとに指定する物である。** 型名は必ず書き(省略の禁止・ADR 0008)、省略時に補われる型は無い。
  補われる型が無い以上、言語が序列を置いても書かれる記述は1文字も変わらない。「よく使われる」は書き手の統計であって、言語の決定ではない。
- **`実数` の宣言が軽いのは、優先されるからではない。** 測った値には桁と丸めの宣言が意味を持たない——だから欄が無い。
  同じ理由で、刻みを決めた値には小数部の桁が要る。**軽さは値の性質の反映であって、順位ではない。**
- 選び方は指針(決定11)に置く。指針は「**その値を、数えたのか・刻みを決めたのか・測ったのか**」という問いであり、順位ではない。

### 3. `十進数(<小数部の桁>)` — 刻みだけを宣言する

```plaintext
十進数(<小数部の桁数>) <単位 | 単位なし>

十進数(2) 円         # 刻み 0.01 円。上限は無い
十進数(4) 単位なし   # 税率・利率(刻み 0.0001)
十進数(0) 単位なし   # 刻み 1 で上限が無い数 = 任意精度の整数
```

- **小数部の桁は必ず書く**。刻みは業務が決めた設計判断であり、型から読めなければならない。
- **整数部の欄は無くなる**。省略しているのではなく、**欄そのものを持たない**(ADR 0017 が `実数` について書いた「桁という欄を持たない完結した型」と同じ形)。
  書かれなかった欄を既定で補う事はしていないため、省略の禁止(ADR 0008)には当たらない。E0008-1 の対象は「型名・単位の欄・小数部の桁」である。
- **静的指数(`指数 e`)は廃止する**。指数は「幅の有限な窓の**位置**」を動かす仕組みであり、上端の無い窓に位置の概念はない。下端は小数部の桁がそのまま決める。
  桁の窓が原点から極端に離れた値(物理定数)は `実数` の領分である。

#### `十進数(i.f)` は廃止する — 2つの形を併存させない

置き換えであって追加ではない。ADR 0010 の形は残さず、`十進数` は可変長の1つの形だけを持つ。
併存させれば、選ぶ判断が全ての値に増え、公開面で形が食い違う組み合わせが生まれる。固定長が要る場所には別の受け皿がある(決定9)。

| ADR 0010 の記述                          | 本 ADR での書き方                      |
| ---------------------------------------- | -------------------------------------- |
| `十進数(7.2) 円`                         | `十進数(2) 円`                         |
| `十進数(9.2) 円`                         | `十進数(2) 円`(整数部の違いは消える)   |
| `十進数(1.5 指数 -31) キログラム`        | 廃止。`実数 キログラム` を使う         |
| `収める(値, 十進数(9.2))`                | 廃止。そのまま渡せる                   |
| `十進数(9.2) 円` と `桁溢れ` の直和      | 廃止。整数部の桁溢れが存在しない       |
| `丸める(値, 十進数(9.2), 丸め 四捨五入)` | `丸める(値, 十進数(2), 丸め 四捨五入)` |
| `収める(合算(列), 十進数(9.2))`          | `合算(列)`                             |

廃止で**失うもの**と、その受け皿。

| 失うもの                         | 受け皿                                                       |
| -------------------------------- | ------------------------------------------------------------ |
| 記憶域が実行前に決まる           | `整数 <細かい単位>`(決定9)。`十進数` では失われる            |
| 値域が型から読める               | 当面は無い。`範囲` の宣言は「将来の変更想定」に送る          |
| 整数部の桁溢れのコンパイル時検出 | 検出する対象そのものが無くなる(`整数` の桁溢れは残る)        |
| 静的指数(桁の窓の位置)           | `実数`。窓の位置が極端な値は測った値であり、実数の領分である |

書き換えが要るのは、第6章 6.3(`十進数` の宣言・`収める`・静的指数)、第3章 3.3(E0010-3・E0010-4・E0019-3)、
および ADR 0019 決定2 の整数の換算規則が参照する E0010-3 である。ADR と思考実験の本文は履歴として旧表記のまま残す(ADR 0016 決定4)。

### 4. 内部表現は「小数桁倍した可変長の符号付き2進整数」

ADR 0010 の表現をそのまま引き継ぐ。変わるのは**幅を型ではなく値が決める**事だけである。

- 値は整数 `m` と型が定める小数部桁 `s` の組で保持し、実数値は `m × 10^-s` である。演算は全て整数演算になる。
- 実装は小さい値を機械語に収め、収まらなくなった時点で多倍長へ移してよい。

  | 値の総桁 | `m` のビット | 典型的な格納           |
  | -------- | ------------ | ---------------------- |
  | 1〜18    | 63 まで      | 1 ワードに収める       |
  | 19〜38   | 127 まで     | 2 ワード、または多倍長 |
  | 39 以上  | —            | 多倍長                 |

- **表現の選び方は実装の自由、値の意味は表現に依存しない**。ADR 0010 の「桁の意味はバイト数に依存しない」を、桁の宣言が無い側へ延長したものである。
- **同じ値は必ず同じ正準形を持つ**。`s` は型が固定するため `m` は一意であり、格納場所(ワードか多倍長か)は等価・順序・ハッシュに影響しない。
  正準形が一意である事は、ハッシュ可能である条件(ADR 0013 決定3)であり、分散でのダイジェスト一致の前提でもある。
- **記憶域を確保できない事は失敗**であり、黙って値を壊さない(U13)。

### 5. 演算 — 誤差の出る場所は3つのまま

| 演算                                                                      | 結果の小数部 | 誤差                          |
| ------------------------------------------------------------------------- | ------------ | ----------------------------- |
| `a + b` / `a - b`                                                         | 細かい方     | なし                          |
| `a × b`                                                                   | 両辺の和     | なし                          |
| `分ける(a, b)`                                                            | `a` と同じ   | なし                          |
| `合算(列)`                                                                | 要素と同じ   | なし                          |
| `割る(a, b, 十進数(s), 丸め <方式>)`                                      | 宣言した桁   | 丸め1回                       |
| `丸める(a, 十進数(s), 丸め <方式>)`                                       | 宣言した桁   | 丸め1回                       |
| `換算(a, <単位>, …)`                                                      | 宣言した桁   | 丸め1回(細かい単位へは無損失) |
| `累乗(a, n, 十進数(s), 丸め <方式>)`・`平方根(a, 十進数(s), 丸め <方式>)` | 宣言した桁   | 丸め1回                       |

- **誤差が出るのは、除算・粗い単位への換算・小数部を狭める受け渡しの3つだけ**である(ADR 0010 と同じ)。
  消えたのは4つ目の心配——整数部の桁溢れ——であり、誤差の出る場所は一つも増えていない。
- **`収める` は要らなくなる**。整数部の桁溢れが存在しないため、`合算(列)` も乗算の連鎖も、そのまま `十進数` で受けられる。
  ADR 0010 が「桁が静的に決まらない唯一の演算」として直和を義務づけた穴は、これで閉じる。
- **10 のべきの換算は、細かい単位へは常に無損失**である(整数部が伸びるだけ)。粗い単位へは、小数部の桁が足りれば無損失、足りなければ丸めの宣言を要求する(E0010-3)。
- 拡張は自動、縮小は必ず書く(ADR 0010 の規則をそのまま適用)。`十進数(2)` の値を `十進数(4)` の欄へ渡すのは無損失で自動、逆は `丸める` を書く。

### 6. 橋は1本だけ架ける — `整数` → `十進数` は暗黙の昇格

```plaintext
data 明細 { 単価: 十進数(2) 円, 数量: 整数 単位なし }

単価 × 数量        # 書ける。結果は 十進数(2) 円
```

- **`整数` は `十進数` の式の中で `十進数` へ昇格する**。値は一つも変わらず、丸めも桁溢れも起こり得ない。
  `整数` の刻みは 1、`十進数(s)` の刻みは `10^-s`(1 以下)であり、上限が無いのだから、**入らない値が存在しない**。
- 昇格した値の小数部は、式の相手の桁に合わせる。`十進数(2) × 整数` の結果は `十進数(2)`(乗算の小数部は和であり、`整数` 側は 0 桁)。
- **可換である**。「左の型を保つ」ではなく「`整数` が `十進数` へ昇格する」と定めるため、`整数 × 十進数` と `十進数 × 整数` は同じ結果になる。
- **単位の規則は変わらない**(ADR 0010 のまま)。`円 × 単位なし = 円`、異なる量の加減算は E0010-1。昇格は型の話であり、単位には触らない。
- **スカラー倍という特別規則は要らない**。計画書 6.1 が書き下ろそうとした規則は、この昇格1本に置き換わる。

**省略の禁止(ADR 0008)との関係。** 0008 が禁じたのは「**選択肢のある欄を、書き手が書かなかったときに言語が選ぶ事**」である。
この昇格には選択肢が無い。結果は一意で、丸めも失敗も起きず、値も単位も変わらない。**判断の無い所に宣言を求める事は、ADR 0017 が「作文」と呼んだものと同じ**である。
ADR 0019 の決定7 も、この向きだけは「原理的に丸めが起きない」と既に認めていた。本 ADR は、その観察を橋にする。

### 7. `実数` との橋は架けない

| 変換          | 書き方                                   | 丸めの宣言 | 失敗          |
| ------------- | ---------------------------------------- | ---------- | ------------- |
| 整数 → 十進数 | **不要(暗黙の昇格)**                     | 不要       | **無い**      |
| 整数 → 実数   | `近似する(値)`                           | 不要       | なし(W0019-1) |
| 十進数 → 実数 | `近似する(値)`                           | 不要       | 桁溢れ時のみ  |
| 実数 → 整数   | `丸める(値, 整数, 丸め <方式>)`          | 必須       | 範囲外        |
| 実数 → 十進数 | `厳密にする(値, 十進数(s), 丸め <方式>)` | 必須       | **無い**      |
| 十進数 → 整数 | `丸める(値, 整数, 丸め <方式>)`          | 必須       | 範囲外        |

- **`整数` → `実数` にも橋を架けない**。2^53 を超える整数は丸まり、その桁溢れは静的に見えない(思考実験 14 の論点2)。Swift・Ada と同じ判断を採る。C# はここも暗黙にしているが、追わない。
- **近似は厳密を飲み込まない**。`実数` が混ざった式は、`十進数` 側でも `整数` 側でもコンパイル時エラー(E0019-3)になる。数値の塔の「伝染」は採らない。
- `実数` → `十進数` の変換に整数部の桁溢れが無くなった(可変長のため)。丸めの宣言だけが要る。

### 8. 量と単位は ADR 0010 から引き継ぐ

破棄した ADR 0010 のうち、**量と単位の体系はそのまま生かす**(思考実験 14 の論点7。F# の Units of Measure が設計を裏付けている)。

- `量`・`単位` の宣言、基準単位に対する比は既約の有理数、換算比を持たない量(通貨・温度)、組立の量は宣言されたものだけ。
- 換算誤差の規則(連鎖換算をしない・掛けてから割る・結果の桁を宣言させる・比較は換算しない)。
- 丸めの語彙6種(切り捨て・切り上げ・床・天井・四捨五入・銀行丸め)と、**既定を持たない**規則。
- 検査 E0010-1・E0010-2・E0010-5、警告 W0010-1・W0010-2。
- 単位は3つの型すべてに載る。型情報のみであり、実行時コストはゼロである。

### 9. 固定長が要る所は `整数 <細かい単位>` で書く

`十進数` は記憶域の上界を型に持たない。動的確保が許されない文脈(割り込み・WCET の要る制御・`no_std` の組込み)では使えない。
**その場合は `整数` を細かい単位で使う。**

```plaintext
整数 銭        # 金額を 1/100 円の整数で持つ。64 ビット固定、上限は型が定める
整数 ナノ秒    # ADR 0019 決定2 が既に示している形
```

刻みを単位が担い、器は 64 ビットに固定される。**言語は固定長の道を閉じていない**——閉じたのは「`十進数` の中に固定長の形を残す」事だけである。

### 10. 検証 — 1つ廃止、2つ改訂、新設は無し

検証番号は ADR 0016 の `E<出自>-<連番>` に従う。**一度与えた番号は動かさない**(0016 決定3)ため、引き継ぐ検査は出自の番号のまま残す。

| 識別子  | 検査                                                  | 本 ADR での扱い                                      |
| ------- | ----------------------------------------------------- | ---------------------------------------------------- |
| E0010-1 | 異なる量の加減算・比較                                | 引き継ぐ(変更なし)                                   |
| E0010-2 | 換算比を持たない量の、単位を跨ぐ演算・換算            | 引き継ぐ(変更なし)                                   |
| E0010-3 | 丸めが避けられない演算に丸めの宣言がない              | **改訂**。対象は除算・粗い単位への換算・小数部の縮小 |
| E0010-4 | 名前を得る所で整数部の桁が宣言を超える                | **廃止(欠番)**。整数部の桁が無くなった               |
| E0010-5 | 宣言のない組立の量の出現                              | 引き継ぐ(変更なし)                                   |
| E0019-3 | 数値型が明示の変換なしに混ざる                        | **改訂**。`整数` → `十進数` の昇格を除く             |
| E0019-4 | 列の添字・長さ・繰り返し回数が `整数 単位なし` でない | 凍結を解く(変更なし)                                 |
| W0010-1 | 換算先の分解能が換算元より粗い                        | 引き継ぐ                                             |
| W0010-2 | 合算する状態の刻みが、足し込む値の刻みより粗い        | 引き継ぐ                                             |
| W0017-1 | 通貨の量を持つ値に `実数` を使っている                | 引き継ぐ                                             |
| W0017-2 | `実数` と `十進数` のあいだで往復変換している         | 引き継ぐ                                             |
| W0019-1 | `整数` → `実数` の変換で 2^53 を超え得る              | 引き継ぐ                                             |

**本 ADR は検査を1つも増やさない。** 設計を軽くした結果として、検査は1つ減る。

### 11. 使い分けの指針

判断の基準は「**その値を、数えたのか・刻みを決めたのか・測ったのか**」である(ADR 0019 決定7 の表を引き継ぐ)。

| 数えた(→ `整数`)             | 刻みを決めた(→ `十進数`) | 測った・計算で作った(→ `実数`) |
| ---------------------------- | ------------------------ | ------------------------------ |
| 個数・注文数・在庫数・回数   | 金額・単価・手数料       | 距離・質量・温度・電圧         |
| 列の添字・長さ・繰り返し回数 | 税率・利率・割引率       | 座標・角度・速度               |
| 版・連番・世代番号           | 按分の結果・帳簿の値     | 平均・分散・標準偏差           |
| 時間の量(ナノ秒・ミリ秒)     | 会計・請求の値           | 確率・尤度・スコア             |

**`単位なし` の係数は、掛ける相手に合わせる。** 金額に掛ける税率は `十進数(4) 単位なし`、測った値に掛ける係数は `実数 単位なし` である。
取り違えても静かには壊れない——`十進数 × 実数` はコンパイル時エラー(E0019-3)になる。

## この形式の名前 — 既存の体系での呼び名

新しい形式ではない。ADR 0010 の同名の節を、可変長の形に合わせて調べ直した。

| 観点                         | 呼称                                                                                                                   | Shidzuku との違い                         |
| ---------------------------- | ---------------------------------------------------------------------------------------------------------------------- | ----------------------------------------- |
| 分類                         | **厳密数値型**(exact numeric)。MySQL は「Fixed-Point Types (Exact Value)」と呼ぶ                                       | 厳密側だけを持つ                          |
| 一般名                       | **十進固定小数点数**(decimal fixed-point number)。精度に上限を置かない版は **arbitrary-precision fixed-point decimal** | 同じ                                      |
| 表現                         | **位取り整数**(scaled integer)。格納整数(stored integer)× 位取り係数(scaling factor `10^-s`)、刻みは分解能(resolution) | 同じ                                      |
| 位取りが**値ごと**(動的)     | Java `BigDecimal`(unscaled value + scale)、Smalltalk `ScaledDecimal`(リテラル `1.23s2`)、Go `shopspring/decimal`       | Shidzuku は位取りを**型**に固定する       |
| **位取りが型・精度は無制限** | **Haskell `Data.Fixed`**(`newtype Fixed a = MkFixed Integer`、`type Centi = Fixed E2`)                                 | **同型**。単位と量が載る点だけが違う      |
| 位取りが型・精度は有界       | SQL `NUMERIC(p,s)`、Ada の十進固定小数点型、PL/I `FIXED DECIMAL(p,q)`、Rust の `fpdec`(位取りは型の定数)               | 精度の上限を持たない                      |
| 精度を書かない宣言           | PostgreSQL の `numeric`(整数部 131072 桁・小数部 16383 桁まで)                                                         | 実務上は同じ。Shidzuku は上限を規定しない |
| 数学                         | `(1/10^s)ℤ` — 整数と同型の格子(ADR 0010 の `ℤ[1/10]` の、位取りを固定した部分群)                                       | 表せる値の集合そのもの                    |
| 単位                         | units of measure(F# の `[<Measure>]`)                                                                                  | 同じ                                      |

まとめると、Shidzuku の `十進数(s)` は**単位付き・静的位取り・任意精度の十進固定小数点数**である。

- **完全な先行例は Haskell の `Data.Fixed`** である。位取りを型パラメータ(`E2` 等、`HasResolution` の実装)に持ち、中身は任意精度の整数1つ——本 ADR の `十進数(2)` と構造が一致する。
  `type Centi = Fixed E2` は `十進数(2)` そのものであり、`Deci`・`Milli`・`Micro`・`Nano`・`Pico` という別名は、Shidzuku で言えば刻みに名前を付けたものにあたる。
- **`BigDecimal`・`ScaledDecimal` との違いは、位取りが値ごとか型かの一点**である。この一点が、等価の素直さ(`1.0` と `1.00` が同じ値になる)と、除算の結果の桁が型から決まる事を生む。
- 名前の選び方: 型の名前は `十進数` のままとする。`ScaledDecimal`(位取り十進数)は表現の呼び名であり、書き手が知るべきは「十進で、刻みを宣言する数」という意味の方である。

### 3. 明細行の金額(思考実験 12 の論点1・思考実験 13)

```plaintext
# 破棄前
data 明細 { 単価: 十進数(7.2) 円, 数量: 整数 単位なし }
金額 = 収める(単価 × 収める(数量, 十進数(5.0)), 十進数(9.2))   # 変換2つと直和2つ

# 本 ADR
data 明細 { 単価: 十進数(2) 円, 数量: 整数 単位なし }
金額 = 単価 × 数量                                              # そのまま書ける
合計 = 合算(明細.金額)                                          # 収める も要らない
```

`収める` が消え、直和の分岐も消える。**思考実験 12 が「全ての明細行に現れる」と書いた重さが、丸ごと無くなる。**

### 4. 記憶域は実際の値に合うか

| 値                            | 破棄前の宣言と割当         | 本 ADR の宣言と割当                      |
| ----------------------------- | -------------------------- | ---------------------------------------- |
| 金額 1234.56 円               | `十進数(7.2)` = 8 バイト   | `十進数(2)`、`m`=123456 → 1 ワード       |
| 明細100行の合計(最大 10 億円) | `収める` が必要            | `十進数(2)`、`m` は 11 桁 → 1 ワード     |
| 単価 × 数量(1234.56 × 100)    | 中間 30 桁 = 16 バイト     | `m`=12345600 → 1 ワード                  |
| ナノ秒の時刻(19 桁)           | `十進数(19.0)` = 16 バイト | `十進数(0)`、`m` は 61 ビット → 1 ワード |
| 円周率を 30 桁で持つ          | `十進数(1.30)` = 16 バイト | `十進数(30)`、`m` は 31 桁 → 多倍長      |

**型が確保するのは最悪値、可変長が確保するのは実際の値である。** 2 のべきの境目(19・39・77 桁)の代償も消える。

## 結果(利点と欠点)

### 利点

- **宣言が減る**。`十進数` に書くのは刻みと単位の2つだけになり、上限の見積りという設計判断が消える。
- **`収める` と直和の分岐が消える**。桁溢れは `十進数` に存在しない(`整数` には残る)。
- **明細行が素直に書ける**。破棄の直接の原因(U23)が、特別規則ではなく型の昇格1本で解ける。
- **危険な4組が全てコンパイル時エラーになる**。近似が厳密を飲み込む経路は一つも無い。
- **誤差の出る場所は3つのまま**。除算・粗い単位への換算・小数部の縮小。設計を軽くしても誤差の管理は緩んでいない。
- **記憶域が実際の値に合う**。中間桁の膨張も 2 のべきの境目も消える。
- **検査が1つ減る**。増えない。
- 厳密さ・結合則・正準形の一意性・分散での再現性は、いずれも失われない(演算は整数演算のまま)。

### 欠点

- **記憶域の上界が実行時まで決まらない**。ADR 0010 が有理数を棄却した理由の後半をそのまま受け入れる事になる。
  分母が `10^s` で固定されるため分子は爆発しない(加減算で最大1桁、乗算で両辺の和)が、乗算の連鎖と反復は伸び続ける。
  **WCET が要る所・`no_std` の組込みでは `整数 <細かい単位>` を使う**——型では防げない指針である。
- **上限が型から読めない**。「金額は 9999999.99 円まで」という業務上の上限が実在する系では、その知識が型から抜ける。
  暴走した反復や外部から来た極端な値が桁を伸ばしても、コンパイル時には落ちない。**外部境界での桁の制限は U12 の仕事**として残る。
- **`実数` の誤用は警告でしか止まらない**。`0.1 + 0.2 ≠ 0.3` はその型を選んだ限り起きる。金額に `実数` を使う誤りを止めるのは W0017-1(警告)だけであり、禁止ではない。
- **暗黙の変換が1つできる**。「数値型は暗黙に混ざらない」は例外を持つ規則になった。例外は1つ・向きも1つで、値が変わらない場合に限るが、規則の単純さは失われる。
- **序数(U24)に掛け算が書けるようになる**(計画書 6.1 の問題8)。`版 整数 単位なし × 十進数` が通る。U24 が解くまで残る。
- **静的指数を失う**。窓の位置が極端な値(物理定数)を `十進数` で持つと桁がそのまま伸びる。`実数` を使う事が前提になる。
- 多倍長整数の実装がトランスパイル先に要る(TypeScript の `BigInt`、Rust の多倍長。ADR 0012 の要件は変わらない)。

### 総括 — 何と引き換えに何を得るか

**型に残すのは「刻み」だけにし、「上限」は器に任せる。**

ADR 0010 は「実行時の驚きを、記述の重さとして前払いする」だった。ADR 0017 はその前払いを厳密さが要る値に絞った。
本 ADR はさらに、**前払いする内容を刻みだけに絞る**。刻みは業務が決めた事実であり、上限は入れ物の都合だからである。

| 問い                   | `整数`        | `実数`     | `十進数(s)`    |
| ---------------------- | ------------- | ---------- | -------------- |
| どれだけ細かいか(刻み) | 型が答える(1) | 答えない   | 型が答える     |
| どれだけ大きいか(上限) | 型が答える    | 型が答える | **答えない**   |
| 値は厳密か             | 厳密          | 近似       | 厳密           |
| 記憶域は静的に決まるか | 決まる        | 決まる     | **決まらない** |

3つの型は、この表の行の組み合わせとして選べる。**どれを選んでも、型の名前が実際の性質を告げている**——ADR 0017 の総括はそのまま生きている。

## 捨てたもの・理由

- **桁を2つ(整数部・小数部)宣言する案(ADR 0010 の形)**: 上限の見積りを全ての値に要求する。上限は業務が決めている事が少なく、外せば桁溢れ、広く取れば記憶域の無駄になる。
  桁溢れの直和・中間桁の膨張・合算の上界不定・2 のべきの境目という4つの負債が、全てここから出ていた。
- **小数部も型から外す案(Java `BigDecimal`)**: 刻みが値ごとになり、`1.0` と `1.00` が別物になる(等価が表現に依存する)。除算の結果の桁も型から決まらず、丸めの宣言の置き場所が消える。
- **器を1つ固定する案(C# `decimal` の 128 ビット)**: 宣言はゼロになるが、刻みが型から読めない。「1 円未満を切り捨てる」という設計判断が型に残らない事は、この言語では失うものが大きい。
- **数値の塔にする案(Scheme の伝染規則・Julia の `promote_rule`)**: 近似が厳密を飲み込む向きを暗黙にする。破棄の原因(`十進数 円 × 実数 単位なし`)がそのまま復活する。
- **「主に使う型」を決める案(ADR 0017 の位置づけ)**: 型は書き手が値ごとに指定する物であり、省略時に補われる型は無い。
  言語が序列を置いても書かれる記述は1文字も変わらず、**「主に使う」が言語の決定として成立しない**。
  ADR 0017 はこれを「宣言がいちばん軽い型」の意味で使っていたが、軽さは値の性質(測った値に桁と丸めの宣言が意味を持たない事)の反映であって順位ではない。
  選び方は指針(決定11)で足り、指針は問いであって順位ではない。
- **橋を1本も架けない案(現行・Swift・Ada)**: 明細行のたびに `収める(数量, …)` が現れる。値が一つも変わらない変換に宣言を求めるのは、ADR 0017 が「作文」と呼んだものと同じである。
- **`倍する(値, 整数)` の名前付き操作(思考実験 13 の推し)**: 安全だが、`×` と `倍する` の使い分けを覚える事になる。可変長により昇格が原理的に無損失になったため、名前で警告する理由が無くなった。
- **`整数` → `実数` も暗黙にする案(C# と同じにする)**: 2^53 を超える整数が黙って丸まる。桁溢れが静的に見えない変換は暗黙にしない。
- **`十進数` に固定長の形も残す案(2つの形を持つ)**: 選ぶ判断が増え、公開面で形が食い違う組み合わせが生まれる。固定長が要る場所は `整数 <細かい単位>` で書ける(決定9)ため、`十進数` の中に2つ目の形を置く必要がない。
- **静的指数を残す案**: 上端の無い窓に位置の概念はない。下端は小数部の桁が決める。窓の位置が極端な値は `実数` の領分である。
- **可変長を公開面・data に書けなくする案(境界は固定桁とする)**: 記憶域を伸ばせる値が障害境界を越える事を防げるが、`十進数` が可変長のみになった以上、**金額を公開面に書けなくなる**。
  外部から来る値の桁の制限は、型ではなく境界の検証(U12)の仕事とする。
- **言語が桁の上限(1 値あたり N バイト)を定める案**: 同じ記述が環境によって成否を変える。ADR 0010 の「桁の意味はバイト数に依存しない」に反する。確保できない事は失敗(U13)として扱う。

## 将来の変更想定

- **値域の宣言**(`十進数(2) 円 範囲 0..999999999`)。業務上の上限が実在する場合に、桁ではなく業務の言葉で書く案。
  ADR 0010 の「将来の変更想定」と同じ提案だが、可変長では**上限の宣言が任意になる**ため、より自然に載る。Phase 1 で必要が確認されたら検討する。
- **外部境界での桁の制限**(U12)。外部形式(JSON の数値・SQL の `DECIMAL`)から `十進数` を作る所で、桁の上限をどう宣言させるか。
- **失敗の体系との統合**(U13)。0 除算・`整数` の巻き戻り・`実数` の特殊値・記憶域の確保失敗を同じ語彙に載せる。
- **序数と基数**(U24)。昇格により掛け算の書ける範囲が広がった分、U24 の優先度は上がる。
- **binary32 の追加**(論点4)・**区間演算**(論点5)。機械学習・GPU・数値解析を対象に含める判断と一緒に決める。
- **三角関数・対数**。正しい丸めを満たす実装を用意できた関数から `実数` に入れる。
- 採用時の反映先: 第6章 6.3 の「再検討中」の注記を外し、`十進数(i.f)` を `十進数(s)` に書き換え、`収める` と静的指数の記述を落とす。
  第6章 6.1 の基本型の表から `実数` の「主に使う数値型」を、6.3 から「主に使うのは `実数`」の記述を落とす(決定2)。
  第3章 3.3 の E0010-3・E0019-3 を改訂し、E0010-4 を欠番にする。ADR 0019 の決定2・決定7 の凍結を解く(決定7 は本 ADR の決定6・決定7 が置き換える)。
