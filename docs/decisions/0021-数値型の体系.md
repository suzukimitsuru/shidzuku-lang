# 0021: 数値型の体系 — 2つの型と、境界の幅付き整数

- 日付: 2026-09-10(改訂: 2026-09-15)
- 状態: 提案
- 関連課題: U23・U15(関連: U9・U22・U12・U13・U5・U24)
- 位置づけ: 破棄した ADR 0010(数値の型と単位)・ADR 0017(数値型の体系)の後継。ADR 0019 の決定2(整数型)を置き換え、決定7 の凍結を解く
- 入力: 思考実験 06・07・12・13・14・16、計画書 第6節 6.1 の8問題
- 改訂: 2026-09-15。書き手の指定(`十進数` を外部システムとの接合や時間の型に使う想定はない・外部との接合では 8/16/32/64 ビットの整数を限定的に扱えればよい・
  時間の型は内部で整数で保持すればよい)を受け、`整数` を基本型から外し、幅付き整数を境界の語彙に移した(思考実験 16 の第7節)

## 背景(なぜ決める必要があるか)

数値型は 2026-09-03 に白紙へ戻った(計画書 第7節 7.1)。破棄されたのは**型を分けるという方針ではない**。
壊れたのは**分けた型のあいだの扱い**であり、引き金は `単位なし` の値とのスカラー倍で現れた9つの組み合わせのうち4つで**宣言のない丸め**が起きる事だった(計画書 6.1 の問題1)。
とりわけ `十進数(7.2) 円 × 実数 単位なし` は、**金額が静かに近似になる経路**である。

同時に、破棄前の設計は別の負債も抱えたままだった。いずれも ADR 0010 が桁を「整数部と小数部の2つ」で宣言した事から出ている。

| 負債                           | 現れ方                                                                 |
| ------------------------------ | ---------------------------------------------------------------------- |
| 上限の見積りが全ての値に要る   | `十進数(9.2)` の `9` を設計時に決める。外せば桁溢れ、広ければ無駄      |
| 桁を狭める受け渡しが直和になる | `収める(値, 十進数(i.f))` の結果を `桁溢れ` と分けて受ける             |
| 中間の桁が膨らむ               | `十進数(9.2) × 整数 単位なし` は 30 桁 = 16 バイト(計画書 6.1 の問題3) |
| 列の合算の桁が静的に決まらない | `合算(列)` は必ず `収める` で受ける(ADR 0010 が認めた唯一の穴)         |
| 2 のべきの境目でバイト数が倍   | ナノ秒の時刻(19 桁)は 8 バイトに収まる値なのに 16 バイト(思考実験 07)  |

本 ADR の中心は、**`十進数` の宣言を刻みだけにする**事である。小数点以下の桁数だけを書き、上限を型から外す(桁数倍した二進整数を、値の大きさに応じた可変長で持つ)。

### 改訂の経緯(2026-09-15)

初版は `整数`・`実数`・`十進数` の3つを維持し、`整数` → `十進数` の昇格1本を暗黙の橋として架けていた。
思考実験 16 で `整数` の要否を調べたところ、**ADR 0019 が `整数` を置いた3つの根拠は本 ADR によってすべて失効している**事が分かった。
残る論拠は「厳密かつ記憶域と実行時間の上界を型が言う唯一の型」だけであり、それも次の3点の指定で外れた(書き手の指定)。

| 指定                                                   | 帰結                                                       |
| ------------------------------------------------------ | ---------------------------------------------------------- |
| `十進数` を Raft など外部システムとの接合には使わない  | 接合の器を数値型に求めない。外部は別の語彙で扱う           |
| 外部との接合では 8/16/32/64 ビットの整数を限定的に扱う | 幅は**外部表現の性質**であり、境界の宣言として持てばよい   |
| `時点`・`日付`・`時刻` は内部で整数で保持すればよい    | 内部表現は実装の話であり、言語の型として `整数` を要さない |

よって本改訂で **`整数` を基本型から外す**。数値型は `実数` と `十進数(s)` の2つになり、**型のあいだの暗黙の変換は1本も要らなくなる**。

## 検討した選択肢

型の数と暗黙変換の2軸は思考実験 14 が比較を済ませている。本 ADR が改めて検討したのは**桁の宣言**・**`整数` の要否**・**幅付き整数の置き場所**である。

### 桁の宣言をどこまで型に残すか

| 案                                    | 先行例                   | 刻みは型から読めるか | 上限は型から読めるか | 記憶域       |
| ------------------------------------- | ------------------------ | -------------------- | -------------------- | ------------ |
| (a) 精度と位取りの両方(`十進数(9.2)`) | ADR 0010・SQL・Ada・PL/I | 読める               | 読める               | 静的に決まる |
| (b) **位取りだけ(`十進数(2)`)**       | 本 ADR                   | 読める               | 読めない             | 値で決まる   |
| (c) どちらも型に持たない              | Java `BigDecimal`        | 読めない             | 読めない             | 値で決まる   |
| (d) 器を1つ固定する                   | C# `decimal`(128 ビット) | 読めない             | 型が1つに固定        | 静的に決まる |

- (a) は上限の見積りを常に要求する。**上限は業務が決めている事が少なく**、書かれた `9` の並びは表現の都合であることが多い。
- (c) は刻みまで値ごとになる。`1.0` と `1.00` が別物になり、等価が表現に依存する(`BigDecimal.equals` の有名な罠)。除算の結果の桁も型から決まらない。
- (d) は宣言がゼロで軽いが、刻みが型から読めない。「1 円未満を切り捨てる」という設計判断が型に残らない。
- (b) は**刻みだけを残す**。刻みは業務が決めた事実であり、上限は入れ物の都合である——この非対称に合わせる。

### `整数` を基本型として置くか

`十進数(0) 単位なし` は刻み 1・上限なし・厳密であり、任意精度の整数そのものである。第6章で `整数` が現れる 10 か所は**すべて `十進数(0)` で書ける**(思考実験 16 の第2節)。

| 案                                 | 暗黙の橋     | 内側の固定長 | 基本型の数 |
| ---------------------------------- | ------------ | ------------ | ---------- |
| (あ) `整数` を置く(初版・ADR 0019) | 1本要る      | ある         | 10         |
| (い) **`整数` を置かない**         | **要らない** | 無い         | **9**      |

(い)を採る。置く根拠が失効している上(改訂の経緯)、**橋が1本も要らなくなる**利点が大きい。
U23(スカラー倍)は型を跨がなくなるため問題ごと消え、整数専用の桁溢れ検査と換算規則も消える。
代償(内側に「厳密かつ上界あり」の型が無くなる)は下記の欠点に記録し、値域の宣言で埋める道を将来に残す。

### 幅付き整数をどこに置くか

外部システムとの接合では 8/16/32/64 ビットの整数を扱う必要がある。置き場所は2つある。

| 案                                    | 形                                                               | 増える基本型 | 要る規則                             |
| ------------------------------------- | ---------------------------------------------------------------- | ------------ | ------------------------------------ |
| (か) 基本型として置く                 | `整数32 単位なし` 等。符号あり/なし × 4幅                        | **8**        | 桁溢れ・巻き戻り・単位・変換を全種に |
| (き) **境界の符号化の語彙として置く** | `符号化(値, 符号付き 32 ビット, ビッグエンディアン) -> バイト列` | **0**        | 詰め替えの宣言だけ                   |

(き)を採る。**幅は値の性質ではなく、外部表現の性質である**——ADR 0010 が単位を型に載せ、外部での綴り(`cm`・`℃`)を U12 へ送ったのと同じ切り分けである。
「限定的に扱えればよい」という要件に、基本型を8つ増やす答えは重い。演算は内側の `十進数(0)` で行い、境界で詰め替える。
外部表現の器(`バイト列`)と役割(`境界`・`解析`)は ADR 0013 が既に置いている。

## 決定

### 1. 数値型は2つ置く

| 型          | 器         | 刻み                | 上限       | 宣言する事       | 何をした値か         |
| ----------- | ---------- | ------------------- | ---------- | ---------------- | -------------------- |
| `十進数(s)` | **可変長** | `10^-s`(型が定める) | **無い**   | 単位と小数部の桁 | 厳密に決まっている   |
| `実数`      | binary64   | 値の大きさで変わる  | 型が定める | 単位             | 測った・計算で作った |

- **数える値は `十進数(0)`** である。個数・添字・長さ・版・連番・時間の量は、いずれも「刻みが 1 の厳密な値」であり、特別な型を要しない。
- **`整数` は基本型から外す**(ADR 0019 決定2 を置き換える)。外部との接合で必要な幅付き整数は、境界の語彙として持つ(決定9)。
- 基本型は10 から9(`論理`・`十進数`・`実数`・`テキスト`・`バイト列`・`時点`・`日付`・`時刻`・`時間帯`)になる。

### 2. `実数` は IEEE 754 binary64 とする — 型に序列は置かない

```plaintext
実数 メートル      # 測った長さ
実数 単位なし      # 測って得た比・確率・尤度
```

ADR 0017 の内容を引き継ぐ。要点だけを再掲する(本 ADR が改めて決定する)。

- **桁も丸め方も書かない**。範囲と有効桁は型が1つに定めており、丸めは全ての演算で起きる。それは `実数` という名前が告げている性質である。
- **四則の演算子 `+ - × ÷` を持つ**。`平方根(値)`・`累乗(底, 指数)` も桁と丸めの宣言を要らない。
- **IEEE 754 に厳密に従う**。binary64 のみ、丸めは最近接偶数に固定、FMA への融合・再結合・拡張精度での中間保持・近似逆数・代数的な書き換えを禁じる。
  超越関数は正しく丸めた結果を要求し、満たせない関数は語彙に入れない。列の合算は先頭から順に行い、実装の並べ替えを禁じる。
  これにより、分散した複数ノードで結果が一致する(Raft の前提・ADR 0001)。
- **NaN・±∞・-0 を値として持たない**。生む演算は失敗とし(U13)、検査は「値が名前を得る所」で例外フラグを見る。比較は全順序、等価は素直である。

**「主に使う型」は置かない。** ADR 0017 は `実数` を「主に使う型」と位置づけたが、本 ADR はこれを引き継がない。

- **型は書き手が値ごとに指定する物である。** 型名は必ず書き(省略の禁止・ADR 0008)、省略時に補われる型は無い。
  補われる型が無い以上、言語が序列を置いても書かれる記述は1文字も変わらない。「よく使われる」は書き手の統計であって、言語の決定ではない。
- **`実数` の宣言が軽いのは、優先されるからではない。** 測った値には桁と丸めの宣言が意味を持たない——だから欄が無い。
  同じ理由で、厳密な値には小数部の桁が要る。**軽さは値の性質の反映であって、順位ではない。**

### 3. `十進数(<小数部の桁>)` — 刻みだけを宣言する

```plaintext
十進数(<小数部の桁数>) <単位 | 単位なし>

十進数(2) 円         # 刻み 0.01 円。上限は無い
十進数(4) 単位なし   # 税率・利率(刻み 0.0001)
十進数(0) 単位なし   # 刻み 1。個数・添字・版・連番
十進数(0) ナノ秒     # 時間の量
```

- **小数部の桁は必ず書く**。刻みは業務が決めた設計判断であり、型から読めなければならない。
- **整数部の欄は無い**。省略しているのではなく、**欄そのものを持たない**(ADR 0017 が `実数` について書いた「桁という欄を持たない完結した型」と同じ形)。
  書かれなかった欄を既定で補う事はしていないため、省略の禁止(ADR 0008)には当たらない。E0008-1 の対象は「型名・単位の欄・小数部の桁」である。
- **静的指数(`指数 e`)は廃止する**。指数は「幅の有限な窓の**位置**」を動かす仕組みであり、上端の無い窓に位置の概念はない。下端は小数部の桁がそのまま決める。
  桁の窓が原点から極端に離れた値(物理定数)は `実数` の領分である。

#### `十進数(i.f)` は廃止する — 2つの形を併存させない

置き換えであって追加ではない。ADR 0010 の形は残さず、`十進数` は可変長の1つの形だけを持つ。
併存させれば、選ぶ判断が全ての値に増え、公開面で形が食い違う組み合わせが生まれる。

| ADR 0010 の記述                          | 本 ADR での書き方                      |
| ---------------------------------------- | -------------------------------------- |
| `十進数(7.2) 円`                         | `十進数(2) 円`                         |
| `十進数(9.2) 円`                         | `十進数(2) 円`(整数部の違いは消える)   |
| `十進数(1.5 指数 -31) キログラム`        | 廃止。`実数 キログラム` を使う         |
| `収める(値, 十進数(9.2))`                | 廃止。そのまま渡せる                   |
| `十進数(9.2) 円` と `桁溢れ` の直和      | 廃止。整数部の桁溢れが存在しない       |
| `丸める(値, 十進数(9.2), 丸め 四捨五入)` | `丸める(値, 十進数(2), 丸め 四捨五入)` |
| `収める(合算(列), 十進数(9.2))`          | `合算(列)`                             |
| `整数 単位なし`(ADR 0019)                | `十進数(0) 単位なし`                   |
| `整数 ナノ秒`(ADR 0019)                  | `十進数(0) ナノ秒`                     |

### 4. 内部表現は「小数桁倍した可変長の符号付き2進整数」

ADR 0010 の表現をそのまま引き継ぐ。変わるのは**幅を型ではなく値が決める**事だけである。

- 値は整数 `m` と型が定める小数部桁 `s` の組で保持し、実数値は `m × 10^-s` である。演算は全て整数演算になる。
- 実装は小さい値を機械語に収め、収まらなくなった時点で多倍長へ移してよい。

  | 値の総桁 | `m` のビット | 典型的な格納           |
  | -------- | ------------ | ---------------------- |
  | 1〜18    | 63 まで      | 1 ワードに収める       |
  | 19〜38   | 127 まで     | 2 ワード、または多倍長 |
  | 39 以上  | —            | 多倍長                 |

- **表現の選び方は実装の自由、値の意味は表現に依存しない**。ADR 0010 の「桁の意味はバイト数に依存しない」を、桁の宣言が無い側へ延長したものである。
  添字・長さ・時間の量のように小さい事が分かっている値を、出力先が機械語整数で持つ事も実装の自由である。
- **同じ値は必ず同じ正準形を持つ**。`s` は型が固定するため `m` は一意であり、格納場所(ワードか多倍長か)は等価・順序・ハッシュに影響しない。
  正準形が一意である事は、ハッシュ可能である条件(ADR 0013 決定3)であり、分散でのダイジェスト一致の前提でもある。
- **記憶域を確保できない事は失敗**であり、黙って値を壊さない(U13)。

### 5. 演算 — 誤差の出る場所は3つのまま

| 演算                                                                      | 結果の小数部 | 誤差                          |
| ------------------------------------------------------------------------- | ------------ | ----------------------------- |
| `a + b` / `a - b`                                                         | 細かい方     | なし                          |
| `a × b`                                                                   | 両辺の和     | なし                          |
| `分ける(a, b)`                                                            | `a` と同じ   | なし                          |
| `合算(列)`                                                                | 要素と同じ   | なし                          |
| `割る(a, b, 十進数(s), 丸め <方式>)`                                      | 宣言した桁   | 丸め1回                       |
| `丸める(a, 十進数(s), 丸め <方式>)`                                       | 宣言した桁   | 丸め1回                       |
| `換算(a, <単位>, …)`                                                      | 宣言した桁   | 丸め1回(細かい単位へは無損失) |
| `累乗(a, n, 十進数(s), 丸め <方式>)`・`平方根(a, 十進数(s), 丸め <方式>)` | 宣言した桁   | 丸め1回                       |

- **誤差が出るのは、除算・粗い単位への換算・小数部を狭める受け渡しの3つだけ**である(ADR 0010 と同じ)。
- **除算の演算子 `÷` は持たない**。`割る(…)` と `分ける(a, b)`(商と余り)だけとする。整数の `/` が切り捨てになるような、宣言されていない丸めは起こさない(ADR 0019 決定2 の判断を引き継ぐ)。
- **`収める` は要らない**。整数部の桁溢れが存在しないため、`合算(列)` も乗算の連鎖も、そのまま `十進数` で受けられる。
  ADR 0010 が「桁が静的に決まらない唯一の演算」として直和を義務づけた穴は、これで閉じる。
- **10 のべきの換算は、細かい単位へは常に無損失**である(整数部が伸びるだけ)。粗い単位へは、小数部の桁が足りれば無損失、足りなければ丸めの宣言を要求する(E0010-3)。
  刻み 1 の値(`十進数(0) ナノ秒`)を粗い単位へ移す場合も同じ規則が当たる——**整数専用の換算規則は要らなくなる**(ADR 0019 決定2 の該当部分を置き換える)。
- 拡張は自動、縮小は必ず書く。`十進数(2)` の値を `十進数(4)` の欄へ渡すのは無損失で自動、逆は `丸める` を書く。

### 6. 数値型のあいだに暗黙の変換を持たない — 例外はゼロ

型が2つになったため、**橋を架ける相手がいない**。初版が置いた `整数` → `十進数` の昇格は、`整数` と共に消える。

- `実数` と `十進数` が混ざった式はコンパイル時エラー(E0019-3)。
- **近似は厳密を飲み込まない。** 数値の塔の「伝染」(Scheme・Julia)は採らない。破棄の原因(`十進数 円 × 実数 単位なし`)がそのまま復活するためである。
- **スカラー倍の特別規則は要らない。** `十進数(2) 円 × 十進数(0) 単位なし` は同じ型どうしの乗算であり、結果は `十進数(2) 円`(小数部は `2 + 0`)。
  計画書 6.1 が書き下ろそうとした規則も、初版の昇格も、**どちらも不要になる**。
- 単位の規則は ADR 0010 のまま(`円 × 単位なし = 円`、異なる量の加減算は E0010-1)。

### 7. 2つの型のあいだの変換は名前で書く

| 変換          | 書き方                                   | 丸めの宣言 | 失敗         |
| ------------- | ---------------------------------------- | ---------- | ------------ |
| 十進数 → 実数 | `近似する(値)`                           | 不要       | 桁溢れ時のみ |
| 実数 → 十進数 | `厳密にする(値, 十進数(s), 丸め <方式>)` | 必須       | **無い**     |

- 変換の前後で**単位は保たれる**。量の検査は変換を跨いで効く。
- **往復は一致を保証しない**(W0017-2)。
- **リテラルは書かれた通りの十進の値**であり、`実数` の文脈では最近接の binary64 になる。`0.1` が実数では 0.1000000000000000055511… である事は、`実数` という型名が告げている。

### 8. 量と単位は ADR 0010 から引き継ぐ

破棄した ADR 0010 のうち、**量と単位の体系はそのまま生かす**(思考実験 14 の論点7。F# の Units of Measure が設計を裏付けている)。

- `量`・`単位` の宣言、基準単位に対する比は既約の有理数、換算比を持たない量(通貨・温度)、組立の量は宣言されたものだけ。
- 換算誤差の規則(連鎖換算をしない・掛けてから割る・結果の桁を宣言させる・比較は換算しない)。
- 丸めの語彙6種(切り捨て・切り上げ・床・天井・四捨五入・銀行丸め)と、**既定を持たない**規則。
- 検査 E0010-1・E0010-2・E0010-5、警告 W0010-1・W0010-2。
- 単位は両方の型に載る。型情報のみであり、実行時コストはゼロである。

### 9. 外部との詰め替えは、幅・符号・バイト順を宣言する

外部システム(プロトコル・機器・DB・ファイル形式)の数は、8/16/32/64 ビットの整数で表される。
これを**型ではなく、境界での符号化の宣言**として扱う。

```plaintext
復号(<バイト列>, <符号と幅>, <バイト順>) -> 十進数(0) 単位なし
符号化(<値>, <符号と幅>, <バイト順>)     -> バイト列 | 範囲外

在庫 = 復号(受信, 符号付き 32 ビット, ビッグエンディアン)     # 失敗しない
応答 = 符号化(在庫, 符号付き 32 ビット, ビッグエンディアン)   # 幅に入らなければ失敗
```

- **幅は `8`・`16`・`32`・`64` ビット、符号は `符号付き`・`符号なし`** とする。バイト順は `ビッグエンディアン`・`リトルエンディアン`。
  8 ビットにはバイト順の欄が無い(選択肢が無いため。`実数` に桁の欄が無いのと同じ形であり、E0008-1 には当たらない)。
- **向きで失敗が非対称である。** 外部 → 内側(`復号`)は**必ず成功する**——任意精度の `十進数(0)` には、どの幅の整数も必ず入る。
  内側 → 外部(`符号化`)は、宣言した幅に入らなければ**失敗**する(U13)。可変長を選んだ事が、受け取り側の安全として効いている。
- **詰め替えは `境界` の役割でのみ書ける**(E0021-1)。ADR 0013 の役割と噛み合い、外部表現の知識が領域層へ漏れない。
- 復号した値は `単位なし` である。単位を付けるのは `単位を付ける`(ADR 0010、body 内でのみ書ける操作)。
- **幅は値の性質ではなく外部表現の性質である。** 内側では `十進数(0)` として扱い、幅の宣言は境界に閉じる。
  外部の構造体をそのまま写した宣言(`外部形式 ヘッダ { 版: 符号なし 8 ビット, … }`)に名前を付ける形は、U12(外部世界との境界)で扱う。

### 10. `時点`・`日付`・`時刻` は範囲を仕様が定め、内部表現は実装に委ねる

ADR 0019 の決定4・決定5・決定6 は「内部表現はエポックからの `整数 ナノ秒`」のように書かれていた。これを次のように読み替える。**決定の意味は変わらない。**

| ADR 0019 の記述                       | 本 ADR での読み替え                                                                       |
| ------------------------------------- | ----------------------------------------------------------------------------------------- |
| 内部表現はエポックからの整数ナノ秒    | **表せる範囲を仕様が定める**(1677〜2262 年)。内部表現は実装に委ねる(整数で保持すればよい) |
| `日付` の内部表現は `整数 日`         | 範囲は暦が定める(紀元前10000年〜西暦9999年)。内部表現は実装に委ねる                       |
| `隔たり` の結果 `整数 <単位>`         | `十進数(0) <単位>`                                                                        |
| `日を足す(日付, 整数 日)`             | `日を足す(日付, 十進数(0) 日)`                                                            |
| `日数(始め, 終わり) -> 整数 日`       | `日数(始め, 終わり) -> 十進数(0) 日`                                                      |
| `時計を進める` の繰り上がり `整数 日` | `十進数(0) 日`                                                                            |

- **範囲は型の器の帰結ではなく、仕様が定める値**になる。これは ADR 0010 の「桁の意味はバイト数に依存しない」と同じ思想であり、移植性は上がる。
- `隔たり` の結果が宣言した単位で範囲を出る失敗は、**器ではなく `時点` の範囲から決まる**(ADR 0019 決定4 の意図はそのまま)。

### 11. 検証 — 2つ廃止、3つ改訂、1つ新設

検証番号は ADR 0016 の `E<出自>-<連番>` に従う。**一度与えた番号は動かさない**(0016 決定3)ため、引き継ぐ検査は出自の番号のまま残す。

| 識別子  | 検査                                                           | 本 ADR での扱い                                        |

| E0010-3 | 丸めが避けられない演算に丸めの宣言がない                       | **改訂**。除算・粗い単位への換算・小数部の縮小に当たる |

| E0010-5 | 宣言のない組立の量の出現                                       | 引き継ぐ(変更なし)                                     |
| E0019-3 | 数値型が明示の変換なしに混ざる                                 | **改訂**。対象は `実数` と `十進数` の2つ。例外は無い  |

| W0017-1 | 通貨の量を持つ値に `実数` を使っている                         | 引き継ぐ                                               |
| W0017-2 | `実数` と `十進数` のあいだで往復変換している                  | 引き継ぐ                                               |
| W0019-1 | `整数` → `実数` の変換で 2^53 を超え得る                       | **廃止(欠番)**。`整数` が無くなった                    |

実行時の失敗(U13)は次のように変わる。

| ADR 0019 が挙げた失敗          | 本 ADR                                     |
| ------------------------------ | ------------------------------------------ |
| 整数の加減乗が表せる範囲を出る | **無くなる**(加減乗は常に厳密)             |
| `分ける(a, 0)`(0 除算)         | 残る                                       |
| `時点` が範囲を出る            | 残る(範囲は仕様が定める。決定10)           |
| `日付` が範囲を出る            | 残る(同上)                                 |

### 12. 使い分けの指針

判断の基準は「**その値は厳密に決まっているか、測って得た値か**」の1問である。数える値は「刻みが 1 の厳密な値」であり、別の型を要しない。

| 厳密に決まっている(→ `十進数(s)`)                | 測った・計算で作った(→ `実数`) |
| ------------------------------------------------ | ------------------------------ |
| 個数・注文数・在庫数・回数(`十進数(0)`)          | 距離・質量・温度・電圧         |
| 列の添字・長さ・繰り返し回数(`十進数(0)`)        | 座標・角度・速度               |
| 版・連番・世代番号(`十進数(0)`)                  | 平均・分散・標準偏差           |
| 時間の量(`十進数(0) ナノ秒` 等)                  | 確率・尤度・スコア             |
| 金額・単価・税率・按分(`十進数(2)`・`十進数(4)`) | 信号・座標変換・統計量         |

- **通貨の量を持つ値に `実数` を使うと警告(W0017-1)**。禁止ではないが、既定の選択ではない。
- **`単位なし` の係数は、掛ける相手に合わせる。** 金額に掛ける税率は `十進数(4) 単位なし`、測った値に掛ける係数は `実数 単位なし` である。
  取り違えても静かには壊れない——`十進数 × 実数` はコンパイル時エラー(E0019-3)になる。

## この形式の名前 — 既存の体系での呼び名

新しい形式ではない。ADR 0010 の同名の節を、可変長の形に合わせて調べ直した。

| 観点                         | 呼称                                                                                                                   | Shidzuku との違い                         |
| ---------------------------- | ---------------------------------------------------------------------------------------------------------------------- | ----------------------------------------- |
| 分類                         | **厳密数値型**(exact numeric)。MySQL は「Fixed-Point Types (Exact Value)」と呼ぶ                                       | 厳密側だけを持つ                          |
| 一般名                       | **十進固定小数点数**(decimal fixed-point number)。精度に上限を置かない版は **arbitrary-precision fixed-point decimal** | 同じ                                      |
| 表現                         | **位取り整数**(scaled integer)。格納整数(stored integer)× 位取り係数(scaling factor `10^-s`)、刻みは分解能(resolution) | 同じ                                      |
| 位取りが**値ごと**(動的)     | Java `BigDecimal`(unscaled value + scale)、Smalltalk `ScaledDecimal`(リテラル `1.23s2`)、Go `shopspring/decimal`       | Shidzuku は位取りを**型**に固定する       |
| **位取りが型・精度は無制限** | **Haskell `Data.Fixed`**(`newtype Fixed a = MkFixed Integer`、`type Centi = Fixed E2`)                                 | **同型**。単位と量が載る点だけが違う      |
| 位取りが型・精度は有界       | SQL `NUMERIC(p,s)`、Ada の十進固定小数点型、PL/I `FIXED DECIMAL(p,q)`、Rust の `fpdec`(位取りは型の定数)               | 精度の上限を持たない                      |
| 精度を書かない宣言           | PostgreSQL の `numeric`(整数部 131072 桁・小数部 16383 桁まで)                                                         | 実務上は同じ。Shidzuku は上限を規定しない |
| 数学                         | `(1/10^s)ℤ` — 整数と同型の格子(ADR 0010 の `ℤ[1/10]` の、位取りを固定した部分群)                                       | 表せる値の集合そのもの                    |
| 単位                         | units of measure(F# の `[<Measure>]`)                                                                                  | 同じ                                      |

まとめると、Shidzuku の `十進数(s)` は**単位付き・静的位取り・任意精度の十進固定小数点数**である。

- **完全な先行例は Haskell の `Data.Fixed`** である。位取りを型パラメータ(`E2` 等、`HasResolution` の実装)に持ち、中身は任意精度の整数1つ——本 ADR の `十進数(2)` と構造が一致する。
  `type Centi = Fixed E2` は `十進数(2)` そのものであり、`Deci`・`Milli`・`Micro`・`Nano`・`Pico` という別名は、Shidzuku で言えば刻みに名前を付けたものにあたる。
- **`BigDecimal`・`ScaledDecimal` との違いは、位取りが値ごとか型かの一点**である。この一点が、等価の素直さ(`1.0` と `1.00` が同じ値になる)と、除算の結果の桁が型から決まる事を生む。
- 幅付き整数を境界だけで扱う形は、Erlang のビット構文・Ada の表現節・Rust の `#[repr]` と同じ位置づけである——**幅は表現の宣言であって、値の型ではない**。

## 机上検証

### 1. 危険な組み合わせは消えるか(計画書 6.1 の問題1)

型が2つになったため、組み合わせは9から4に減る。

| 単位を持つ側 | `単位なし` 側 | 破棄前の規則案         | 本 ADR                                         |
| ------------ | ------------- | ---------------------- | ---------------------------------------------- |
| `十進数`     | `十進数`      | 桁が和になる           | `十進数`(小数部は和)。**数える値もここに入る** |
| `十進数`     | `実数`        | **近似が厳密に化ける** | **エラー**(E0019-3)                            |
| `実数`       | `十進数`      | **暗黙の丸め**         | **エラー**(E0019-3)                            |
| `実数`       | `実数`        | `実数`                 | `実数`                                         |

**宣言のない丸めが起きる組は存在しない。** 危険だった4組は、型が消えた事で組み合わせごと無くなるか、コンパイル時エラーになる。

| 問題                                       | 本 ADR の答え                                                    |
| ------------------------------------------ | ---------------------------------------------------------------- |
| 1. 9組中4組で宣言のない丸め                | 解ける。**型を2つにしたため、危険な組が存在しない**              |
| 2. 「型を変えない」の型が桁を含むか        | 解ける。桁は小数部だけであり、乗算では和(数える値は 0 桁)        |
| 3. `整数` をスカラーにすると中間桁が膨らむ | 解ける。**中間桁の見積り自体が無くなる**(可変長)                 |
| 4. 除算の側が決まっていない                | 解ける。`割る(金額, 人数, 十進数(2), 丸め 切り捨て)` と書ける    |

| 6. 両辺 `単位なし` で型が違う場合          | 決まる。`十進数 × 実数` はエラー、`十進数 × 十進数` は小数部の和 |

### 3. 明細行の金額(思考実験 12 の論点1・思考実験 13)

```plaintext
# 破棄前
data 明細 { 単価: 十進数(7.2) 円, 数量: 整数 単位なし }
金額 = 収める(単価 × 収める(数量, 十進数(5.0)), 十進数(9.2))   # 変換2つと直和2つ

# 本 ADR
data 明細 { 単価: 十進数(2) 円, 数量: 十進数(0) 単位なし }
金額 = 単価 × 数量                                              # 同じ型どうし。十進数(2) 円
合計 = 合算(明細.金額)                                          # 収める も要らない
```

変換も直和の分岐も、**型を跨ぐ規則そのものも**無くなる。思考実験 12 が「全ての明細行に現れる」と書いた重さは残らない。

### 4. 記憶域は実際の値に合うか

| 値                            | 破棄前の宣言と割当         | 本 ADR の宣言と割当                      |
| ----------------------------- | -------------------------- | ---------------------------------------- |
| 金額 1234.56 円               | `十進数(7.2)` = 8 バイト   | `十進数(2)`、`m`=123456 → 1 ワード       |
| 明細100行の合計(最大 10 億円) | `収める` が必要            | `十進数(2)`、`m` は 11 桁 → 1 ワード     |
| 単価 × 数量(1234.56 × 100)    | 中間 30 桁 = 16 バイト     | `m`=12345600 → 1 ワード                  |
| ナノ秒の時刻(19 桁)           | `整数 ナノ秒` = 8 バイト   | `十進数(0)`、`m` は 61 ビット → 1 ワード |
| 円周率を 30 桁で持つ          | `十進数(1.30)` = 16 バイト | `十進数(30)`、`m` は 31 桁 → 多倍長      |

`整数` を外しても、**実装が1ワードに収める限り記憶域は変わらない**(19 桁の値は 61 ビット)。変わるのは「型がそれを保証しない」事である。

### 5. 外部との詰め替え(決定9)

```plaintext
component 在庫同期 {
  layers { 境界: io, 領域: pure }

  # 境界層 — 外部の 32 ビット整数を内側の値にする
  在庫数 = 復号(受信, 符号付き 32 ビット, ビッグエンディアン)     # 十進数(0) 単位なし。失敗しない
  数量   = 単位を付ける(在庫数, 個)                               # 十進数(0) 個

  # 領域層 — 幅は現れない
  残り = 数量 - 出荷数

  # 境界層 — 外へ出す時だけ幅を宣言する
  応答 = 符号化(単位を外す(残り), 符号付き 32 ビット, ビッグエンディアン)   # 範囲外は失敗
}
```

外部の幅は**境界層にしか現れない**(E0021-1)。領域層は刻みと単位だけを見る。

## 結果(利点と欠点)

### 利点

- **暗黙の変換が1本も無い**。「数値型は混ざらない」が例外ゼロの規則になる(Swift・Ada・Haskell と同じ厳格さ)。U23 は問題ごと消える。
- **型が2つになり、選ぶ問いが1つになる**。「厳密に決まっているか、測った値か」。数える値は刻み 1 の特別な場合として畳める。
- **宣言が減る**。`十進数` に書くのは刻みと単位の2つだけで、上限の見積りという設計判断が消える。
- **`収める` と直和の分岐が消える**。桁溢れが存在しない。
- **失敗が1種類減る**。整数の加減乗の桁溢れ(演算ごとの検査)が無くなり、加減乗は言語全体で常に厳密になる。
- **特別扱いが減る**。整数専用の換算規則が要らなくなり、換算は1本の規則で済む。
- **記憶域が実際の値に合う**。中間桁の膨張も 2 のべきの境目も消える。
- **外部との詰め替えが安全な向きに非対称**。外部から受ける `復号` は必ず成功し、外へ出す `符号化` だけが失敗し得る。
- 厳密さ・結合則・正準形の一意性・分散での再現性は、いずれも失われない(演算は整数演算のまま)。

### 欠点

- **内側に「厳密かつ上界あり」の型が無い**。`十進数` は上界を持たず、`実数` は近似である。
  動的確保を伴うため**WCET が要る所・`no_std` の組込みでは使えない**。この空白は、値域の宣言(将来の変更想定)が来るまで埋まらない。
  **組込み・実時間を Phase 1 の対象に含めるなら、値域の宣言を前倒しする必要がある。**
- **添字・長さの上界が型から消える**。実装が機械語で持つ事は自由だが、型はそれを保証しない。
  Haskell は整数リテラルの既定を任意精度の `Integer` に置きながら、`length` は機械語の `Int` を返している——その保証をこの言語は持たない。
- **出力先で多倍長が常用になる**。TypeScript では数え上げが `BigInt` になり得る(V8 の BigInt は最適化が薄い)。小さい整数の即値化は出力先の実装に委ねる事になる。
- **上限が型から読めない**。「金額は 9999999.99 円まで」という業務上の上限が実在する系では、その知識が型から抜ける。暴走した反復や極端な入力はコンパイル時に落ちない。
- **境界の語彙が増える**。`復号`・`符号化` と、符号・幅・バイト順の語が要る。外部の構造体を写す宣言の形は U12 に残る。
- **`実数` の誤用は警告でしか止まらない**。`0.1 + 0.2 ≠ 0.3` はその型を選んだ限り起きる。金額に `実数` を使う誤りを止めるのは W0017-1(警告)だけである。
- **序数(U24)に掛け算が書ける**。`版 十進数(0) 単位なし × 3` が通る。U24 が解くまで残る。
- **静的指数を失う**。窓の位置が極端な値(物理定数)は `実数` を使う事が前提になる。

#### 「厳密かつ上界あり」が無い事で、具体的に何が起きるか

上の1つ目は本 ADR の最大の欠点であり、一般論では足りない。**この言語のどの機能で、どう現れるか**を挙げる。

| #  | 場面                                     | 起きる事                                                                                                                     | いまの受け皿                             |
| -- | ---------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------- | ---------------------------------------- |
| 1  | 期限付きの ask(ADR 0004 の `deadline`)   | 桁が伸びた値の演算は時間が延びる。**期限超過が値の大きさで起きる**——同じ記述が、値によって間に合ったり間に合わなかったりする | 無い。期限超過として観測されるだけ       |
| 2  | 失敗し得る演算の一覧(U13)                | 確保の失敗は**すべての算術で起き得る**。「失敗は型に出す」方針に対し、加減乗が失敗し得る演算の側に回る                       | 決定4 が失敗と定めるのみ                 |
| 3  | `state` に溜める累計・連番・世代番号     | 桁が単調に伸びる状態は**記憶域が単調に増える**。いつ確保に失敗するかは入力次第で、コンパイル時には見えない                   | W0010-2 は刻みの警告であり、伸びは見ない |
| 4  | 外部から来る数(テキストの解析・外部形式) | 境界の `復号`(決定9)は幅で守られるが、**テキストや外部形式の十進には幅が無い**。長大な数をそのまま内側へ通せる               | U12 に送ってある(未定)                   |
| 5  | 分散の応答性(ADR 0001 の Raft)           | 多倍長の確保は任意の場所で起き得る。心拍・選挙の締切に一時停止が乗れば、**再選挙が値の大きさで誘発され得る**                 | 無い                                     |
| 6  | 列の添字・長さ                           | 実装が機械語に落とす保証が型に無いため、**列の操作そのものが値依存**になり得る                                               | 実装の裁量                               |
| 7  | 64 ビットの外部と突き合わせる値(識別子)  | 内側で伸びた値は、外へ出す `符号化` まで範囲外が分からない。**失敗が境界まで遅れる**                                         | 決定9 の `符号化` の失敗                 |
| 8  | 性能の可搬性                             | 出力先が小さい整数の即値化(fixnum・Smi)を持つかで性能が桁違いに変わる。**意味は環境に依存しないが、性能は依存する**          | 無い                                     |

**1・2・5 は第0章 0.5 の「運用で驚きがない」に直接当たる。** 驚きは「値が大きいと遅くなる・落ちる」という形で現れ、**型からは読めない**。
ADR 0010 が排したのは「値が黙って壊れる驚き」だったが、ここで入るのは「**資源と時間が値に依存する驚き**」である。種類は違うが、運用で出会うという点では同じである。

一方で、**起きない事**も明記しておく。

- **値が黙って壊れる事は無い。** 確保できなければ失敗であり(決定4)、桁が落ちたり巻き戻ったりはしない。
- **分散の合意そのものは壊れない。** 桁は入力から決まるため全ての複製で同じ値・同じ桁になる。足りないノードは落ちるが、状態が食い違う事はない(決定2 の再現性は保たれる)。
- **境界を越えた先を壊す事も無い。** 外へ出る値は `符号化` で幅に入らなければ失敗する(決定9)。相手の記憶域を伸ばす経路は無い。

つまり残る危険は**自ノードの資源と応答時間**に閉じている。それでも 1・5 は障害境界の中でノードを止める経路であり、
**組込み・実時間・低遅延の分散を対象に含めるなら、値域の宣言(将来の変更想定)を前倒しして塞ぐ必要がある**。

### 総括 — 何と引き換えに何を得るか

**型が答えるのは「刻み」だけにし、「上限」は外部との境界だけで言う。**

| 問い                   | `十進数(s)`  | `実数`     | 境界の宣言(決定9) |
| ---------------------- | ------------ | ---------- | ----------------- |
| どれだけ細かいか(刻み) | 型が答える   | 答えない   | —                 |
| どれだけ大きいか(上限) | **答えない** | 型が答える | **幅が答える**    |
| 値は厳密か             | 厳密         | 近似       | 厳密              |
| 記憶域は静的に決まるか | 決まらない   | 決まる     | 決まる            |

ADR 0010 は「実行時の驚きを、記述の重さとして前払いする」だった。本 ADR は**前払いする内容を刻みだけに絞り、上限は外部と接する所でだけ払う**。
上限は業務が決めている事が少なく、本当に固定幅が要るのは外部と詰め替える瞬間だからである。

## 捨てたもの・理由

- **桁を2つ(整数部・小数部)宣言する案(ADR 0010 の形)**: 上限の見積りを全ての値に要求する。桁溢れの直和・中間桁の膨張・合算の上界不定・2 のべきの境目という4つの負債が、全てここから出ていた。
- **小数部も型から外す案(Java `BigDecimal`)**: 刻みが値ごとになり、`1.0` と `1.00` が別物になる(等価が表現に依存する)。除算の結果の桁も型から決まらず、丸めの宣言の置き場所が消える。
- **器を1つ固定する案(C# `decimal` の 128 ビット)**: 宣言はゼロになるが、刻みが型から読めない。「1 円未満を切り捨てる」という設計判断が型に残らない。
- **汎用の `整数` を基本型として置く案(ADR 0019 決定2・本 ADR の初版)**: 置いた3つの根拠(桁の宣言が全ての数えた値に掛かる・19 桁で記憶域が倍になる・任意精度は記憶域が読めない)は、
  決定3 と決定4 で失効している(思考実験 16)。数える値は `十進数(0)` で書け、時間の型の内部表現は実装の話である。
  置けば**暗黙の橋が1本要る**——その例外を作らずに済む方を採る。
- **幅付き整数(`整数8`〜`整数64`)を基本型として置く案**: 符号あり/なしで8種増え、それぞれに桁溢れ・巻き戻り・単位・変換の規則が要る。
  **幅は値の性質ではなく外部表現の性質**であり、内側に持ち込むと外部の都合が領域層まで漏れる。
- **`整数` → `十進数` の暗黙の昇格(本 ADR の初版)**: `整数` を外した事で、架ける相手が無くなった。例外ゼロの規則の方が単純である。
- **数値の塔にする案(Scheme の伝染規則・Julia の `promote_rule`)**: 近似が厳密を飲み込む向きを暗黙にする。破棄の原因がそのまま復活する。
- **「主に使う型」を決める案(ADR 0017 の位置づけ)**: 型は書き手が値ごとに指定する物であり、省略時に補われる型は無い。
  言語が序列を置いても書かれる記述は1文字も変わらず、**「主に使う」が言語の決定として成立しない**。
- **静的指数を残す案**: 上端の無い窓に位置の概念はない。下端は小数部の桁が決める。窓の位置が極端な値は `実数` の領分である。
- **可変長を公開面・data に書けなくする案**: `十進数` が可変長のみになった以上、金額を公開面に書けなくなる。外部から来る値の桁の制限は境界の検証(U12)の仕事とする。
- **言語が桁の上限(1 値あたり N バイト)を定める案**: 同じ記述が環境によって成否を変える。ADR 0010 の「桁の意味はバイト数に依存しない」に反する。

## 将来の変更想定

- **値域の宣言**(`十進数(2) 円 範囲 0..999999999`)。業務上の上限が実在する場合に、桁ではなく業務の言葉で書く案。
  **内側に「厳密かつ上界あり」の型が無い**という本 ADR の欠点を埋める唯一の道でもあり、組込み・実時間を対象に含めるなら Phase 1 で前倒しする。
- **外部形式の名前付き**(U12)。`外部形式 ヘッダ { 版: 符号なし 8 ビット, 長さ: 符号なし 32 ビット ビッグエンディアン }` のように、詰め替えの宣言に名前を付ける形。
  外部形式(JSON の数値・SQL の `DECIMAL`)から `十進数` を作る所で桁の上限をどう宣言させるかも、ここで決める。
- **失敗の体系との統合**(U13)。0 除算・`符号化` の範囲外・`実数` の特殊値・記憶域の確保失敗・`時点`/`日付` の範囲外を同じ語彙に載せる。
- **序数と基数**(U24)。`十進数(0)` に掛け算が書ける事は変わらない。
- **binary32 の追加**(論点4)・**区間演算**(論点5)。機械学習・GPU・数値解析を対象に含める判断と一緒に決める。
- **三角関数・対数**。正しい丸めを満たす実装を用意できた関数から `実数` に入れる。
- 採用時の反映先:
  - 第6章 6.1 の基本型の一覧から `整数` を外し(10 → 9)、`実数` の「主に使う数値型」の記述を落とす。
  - 第6章 6.3 の「再検討中」の注記を外し、`十進数(i.f)` を `十進数(s)` に、`整数` を `十進数(0)` に書き換え、`収める`・静的指数・整数専用の換算規則を落とす。
  - 第6章 6.4〜6.6(`時点`・`日付`・`時刻`)の内部表現の記述を、決定10 の読み替えに合わせる。
  - 第3章 3.3 に E0021-1 を追加し、E0010-3・E0019-3・E0019-4 を改訂、E0010-4・W0019-1 を欠番にする。実行時の失敗の一覧も決定11 に合わせる。
  - ADR 0019 の決定2 を本 ADR が置き換える旨と、決定7 の凍結を解く旨を記録する。
