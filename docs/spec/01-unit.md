# Shidzuku 言語仕様書 — 第1章 基本単位の定義

- 状態: Draft
- 日付: 2026-08-19
- 依拠: 第0章 0.3〜0.4、ADR 0003(提案)・0005(提案)・0006(提案)。ADR の採否により本章も改訂される

## 1.1 単位の宣言

単位(unit)は Shidzuku の唯一の構成要素である。設計単位・処理単位・障害境界・配置単位は同一である(第0章 0.3)。

```plaintext
unit <単位名> {
  intent     { ... }   # 第一層: 意図(1.2)
  constraint { ... }   # 第二層: 制約(1.3、語彙は第2章)
  body       { ... }   # 第三層: 実装(1.4)
}
```

- 三層はいずれも省略できない(第0章 0.4)。欠落はコンパイル時エラーとする。
- 単位名はプログラム内で一意とする。
- 単位の外との相互作用は、constraint に宣言された公開面を通る通信のみである(通信は第3章)。
  単位を跨ぐ直接呼び出し・共有メモリは存在しない。

## 1.2 第一層: 意図(intent)

検証不能な理由の記録。形式は ADR 0003 に従う。

```plaintext
intent {
  why      "<なぜこの境界で切るか。この単位は何の知識を隠すか>"
  rejected option "<検討して捨てた選択肢>"
           reason "<なぜ捨てたか>"
  change   "<将来どんな変化を想定するか。この単位はそれをどう吸収するか>"
  refs     "<意図の理解を助ける外部資料>"     # 任意
}
```

- why・rejected・change は必須、refs は任意。
- rejected は(選択肢, 理由)の組を1件以上書く。棄却の対象は、この単位の境界を決めた判断の全て(分割方法・実装方式のどちらも可)。
  検討の結果、捨てた選択肢が存在しなかった場合のみ `rejected none "<選択肢がなかった理由>"` と明示できる。
- 記述の検証(エラー E1〜E2・警告 W1〜W2)は第2章 2.3 に一覧する。内容の意味的な正しさは機械検証しない。

## 1.3 第二層: 制約(constraint)

検証可能な意図。コンパイラ・実行系が違反を拒否する。語彙と検証時期の一覧は第2章に置く。

```plaintext
constraint {
  depends    <単位名の列挙 | なし>       # 通信してよい相手
  expose     <公開面の宣言>              # ask の受け口 / flow の出入り(第2章 2.2)
  idempotent <公開面名>                  # 再実行が二重の効果を持たない
  isolate    failure                     # 障害を外へ伝播させない
  state      <状態名> volatile | recoverable(<復元元>)   # 状態の再起動時の扱い
  layers     { <階層名> { pure | io } ... }   # 内部階層(1.4)
}
```

## 1.4 第三層: 実装(body)と内部階層

単位の内側は原則自由である(ミュータブル・例外可)。言語が管轄するのは外側との通信のみ。

内部に階層を設ける場合は ADR 0005 に従う。

- 階層の名前と数は自由(domain / driver、planning / codec など、単位の文脈に合った名前を付ける)。
- 制約強度は固定の2種から選ぶ。

| 強度 | 意味                                                  |
| ---- | ----------------------------------------------------- |
| pure | 純粋。IO 不可・外部状態への依存不可。決定的な計算のみ |
| io   | 自由。IO・可変状態を許す(単位の内側の原則通り)        |

- pure 層は io 層に依存できない。環境依存値(現在時刻・乱数・設定)は io 層が取得し、値として pure 層へ注入する。
- 階層を宣言しない単位は body 全体が io とみなされる。

## 1.5 粒度の指針

**1単位 = 隠す設計判断が1つ**(ADR 0006)。判定には intent の why を使う。

- why が1文で書けない(「〜し、かつ〜する」)→ 分割を検討する。
- why が隠す知識を挙げられない(公開面が素通しの委譲だけ、親単位の why の言い換え)→ 統合を検討する。

この指針は機械検証しない。担保はレビューと思考実験に置く。
