# Shidzuku 言語仕様書 — 第6章 データと型

- 状態: Draft
- 日付: 2026-08-29(新設: ADR 0009・0010・0017・0019・0020 の採用に伴う。改訂 2026-09-16: ADR 0021 の採用により 6.2 の基本型と 6.3 の数値型を確定した)
- 依拠: 第0章 0.5、第2章 2.3、第5章、ADR 0008・0009・0013・0014・0019・0020・0021(いずれも採用)

データはコンポーネントの外側を流れる語彙である。段に属さず段を跨ぐため、本章は段の順の後ろに置く(第4章・第5章と同じ立場。ADR 0015 決定6)。

## 6.1 データの宣言

公開面(`expose`)と `flow` の内容を流れるデータは、コンポーネント・フローと並ぶ**トップレベルの `data` 宣言**で定義する(ADR 0009)。

``` plaintext
data <名前> { <欄名>: <型>, ... }          # 直積(レコード)
data <名前> = <区分>(<型>) | <区分> | ...  # 直和(選択)
data <名前> (id)                           # 識別子型
list<<型>>                                 # 列
```

- **名前的型付け**である。構造が同じでも名前が違えば別型とする。受注番号と受付ID は中身が同じでも、取り違えはコンパイル時エラー(E0009-1)となりコンパイルできない。
- **型引数を持つのは `list` だけ**である。継承は持たない。階層が要る形は直和で書く。
- **「無い」は直和で明示する。** `null` は存在しない。欠損・不在は `見つかった(値) | なし` のように区分で書く。
  これは省略の禁止(第0章 0.5)の型への適用である。
  **不在の区分名は、何が無いのかを言う。** `欠損`(計測が取れなかった)・`暦の外`(その暦では呼べない)・`訳なし`(訳文が無い)のように、
  不在の理由が名前に出る。言語が単一の `なし` を持たないのは、不在の意味が文脈ごとに違うためである。
- **データとして正常な「なし」と、系の失敗(期限超過・相手障害)は別の語彙とする。** 後者の体系は U13 で定める。
- **`data` に intent は課さない。** データ形状の設計判断は、それを公開面に持つコンポーネント・フローの intent に宿る(ADR 0003 の教訓)。
- **body 内部の型は自由である。** `data` はコンポーネント間の語彙のみを対象とし、DB スキーマ等の内部表現は隠されたままとなる(内側の原則。第2章 2.4)。
- 接続の両端で型が一致しない場合はコンパイル時エラー(E0009-1)。公開面が参照する `data` の変更は W0003-2 の対象に含める。

## 6.2 基本型 — 11 種

言語が持つ基本型は次の11である(ADR 0019 決定1、ADR 0021 が数値の行を確定した)。

| 基本型         | 綴り                 | 欄                 | 内容                                     | 節  |
| -------------- | -------------------- | ------------------ | ---------------------------------------- | --- |
| `論理`         | `bool`               | 無い               | 条件の値。**body 内にのみ置ける**        | 6.2 |
| 整数           | `int8`〜`int256`     | 位取りと単位が必須 | 幅が上限を、位取りが刻みを決める         | 6.3 |
| 整数(符号なし) | `uint8`〜`uint256`   | 位取りと単位が必須 | 同上。負にならない値                     | 6.3 |
| 浮動小数点     | `float32`・`float64` | 単位が必須         | IEEE 754 binary32 / binary64             | 6.3 |
| 十進数         | `dec(i.f)`           | 位取りと単位が必須 | 桁が上限、格納は可変長。**内部計算のみ** | 6.3 |
| `テキスト`     | `text`               | 無い               | 値としての自然言語。正準形を持たない     | 6.2 |
| `バイト列`     | `bytes`              | 無い               | 不透明な媒体・外部表現                   | 6.2 |
| `時点`         | `instant`            | 無い               | 壁時計の一点。UTC のエポック起点         | 6.4 |
| `日付`         | `date`               | **暦が必須**       | 暦上の日。紀元前から                     | 6.4 |
| `時刻`         | `clock`              | 無い               | 1日の中の時計の読み。日を持たない        | 6.4 |
| `時間帯`       | `zone`               | 無い               | どこの時計で読むか。IANA の地帯名        | 6.4 |

識別子型(`id`)は基本型ではなく**宣言の形**である(6.1)。**暦**は型ではなく `日付` の欄である(6.4)。

**選択のある欄に省略時の既定は無い**(第0章 0.5、E0008-1)。単位を持たない事は `none` と、暦は `グレゴリオ暦` のように、必ず書く。
欄を**持たない**型(`論理`・`時点`・`時刻`・`時間帯`、および `float` の位取り)にその欄が無い事は E0008-1 ではない。

### 論理 — 条件の値であり、データの語彙ではない

``` plaintext
論理        # 値は 真 と 偽 の2つ。演算は かつ・または・でない と比較の結果
```

**`data` の欄・公開面の引数と応答・`flow` の内容・`state` に論理型は書けない**(E0019-1)。そこには名前の付いた直和を書く。
**型の入れ子の中も同じである**——`list<論理>` も `data 結果 = 成否(論理)` も E0019-1 とする。禁じるのは場所ではなく、
**コンポーネントの外へ論理が出る事**である。

``` plaintext
expose 在庫確認(品目ID) -> 論理                  # 書けない。真が何を意味するかが型に無い
expose 在庫確認(品目ID) -> 在庫あり | 在庫なし   # これを書く
```

2値の直和は実行時表現が同じであり、失うものが1つも無い。得るのは名前だけであり、**名前は公開面の語彙の全てである**。
テキストは条件になれず(E0013-1)、論理はデータになれない——この対が第0章 0.5 の「名前で語る」を型の側から支えている。
3値論理は無い。「不明」は直和で書く。

### テキストとバイト列 — 不透明な値

``` plaintext
テキスト    # 値としての自然言語。(ロケール, 正規化形, 内容) の三つ組
バイト列    # 外部表現の運搬。中身の解釈は parse の役割を持つ層が行う
```

- テキストは**正準形を持たない**ため、素の等値比較・ハッシュ・キー利用ができない(E0013-1)。
  一般規則として、**ハッシュ可能なのは正準形が一意に定まる型だけ**である——識別子型・直和の区分・整数・時点・日付はこれを満たす。
- テキストへの構造的操作(部分取得・分割・パターン照合・連結・長さ・添字)は、役割を宣言した層に閉じる(E0013-2)。
  詳細は ADR 0013 と第2章 2.4 の役割の表による。
- 識別子・日時・パス・URL・通貨・電話番号・区分コード・版は、テキストではなく専用の型(識別子型・時間の型・直和・数値型)で表す。

## 6.3 数値型 — 4種と、量と単位

### 4つの数値型

| 型             | 綴り                     | 欄                 | 上限を決めるもの | 格納       | 書ける場所                  |
| -------------- | ------------------------ | ------------------ | ---------------- | ---------- | --------------------------- |
| 整数(符号付き) | `int8` 〜 `int256`       | 位取りと単位が必須 | 幅               | 固定       | どこでも                    |
| 整数(符号なし) | `uint8` 〜 `uint256`     | 位取りと単位が必須 | 幅               | 固定       | どこでも                    |
| 浮動小数点     | `float32`・`float64`     | 単位が必須         | 幅               | 固定       | どこでも                    |
| 十進数         | `dec(<整数部>.<小数部>)` | 位取りと単位が必須 | 宣言した桁       | **可変長** | **body の式と局所の値だけ** |

``` plaintext
int64(2) 円         # 金額。刻み 0.01 円、上限 ±約 9.2 京
int64(0) none       # 個数・版・連番
uint64(0) none      # 列の添字・長さ
int64(0) ナノ秒     # 時間の量(±約 292 年)
int64(4) none       # 税率(0.1000 = 10%)
uint8(0) none       # バイトの値
float64 メートル    # 測った長さ
dec(18.2) 円        # 中間計算(body の中だけ)
```

**幅が上限を、位取り(小数点以下の桁数)が刻みを決める。** 幅は 8/16/32/64/128/256 の6種である。

| 型          | 刻み   | 値の範囲    | 主な用途                   |
| ----------- | ------ | ----------- | -------------------------- |
| `uint8(0)`  | 1      | 0 〜 255    | バイト・小さな符号なしの値 |
| `int32(0)`  | 1      | ±約 21 億   | 個数・外部の 32 ビット整数 |
| `int64(0)`  | 1      | ±約 922 京  | 添字・連番・時間の量       |
| `int64(2)`  | 0.01   | ±約 9.2 京  | 金額                       |
| `int64(4)`  | 0.0001 | ±約 92 兆   | 税率・利率                 |
| `int128(2)` | 0.01   | ±約 1.7e36  | 桁の大きい金額・中間結果   |
| `int256(0)` | 1      | ±約 5.79e76 | 暗号・分散台帳             |

**既定の数値型は置かない。** 型名も幅も位取りも単位の欄も、必ず書く(第0章 0.5、E0008-1)。言語は数値型に序列を置かない。

判断の基準は次の4つである。

| 問い               | 答え                                                                 |
| ------------------ | -------------------------------------------------------------------- |
| 厳密か、測った値か | 厳密なら `int`/`uint`、測った値なら `float`                          |
| 刻みはいくつか     | 位取り(金額は 2、税率は 4、数えるなら 0)                             |
| 上限はいくつか     | 幅(業務の上限ではなく、**器として足りる幅**を選ぶ。迷ったら `int64`) |
| 負になり得るか     | なるなら `int`、ならないなら `uint`(差を取るなら `int`)              |

### 整数 — `intN(s)`・`uintN(s)`

``` plaintext
int64(2) 円
```

- 値は `m × 10^-s` である。`m` は幅 N の2進整数(符号付きは2の補数)であり、**位取り `s` は型情報のみ**で実行時の値には現れない。
- **演算は小数部倍した整数で行う。** 誤差の出る場所は3つに限る——除算・粗い単位への換算・位取りを粗くする受け渡し。
- **同じ幅・同じ符号の型どうしは演算できる。** 位取りと単位は規則で決まり、書き手は揃えなくてよい。

  | 演算                                 | 結果の位取り | 結果の幅   | 失敗し得る所                     |
  | ------------------------------------ | ------------ | ---------- | -------------------------------- |
  | `a + b` / `a - b`                    | 細かい方     | 同じ       | 位取りを揃える所と、和差の範囲外 |
  | `a × b`                              | 両辺の和     | 同じ       | 積の範囲外                       |
  | `分ける(a, b)`(商と余り)             | `a` と同じ   | 同じ       | `b` が 0                         |
  | `合算(列)`                           | 要素と同じ   | 同じ       | 途中の範囲外                     |
  | `割る(a, b, <型>, 丸め <方式>)`      | 宣言した型   | 宣言した型 | 範囲外・`b` が 0                 |
  | `丸める(a, <型>, 丸め <方式>)`       | 宣言した型   | 宣言した型 | 範囲外                           |
  | `換算(a, <単位>, <型>, 丸め <方式>)` | 宣言した型   | 宣言した型 | 範囲外                           |

- **桁溢れはラップもトラップもせず、失敗とする**(U13)。検査は**演算ごと**に行う——幅が有限で中間が広がらないためである。
- **乗算は位取りが和になる。** 元の型に戻すには `丸める` を書く(`int64(2) × int64(4)` は `int64(6)`)。
- **加算は位取りの細かい方へ揃える。** 揃える所でも溢れ得る(`int64(0) 円 + int64(2) 円` は前者の `m` を 100 倍する)。
- **除算の演算子は持たない。** `割る(<被除数>, <除数>, <結果の型>, 丸め <方式>)` と `分ける(a, b)` だけとする。
  整数の `/` が切り捨てになる事は宣言されていない丸めであり、この言語では起きない。
- 列の添字・長さ・繰り返し回数は `uint64(0) none` に限る(E0019-4)。負にならない事を型に出す。

### 浮動小数点 — `float32`・`float64`

``` plaintext
float64 メートル
```

- 位取りの欄を**持たない**。刻みが値の大きさで変わるため、書いても情報が増えない(`float64(2)` は E0021-2)。
- 四則の演算子 `+ - × ÷` と `平方根`・`累乗` を持ち、丸めの宣言を要さない。`割る(…)` は持たない——常に丸まるため、丸めの欄が意味を持たないからである。
- **意味は IEEE 754 に厳密に従う。** `float32` は binary32、`float64` は binary64。丸めは最近接偶数に固定し、
  FMA への融合・再結合・拡張精度での中間保持・近似逆数/平方根・代数的な書き換えを**禁じる**。
  超越関数は正しく丸めた結果を返す事を要求し、満たせない関数は語彙に入れない。列の合算・畳み込みは先頭から順に行う。
  これにより、どのノード・どの出力先でも結果は同一になる(ADR 0001 の前提)。
- **NaN・±∞・-0 を値として持たない。** これらを生む演算(0 除算・負数の平方根・`∞ − ∞`・桁溢れ)は失敗とする(U13)。
  検査は**値が名前を得る所**(`data` の欄・公開面・`state` への受け渡し)で行い、式の途中では行わない。`-0` はそこで `+0` に正規化する。
  アンダーフローは失敗にしない。結果として比較は全順序であり、`NaN ≠ NaN` は起きない。
- **`float128`(四倍精度)は持たない。** x86-64 と AArch64 は命令セットに規定が無く必ずソフトウェア実装になり、
  トランスパイル先(Rust の `f128` は実験的 API、TypeScript には無い)も安定して持たないためである(ADR 0021 決定8)。`float16` も同じ理由で持たない。

### 十進数 — `dec(<整数部>.<小数部>)`(内部計算のみ)

``` plaintext
dec(9.4) 円          # 整数部9桁・小数部4桁。±999,999,999.9999
dec(18.2) 円         # int64(2) の値を受けられる桁
```

- 演算は小数部倍した整数で行う(`int`/`uint` と同じ)。**格納は値による可変長**である。
- **宣言した桁は上界であり、可変長は表現の最適化である。** この2つは矛盾しない。

  | 何を決めるか         | 決めるもの     | 効く場面                             |
  | -------------------- | -------------- | ------------------------------------ |
  | 値の上限と刻み(意味) | **宣言した桁** | 検査・記憶域の見積り・実行時間の上界 |
  | 実際に使うバイト数   | **値の大きさ** | 実行時の記憶域                       |

  `dec(9.4)` は 13 桁 = 最大 6 バイトと静的に見積もれ、実際の値が小さければ1ワードで足りる。
- **中間の桁は自動で広がり、検査は値が名前を得る所で行う。** 加算は整数部が大きい方 + 1、乗算は整数部・小数部とも和である。
  式の途中では溢れず、受ける所で宣言桁と照合して、超えていれば失敗とする。`合算(列)` もそのまま書ける。
- **`dec` は内部計算のみに使える**(E0021-4)。

  | 場所                               | `dec`    | 理由                                                           |
  | ---------------------------------- | -------- | -------------------------------------------------------------- |
  | body の式・局所の値                | 書ける   | 中間計算がこの型の用途である                                   |
  | `data` の欄・公開面・`flow` の内容 | 書けない | コンポーネントを跨ぐ値は、受け手が記憶域を見積もれる必要がある |
  | 外部との詰め替え(`復号`・`符号化`) | 書けない | 外部形式は幅で定義されている                                   |
  | `state`                            | 書けない | 状態の大きさは配置単位(障害境界)の資源に直結する               |

- 書き方は「**持ち上げて・計算して・収める**」の3段になる。

  ``` plaintext
  素   = 変換(小計, dec(18.2)) × 変換(税率, dec(1.4))   # dec(19.6) 円。中間では溢れない
  税額 = 収める(素, int64(2), 丸め 切り捨て)             # 名前を得る所で int へ戻す
  ```

### 数値型は暗黙に混ざらない

**暗黙の変換は1本も無い。** 幅・符号・`int`/`float`/`dec` の別を跨ぐには、必ず変換を書く(E0019-3・E0021-3)。
無損失な向き(`int32(0)` → `int64(0)`)も例外にしない——幅が 12 通りある以上、どちらへ寄るかの表を書き手に覚えさせないためである。

| 変換                             | 語彙                                | 丸めの宣言       | 失敗             |
| -------------------------------- | ----------------------------------- | ---------------- | ---------------- |
| 幅・符号を変える / `int` → `dec` | `変換(値, <型>)`                    | 不要             | 範囲外           |
| 位取りを粗くする                 | `丸める(値, <型>, 丸め <方式>)`     | 必須             | 範囲外           |
| `dec` → `int`/`uint`             | `収める(値, <型>, 丸め <方式>)`     | 粗くするなら必須 | 整数部が入らない |
| `int`/`uint`/`dec` → `float`     | `近似する(値, <型>)`                | 不要             | 桁溢れ時のみ     |
| `float` → `int`/`uint`/`dec`     | `厳密にする(値, <型>, 丸め <方式>)` | 必須             | 範囲外           |

**変換の前後で単位は保たれる。** 量の検査は変換を跨いで効く。

### 外部との詰め替え

``` plaintext
受信値 = 復号(受信, int32(0), ビッグエンディアン)     # int32(0) none
応答   = 符号化(変換(値, int32(0)), ビッグエンディアン)
```

- **幅は型が言うため、詰め替えに書くのはバイト順だけ**である。8 ビット幅にバイト順の欄は無い。
- 詰め替えは **`boundary` の役割でのみ書ける**(E0021-1)。外部形式の知識が領域層へ漏れない。
- 復号した値は `none` である。単位を付けるのは `単位を付ける`(body 内でのみ書ける操作)。

### 丸めの語彙 — 既定は無い

丸めが起きる場所では必ず選ぶ。

| 方式     | 意味                         |
| -------- | ---------------------------- |
| 切り捨て | 零へ向かう(絶対値が減る)     |
| 切り上げ | 零から離れる(絶対値が増える) |
| 床       | 負へ向かう                   |
| 天井     | 正へ向かう                   |
| 四捨五入 | 半数は零から離れる方へ       |
| 銀行丸め | 半数は偶数側へ               |

循環小数(1/3)・無理数(√2・π)は書けない。丸めの宣言を伴う演算としてのみ扱う。
**繰り返しの中の丸めは累積する。** 合算する状態は、足し込む値の刻みより細かい位取りで持つ(W0010-2)。

### 量と単位

``` plaintext
量   長さ 基準 メートル
単位 センチメートル : 長さ = メートル × 1/100
単位 インチ         : 長さ = メートル × 127/5000
量   通貨 基準 なし                                    # 換算比を持たない量
量   時間 基準 秒                                      # 言語が最初から持つ量
```

- **量**は加減算・比較の可否を決める。異なる量の加減算・比較はコンパイル時エラー(E0010-1)。
- **単位**は量に属し、基準単位に対する比で定義する。**比は必ず有理数(整数の分子/分母)で書く。**
- **換算比を持たない量**(`基準 なし`)を認める。通貨と温度がこれにあたり、単位を跨ぐ演算・換算はエラー(E0010-2)。変換は body の仕事になる。
- **組立の量は宣言されたものだけが存在する**(E0010-5)。無名の量は作らない。
- **単位の欄は省略できない。** 単位を持たない事は `none` と明示する。これは単位を持つ事を必須にするものではない。
- 単位は**型情報のみ**であり、実行時コストはゼロである。
- 換算誤差は消せない。**隠さず・累積させず・上限を設計者が決める**の3点で扱う——比は既約の有理数で保持し、連鎖換算をせず、
  掛けてから割り、結果の桁を宣言させ、換算先の分解能を換算元より細かく取り(W0010-1)、境界で1回だけ換算し、比較は換算しない。
- 比で書けない変換(℉→℃ 等)のために `単位を外す(値)`・`単位を付ける(値, 単位)` を持つ。**body 内でのみ書ける。**
- **`量 時間` は言語が最初から持つ**(ADR 0019 決定6)。時間の長さは `int64(0) ミリ秒`・`float64 秒`・`int64(3) 秒` のように数値型と単位で書き、
  `時間量` という基本型は置かない。単位は ナノ秒・マイクロ秒・ミリ秒・秒・分・時・日である。
  **「月」「年」は単位にしない**——1 か月は 28〜31 日であり固定の比を持たない。

## 6.4 時間の型 — 時間軸と暦を分ける

時間は3つの層に分かれ、型がその層を告げる。

| 層       | 型                  | 何を表すか           |
| -------- | ------------------- | -------------------- |
| 時間軸   | `時点`              | いつ起きたか         |
| 暦       | `日付 <暦>`・`時刻` | 暦と時計に何と書くか |
| 読む場所 | `時間帯`            | どこの時計で読むか   |

### 時点 — 壁時計の一点

``` plaintext
時点        # UTC のエポック(1970-01-01T00:00:00Z)を原点とする時間軸上の一点
```

- **表せる範囲は仕様が定める**(内部表現は実装に委ねる。整数で保持すればよい)。範囲は `1677-09-21T00:12:43.145224192Z` 〜 `2262-04-11T23:47:16.854775807Z`(範囲外は失敗)。
- **暦・時間帯・書式を持たない。**
- **うるう秒を持たない。1 日は常に 86400 秒とする。** うるう秒表を持つと `時点 + 量 時間` が表の版に依存し、
  分散したノードで表が食い違えば同じ入力から違う状態へ遷移する(ADR 0001 の前提が壊れる)。

  | 演算                                              | 結果                              | 備考                     |
  | ------------------------------------------------- | --------------------------------- | ------------------------ |
  | `時点 + <量 時間 の値>` / `時点 - <量 時間 の値>` | `時点`                            | 範囲外は失敗             |
  | `時点` どうしの比較                               | `論理`                            | 記録された壁時計の値の順 |
  | `隔たり(<始め>, <終わり>, <単位>, 丸め <方式>)`   | 直和(`int64(0) <単位>` か `逆行`) | 減算演算子は置かない     |

- **`時点 - 時点` は持たない**(E0019-2)。壁時計は巻き戻る(NTP の補正・仮想機の停止)ため差が負になり得る。
  差は `隔たり` で書き、`逆行` を直和で受ける。結果の単位と丸めを宣言させるのは、ナノ秒固定では最大の隔たり(584 年)が整数の範囲を出るためである。
- **期限(`deadline`)と経過時間の測定に `時点` を使えない**(E0019-2)。期限は `量 時間` の値でのみ宣言し、測るのは動作環境の仕事とする。
- **順序比較は「記録された壁時計の値の順」であって「起きた順」ではない。** 因果の順序が要るなら単調増加の版(`uint64(0) none`)を使う。
- 現在の時点の取得は io の強度を持つ層に限る(第2章 2.4)。

### 日付 — 暦の欄を持つ

``` plaintext
日付 <暦>        # 例: 日付 グレゴリオ暦・日付 ユリウス暦・日付 和暦
```

- **暦は型の欄であり、省略できない。** 単位が数値の欄であるのと同じ形であり、実行時の表現には現れない。
- **年は天文学的年番号の整数**とする。`0` が紀元前1年、`-1` が紀元前2年、`-9999` が紀元前10000年である。
  紀元(BC / AD)の欄は持たない——欄を分けると年の比較と減算が欄をまたいで分岐する。
- **範囲は日番号で定める。** エポック日(1970-01-01)から `-4371587` 日 〜 `2932896` 日(範囲外は失敗)。
  グレゴリオ暦では `-9999-01-01` 〜 `9999-12-31` にあたる。**範囲は仕様が定め、内部表現は実装に委ねる。**
- 演算は `日を足す(日付, <int64(0) 日>)`・比較・`日数(始め, 終わり) -> int64(0) 日`・`換算(日付, <暦>)`・`曜日(日付)` の5つ。
  **月と年の加算は持たない**——「1 か月後」は末日の扱いを決めない限り書けず、その規則は言語ではなく設計判断である。
- **`曜日(日付) -> 月 | 火 | 水 | 木 | 金 | 土 | 日` は暦に依らない。** 曜日は日番号を 7 で割った余りで決まり、
  グレゴリオ暦の改暦(1582-10-04 の翌日が 1582-10-15)でも並びは途切れていない。

### 暦 — 3つの種

線は「表が要るか」ではなく、**表がどこから来るか**で引く(ADR 0020)。

| 種     | 誰が持つか       | 例                                       | 換算の性質       |
| ------ | ---------------- | ---------------------------------------- | ---------------- |
| 算術暦 | **言語**         | グレゴリオ暦・ユリウス暦                 | 厳密・全域       |
| 紀年法 | **書き手が宣言** | 和暦・仏暦・民国紀元・皇紀               | 厳密・**部分的** |
| 表暦   | **持たない**     | ウンム・アルクラー暦・天保暦・ヘブライ暦 | —                |

ソースの中にある表はプログラムの一部であり、分散したノードで食い違わない。実行環境から来る表は食い違う。

``` plaintext
暦 和暦 : グレゴリオ暦 の紀年法 {
  紀元 明治 : 1873-01-01 から 6 年
  紀元 大正 : 1912-07-30 から 1 年
  紀元 昭和 : 1926-12-25 から 1 年
  紀元 平成 : 1989-01-08 から 1 年
  紀元 令和 : 2019-05-01 から 1 年
}

暦 仏暦 : グレゴリオ暦 の紀年法 { 紀元 仏滅紀元 : 0001-01-01 から 544 年 }
```

- **紀年法は月日を変えない。** 変わるのは年の呼び方だけであり、必要な宣言は改元日の一覧だけである。
- 年番号は基準の暦の年が変わる所で 1 増える(昭和元年は 1926-12-25 から 12-31 までの7日間)。
- `から <年番号> 年` はその紀元が始まる年番号を書く。和暦の `明治 : 1873-01-01 から 6 年` は
  **明治5年以前が太陰太陽暦(天保暦)であり紀年法では書けない**という事実を、宣言がそのまま表す。
- 基準は算術暦に限る(E0020-3)。紀年法の入れ子は持たない。
- 起点は単調増加でなければならない(E0020-1)。

**換算は厳密なまま、全域でなくなる。**

| 換算            | 厳密か | 全域か                       |
| --------------- | ------ | ---------------------------- |
| 算術暦 ↔ 算術暦 | 厳密   | 全域                         |
| 算術暦 ↔ 紀年法 | 厳密   | **部分的**(表の外がある)     |
| 紀年法 ↔ 紀年法 | 厳密   | **部分的**(両方の表の中のみ) |

紀年法が絡む `換算` の結果は直和 `日付 <紀年法> | 暦の外` とし、呼び手が扱う(E0020-2)。
`暦の外` はデータとして正常な不在であり、系の失敗ではない。

**改元はプログラムの変更である。** 宣言を1行足す事は公開面の変更(W0003-2)であり、差分に現れレビューを通る。
表の最後の紀元に終わりが無い状態で未来の日付を換算していると警告(W0020-1)。

### 時刻 — 1日の中の時計の読み

``` plaintext
時刻        # 00:00:00.000000000 〜 23:59:59.999999999
```

- **範囲は1日の中の時計の読みであり、内部表現は実装に委ねる。**うるう秒を持たないため、この対応は例外なく一対一である。
- **日付・暦・時間帯を持たない。** 「毎日 09:00 開店」「締切は 17:00」は日を持たない値である。
- 演算は比較・等価と、**`時計を進める(時刻, <量 時間 の値>) -> (時刻, int64(0) 日)`**。

  ``` plaintext
  時計を進める(09:00, 480 分)  ->  (17:00, 0 日)
  時計を進める(23:00, 3 時)    ->  (02:00, 1 日)
  ```

  文字盤の上の加算であり、時間軸の加算ではない。**繰り上がった日数を必ず返す**ため、黙って巻き戻らない。
- **時計の読みは、それだけでは場所が決まらない。** `09:00` はどこの時計の 09:00 かを持たない(単位を持たない `none` と同じ形)。
  **指針**: 時計の読みを持つ `data` は、同じ直積の中にその時計の持ち主(拠点・`時間帯`)を持つ。

### 時間帯 — どこの時計で読むか

``` plaintext
時間帯        # IANA tz database の地帯名(Asia/Tokyo・UTC)
```

ログ行の `2026-08-29T14:30:00+09:00` は、**2つの値が混ざった外部表現**である。

``` plaintext
data ログ記録 { 起きた: 時点, 記録地: 時間帯, 内容: 事象 }
```

- **他の時間帯への「変換」は、時間帯の欄を差し替えるだけである。`時点` は動かない。変換ではなく読み替えである。**
- 時間帯は `日付`・`時刻` の欄にはしない。暦は設計判断だが、時間帯は実行時のデータであり行ごとに違い得る。
- オフセット(`+09:00`)は基本型にせず `量 時間` の値で書く。ただしオフセットはその1点の読みしか持たず、他の時間帯へ読み替えられない。
- 値の出所は動作環境であり、io の強度を持つ層が取得して注入する(第2章 2.4)。

### 時間軸と暦のあいだの変換

| 変換                                   | 結果                                         | 曖昧さ                               |
| -------------------------------------- | -------------------------------------------- | ------------------------------------ |
| `暦で読む(<時点>, <時間帯>, <暦>)`     | (`日付 <暦>`, `時刻`)                        | なし(時間軸から暦へは常に決まる)     |
| `時点にする(<日付>, <時刻>, <時間帯>)` | `時点 \| 存在しない \| 二度ある(時点, 時点)` | 夏時間で存在しない時刻・二度ある時刻 |

- **変換は `boundary` または `format` の役割を持つ層でのみ書ける**(E0019-5)。`domain` は暦も時間帯も知らない。
- **tzdata の版依存は、合意の外に閉じ込められる。** 状態・記録・比較・順序は全て `時点` の上で行い、
  時間帯が要るのは暦の読みへ移す時だけである。版が食い違えば表示がずれるが、複製された状態機械は割れない。
- **時間帯で変換した結果をそのまま `state`・`data` に持つと警告(W0019-3)。** ただし**業務規則が決めた暦の値**
  (就業規則が定める勤務日・締め日・営業日)は対象外である。前者は版で変わり得るが、後者は変わらない。
- **暦の上に時間軸の加算を持ち込まない。**(`日付`, `時刻`)の組を1つの時点のように扱って `量 時間` を足す事はできない(E0019-6)。

  | 書きたい事                            | 書き方                                                    |
  | ------------------------------------- | --------------------------------------------------------- |
  | 翌日の同じ時刻(暦の操作)              | `日を足す(日, 1)`。`時刻` はそのまま                      |
  | 09:00 から 8 時間の終わり(文字盤の上) | `時計を進める(09:00, 480 分)`。繰り上がりも受ける         |
  | 3時間後(時間軸の操作)                 | `時点にする` → `時点 + 3 時` → 必要なら `暦で読む` で戻す |

  「2026-03-08 02:30 の3時間後」は時間帯が分からなければ答えが決まらない。**畳まず、時間帯を要求する変換の側へ寄せる。**

## 6.5 型が告げる事

型の名前が、値の出どころを告げる。これが「運用で驚きがない」(第0章 0.5)の型の側からの支えである。

| 型                    | 名前が告げている事                                                     |
| --------------------- | ---------------------------------------------------------------------- |
| `intN(s)`・`uintN(s)` | 厳密である。刻みは位取りが、上限は幅が言う                             |
| `floatN`              | 近似である                                                             |
| `dec(i.f)`            | 厳密で、中間計算のためにある(コンポーネントを跨がない)                 |
| `時点`                | 壁時計の読みである。巻き戻り得るし、経過時間には使えない               |
| `日付`                | 暦の上の日である。時間軸上の点ではなく、どの暦で呼ぶかは欄に書いてある |
| `時刻`                | 時計の読みである。どの日かは持たない                                   |
| `時間帯`              | どこの時計で読むかである。いつ起きたかは持たない                       |
| `論理`                | 条件の値である。データの語彙ではない                                   |

黙って壊れる物——切り捨てられる整数除算、巻き戻る時計の差、意味の無い真、うるう秒表に依存する加算、
時間帯を隠した日時——は、どれも型か検証で表に出す。

## 6.6 未定事項(Phase 1 以降で決める)

- **`data`・`量`・`単位`・`暦` の宣言の置き場所の最終形**(U14)。いずれもトップレベルの宣言だが、`contains` には現れない。
  内側のシステムだけが使う量や暦をどこに書くか、**直和の区分名がどの名前空間に属するか**(`data` の中に閉じるのか、トップレベルに出るのか)を含めて定める。
  現在は1プログラム内を範囲とする(第5章 5.5)。
- **中間結果の幅を助ける手段**。`変換(a, dec(18.2))` を挟む場面が続くようなら、書き方を検討する(思考実験 18 の論点4)。
- **値域の宣言**(`int64(2) 円 範囲 0..999999999`)。幅では表せない業務上の上限を書く案。
- **失敗の体系**(U13)。桁溢れ(演算ごと)・0 除算・特殊値を生む演算・`dec` が宣言桁を超える事・`時点` と `日付` の範囲外は、いずれも失敗である。
  ドメインの失敗(在庫不足)・データとして正常な不在(`なし`・`暦の外`)との切り分けを含めて U13 で定める。
- **外部世界との境界**(U12)。外部の時刻表現(ISO 8601 の文字列・Unix 秒・DB の `TIMESTAMP`)を `時点` と `時間帯` に分解する規則、
  動作環境が tzdata を供給する形、**解決できない地帯名を受け取った時の扱い**(地帯の廃止・改名を含む)。
- **書けない暦**。イスラム暦(タブラー暦法は算術だが紀年法ではなく、閏年の配置に流派が複数ある)、
  ウンム・アルクラー暦と観測ベース(版を持つ表)、太陰太陽暦。**書けないと認める**(ADR 0020 決定6)。
  算術暦を書き手が宣言する仕組みは、必要が確認されてから設計する。
- **月・年の加算**。末日の扱いを宣言させる形が候補である。
- **対応表(map)・集合(set)**。公開面に現れる例が出たら再検討する。キーは正準形が一意に定まる型に限る。
- **単調時点**。Phase 2 の動作環境で、経過時間をコンポーネントの記述に持ち込む必要が確認されたら足す。
- **`float128`・`float16` の追加**。出力先(Rust の `f128` の安定化等)が持ち、必要が確認された時点で再検討する(ADR 0021 決定8)。
