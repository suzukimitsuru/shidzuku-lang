# compiler — Shidzuku のコンパイラ

[全体](../docs/PLAN.md) › compiler

- 状態: 細い縦の試作の範囲を読む(2026-11-07)
- 実装の言語: Rust。動作環境が Rust であり、正準形の扱いと検証の規則の一覧を共有できる(計画書 第4節「Phase 1 の中で決める物」の推奨の通り。候補を比べていないので ADR は起こしていない)

記述(`.shidzuku`)を字句・構文・検証の順に通し、通った記述から Rust を生成する。

| ファイル                       | 役目                                                                                                        |
| ------------------------------ | ----------------------------------------------------------------------------------------------------------- |
| [src/lexer.rs](src/lexer.rs)   | 字句。UTF-8 と改行の LF(line feed。第5章 5.2)。行末の CR(carriage return)と全角空白は E0014-1(使えない文字) |
| [src/parser.rs](src/parser.rs) | 構文。欠けた宣言も読み、欠落の報告は検証器に任せる                                                          |
| [src/check.rs](src/check.rs)   | 検証器                                                                                                      |
| [src/rust.rs](src/rust.rs)     | Rust の生成器。生成の前に名前を解決する                                                                     |
| [src/main.rs](src/main.rs)     | `shidzuku` コマンド                                                                                         |

## 使い方

```sh
cargo run -p shidzuku-compiler -- check <記述>          # 検証だけ
cargo run -p shidzuku-compiler -- rust <記述> -o <出力> # Rust を生成する
```

試作の例は `build.rs` からライブラリとして呼び、ビルドのたびに生成する([examples/細い縦の試作](../examples/細い縦の試作/README.md))。

## 読む範囲(細い縦の試作)

- `system`・`component`・`intent`・`constraint`・`flow` を読む。`body` は中を読まずに読み飛ばす(body は出力言語で直に書く。計画書 第4節「仮置き」)
- データ宣言は `id`・`quantity`・`record` を読む。型は `instant`・`float32`・`float64`・`intN(位取り) 単位`・`uintN(位取り) 単位` と、宣言した名前
- 公開面は `flow in`・`flow out` だけを読む。`ask`・`correlate`・`on expiry`・`on failure` の `at` と `restart` 以外の行は、扱わない事を報告して止まる

## 検証器が見る物

省略の禁止(ADR 0008)のうち、計画書 第4節の範囲だけを見る。

| 見る物                                      | 検証番号                                                                 |
| ------------------------------------------- | ------------------------------------------------------------------------ |
| `system` の intent と constraint            | E0015-1                                                                  |
| `component` の三層                          | E0000-1                                                                  |
| `intent` の why・change と、rejected の組   | E0003-1・E0003-2                                                         |
| `flow` の `intent`                          | E0003-1(仕様書に `flow` の intent の欠落の番号が無いため)                |
| 接続の `pressure`・配達保証・`block` の期限 | E0008-1                                                                  |
| `block`・`drop` の `bound`                  | E0008-1(ADR 0032 の決定6(上限を `bound` で書く)。提案。仮置きとして従う) |
| `latest` の `bound`・0 の `bound`           | E0032-2(同上)                                                            |

名前が解決できない記述(宣言の無い型・単位、担い手に無い口 等)は、仕様の検証番号を付けずに「生成できない」と報告する。
E0000-2・E0000-3(`depends`・`expose` の外への通信)などの検査は、まだ持たない。

## 生成する物

トランスパイル先の言語のバックエンドの責務(ADR 0012 の決定8(バックエンドの責務は6つ))のうち、次を出す。

- データの写像: `id` は64ビットの整数を包む型、`record` は構造体。`instant` は UTC のエポックからのナノ秒(`i64`)、`float64` は `f64`(単位は型に残らない)
- 正準形への符号化と復号(試作の仮の形式)と、型の指紋
- 公開面の骨組み: コンポーネントごとの `<名前>の本体`(body の trait)と `<名前>の出口`
- 接合面の呼び出し: 結合・流す・流れを受ける(PC の器を直接呼ぶ)
- 起動の骨組み: 記述子と、全てのコンポーネントを結合して起こす `起動`

内部階層の写像は、まだ出さない。

## 試作の中で決めた事

- 記述のファイルの拡張子は `.shidzuku` とする(略号を作らないため)
- 量の宣言の綴りは `quantity <名前> <種別> base <単位 | none>` とした(語と型の語彙の綴りは、パーサの実装中に決める。計画書 第4節「Phase 1 の中で決める物」)
- `pressure` の欄は `block(deadline <期限 | none>, bound <数> 要素)` の形で読む(ADR 0032 の決定6(上限を `bound` で書く) の例の通り)
